## Selection and interface inventory

`src/server.rs:2718` mounts `/v1/chat/completions` to `api_chat_completion`; `:2719` mounts `/v1/messages` to `api_messages`. These server adapters must be traced separately from `src/uar/api/openai/routes.rs::chat_completions`: that latter handler interprets `model: default` as `default-agent`, `orchestrator` as `orchestrator-agent`, and other model strings as registered agent IDs. Do not assume that semantic applies to every OpenAI-shaped route or that a provider model ID is an agent ID. `src/server.rs:5928` documents native selection falling through explicit agent to session to default-agent; the eventual request author must read the concrete request schema and mounted handler before writing payloads.

AG-UI explicitly selects an agent in `/api/uar/ag-ui/agents/{agent_id}`. A2A selects it in `/a2a/v1/agents/{agent_id}` or preserved `/a2a/agents/{agent_id}`; compiler routes select the compiler and do not establish default-agent inference. ACP stores session `agent_id` and maps `default` to `default-agent` in `src/uar/api/acp/handler.rs:389`. Native run routes are declared in `src/uar/api/routes.rs`. Configured targets appear in `src/uar/api/targets.rs`; provider/model binding and advertised availability must agree with real execution.

The default positive scope is every claimed supported interface. Include A2A v1 JSON-RPC and advertised gRPC, preserved legacy A2A where claimed, AG-UI with actual A2UI use, native REST run/chat, OpenAI compatibility, Anthropic compatibility, ACP, and any additional advertised execution surface discovered while completing the route ledger. Catalog-only, disabled, unsupported, and configuration-conditional surfaces must be explicit rows with their reason. They cannot disappear from the denominator of an all-interface claim. MCP/compiler/registry administration alone is not evidence of a default-agent prompting interface; classify it before adding or excluding it.

## Evidence and unresolved design decisions

Retain each positive request's protocol, configured provider/model, selected agent ID and persisted prompt revision, source identity, installed artifact/profile, redacted request and model response, run/session/task correlations, elapsed time and request/output limits. Record actual result and rubric assessment separately from transport validity. A nonce-linked second turn and a small prompt-instruction task can assess context and saved prompt effects without assuming exact stochastic wording. Quality criteria must be fixed before execution and must reflect the user's intended tasks.

`scripts/dot/provider.py::Provider` and `scripts/dot/provider_peer.py` implement a controlled local provider; `tests/fixtures/uar_1_1_1_provider.py` explicitly handles synthetic credentials. Their independently recorded requests are useful for routing/fault attribution. They cannot satisfy genuine inference reliability, regardless of whether the installed UAR host and DB are real. Do not substitute these for an unavailable approved real model. `openspec/specs/product-validation-evidence/spec.md` explicitly requires genuine bounded inference and reports required unavailable providers as unmet.

Before production work or proposed execution commands, finish route/schema inspection for server compatibility adapters, agent CRUD/prompt fields, provider mount/model writes, advertised gRPC and legacy support, frontend A2UI actions, ACP methods, and maintenance worker registration. Resolve any claim/implementation mismatch explicitly in the canonical plan. This inventory makes those unknowns visible rather than excluding them.
