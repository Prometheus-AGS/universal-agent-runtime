## Problem

A host that wants to validate agent output exactly as the client will, or compact a long-lived surface, needs the official processor outside React, plus a lossless way to turn a surface's state back into messages.

The runtime already rebuilds live surfaces for its shadow preflight (`packages/a2ui-react/src/official/runtime.ts:445-486`). That reconstruction is private and loses information:

- it drops a component-level `catalogId` and `rootId` (`:449-464`);
- v1 `wantResponse`/`responsePath` are removed from components (`src/official/v1-compat.ts:129-141`) and kept only in a private map, so restored v1 surfaces lose action responses.

Also, `web_core` 0.12.0 has no remove-component operation (`removeComponent` runs only when a component's type or catalog changes, `message-processor.js:549`). Components a producer stops referencing stay as orphans. They count toward limits and would be rebuilt by any export.

## Proposed

1. **A headless runtime entry** (no React, no DOM) with the same catalog, component and function validation as the React runtime. First check that `web_core`'s processing modules run under Node, since it depends on `lit` and `@preact/signals-core`.
2. **Public `exportSurfaceMessages(surfaceId)`.** It returns a lossless message form, preferably one v1.0 inline `createSurface`, and preserves catalog, root, theme, `sendDataModel` and v1 action metadata.
3. **Pruning of components unreachable from the root** during export, with documented orphan accounting.

## Acceptance criteria

- [ ] export → fresh runtime → export is a fixed point, including v1 action responses.
- [ ] Headless and React runtimes accept and reject the same fixtures.
- [ ] Unreachable components are absent from the export.

## Context

Requested by the Universal Agent Runtime (UAR) A2UI surface-architecture review (KBD child `a2ui-surface-architecture`, 2026-10-28). UAR intends to use `@prometheus-ags/a2ui-react` 4.2.0 as its client A2UI runtime for chat surfaces, full applications and per-user surfaces that change shape at runtime, delivered as AG-UI `a2ui-surface` activities. Findings come from reading source at `28a500d6`; nothing was built or run. The intended use is a non-authoritative server mirror that validates and compacts surfaces with the same code the web client runs (pending UAR operator decision D2).
