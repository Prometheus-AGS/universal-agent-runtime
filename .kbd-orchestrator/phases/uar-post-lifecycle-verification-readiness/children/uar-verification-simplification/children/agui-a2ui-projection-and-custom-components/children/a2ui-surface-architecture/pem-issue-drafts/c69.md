**UAR request: A2UI cross-renderer fixtures** (A2UI surface-architecture review, 2026-10-28).

UAR will validate the same A2UI surfaces in React (`a2ui-react` on `web_core` 0.12.0), Flutter (GenUI 0.10.2) and a server-side mirror running `web_core`. A shared, language-neutral fixture corpus would make divergence visible. It should contain message sequences with expected accept/reject results and a normalized structure dump. Cases to include:

- duplicate and out-of-order activity delivery, and `MESSAGES_SNAPSHOT` replay with live input;
- a compacted restatement sent to a client that still holds the surface;
- a batch the producer accepts but a client refuses (catalog, topology, caps), followed by resync;
- an incremental change that keeps typed input, and orphaned components after a change;
- actions: unique ids, a stale version, a duplicate, the same action from two tabs, and `sendDataModel` on or off;
- per-viewer isolation (one user's reported values never reaching another).
