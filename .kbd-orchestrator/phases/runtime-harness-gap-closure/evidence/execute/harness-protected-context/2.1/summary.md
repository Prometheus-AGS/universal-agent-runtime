# Harness protected context task 2.1

Task `harness-protected-context-2-1` now acquires canonical tool receipts in the trusted host before presentation formatting. Native, MCP, graph, sandbox and terminal success paths persist the typed JSON value, its canonical bytes and digest, and any exact raw byte segments that were acquired. Terminal capture drains and hashes the full stdout/stderr streams while retaining exact bytes only within its acquisition allowance; display previews remain independently bounded. Receipt records are tenant/run scoped, ordered, immutable by call identity and admitted against a 16 MiB receipt limit and 64 MiB retained-per-run limit. Any acquisition or run-storage overflow is an explicit metadata-and-digest-only completeness state, so partial payloads cannot be labeled complete or presented as a successful canonical result.

Persistence support was added to the shared trait and all configured providers. Memory supplies deterministic semantic coverage. Postgres uses a transaction and locked run envelope for atomic admission. Surreal uses a compare-and-set run envelope with bounded conflict retries for parallel tool completions. The two migrations and the `RunManager` persistence injection are necessary trusted-host wiring for the requested behavior; no unrelated feature was added.
