## Required technical decisions

**Canonical preservation and budget.** Acquire native, MCP, graph and terminal results before display formatting. Retain immutable record/order/role/call identity, original bytes where supplied and typed values, provenance, completeness and digest. Existing newline-normalized hashes cannot prove raw-byte identity. The selected host acquisition ceilings are 16 MiB per canonical receipt and 64 MiB per run; presentation retains its separate 32,000-byte bound. They are new policy choices, not existing API fields. Stream-limit acquisition when possible; storage or acquisition failure records incomplete data truthfully. A truncated legacy record cannot be repaired by inventing its missing suffix: migrate only provably complete receipts, otherwise mark legacy completeness unknown/incomplete and stop guaranteed replay until reacquired or explicitly resolved.

The proposed pure planner computes `I = min(L, H, C - O - R - M)` and `B = I - F`, using checked arithmetic. L/H are optional independent input limits, absent means no additional ceiling; C is total context, O the actual provider output reserve, R only additional non-overlapping reasoning, M justified count uncertainty, F all required protected content plus framing. Invalid limits are invalid; negative B is protected overflow. Count the final serialized request as a whole because framing is not additive. R is zero where O already includes reasoning. An unbounded estimate is insufficient. No protected tool calls, arguments/results, structured/code/log/file/media data, evidence, active skill bodies, required instructions/current input, durable decisions or pending work may be summarized, truncated or dropped. Only host-marked contiguous prose is eligible. Summarizer calls are governed Liter host work, charged to shared limits; failed/empty/oversized/cancelled summaries preserve originals. Reattach and reauthorize before final counting. If no authorized destination fits, return overflow with canonical data intact.

**Per-model templates and settings.** Keep typed layout separate from endpoint wire serialization and provider settings. Resolve an exact versioned destination profile before a verified family profile, then a generic profile only for its declared supported subset. Carry compiler overrides and required protected slots through escaped deterministic rendering. Never infer compatibility from family substrings. Supply resolved profiles to the common contract already installed by change 1 at initial, iteration, retry, failover, graph, child and resume boundaries. Cache/manifests include profile/template/count contract/authorization identity without raw secrets or payloads. Count and capture the final outbound HTTP after Liter's transforms. In pinned Liter, the Anthropic adapter can raise max_tokens to thinking budget + 1: a fixture must force this case and require matching reserves or rejection before dispatch. Inspecting build_chat_request alone cannot prove the cap. No pinned-vendor edit is planned.

**Production task routing.** Change 2 task 2.4 replaces the observed default RouteRequirements construction in RunManager with actual host-derived tools/media/schema/context requirements and a versioned semantic task classification. Use governed Liter for semantic classification, charged to the shared budget; invalid/unavailable output is unknown and provides no invented ranking advantage. Classification is a soft selection signal, not tool authority. Keep explicit model choice and hard host constraints authoritative. Reuse relevant Coding/Agentic/Context benchmark dimensions with provenance; generic tasks have no fabricated benchmark score. A learned selector remains experimental until its separate live acceptance gate passes. Eight task-input/classification/output/usage cases T01–T08 measure this connection; R01–R12 remain independent admission tests. Synthetic timing/prices/outcomes prove arithmetic and wiring only, never real model performance.

**Durability and graph ownership.** Persist owner/agent/request identity and task/context/thread/run/artifact correlations before enqueue, claim with existing revision compare-and-swap and reconcile accepted intent after restart. A repeated identity with changed payload conflicts. Memory checks logical semantics but cannot prove crash durability; Postgres and Surreal each need the crash suite. Database transactions cannot promise exactly-once remote effects: an effect with unknown receipt remains recovery-required. Optional node/iteration/parent/child/tool correlation extends RuntimeStep compatibility; committed event identity supplies order and replay deduplication. Approvals, denial, shared reservations, cancellation and cleanup stay in trusted host services. Agent kernels gain no mutation authority.

**Skills and evidence.** Preserve conversation > agent > global precedence, explicit governed activation, and immutable skill version/body reattachment. Keep task success, tool use and prompt-only attribution distinct without double counting usage. For knowledge, use governed claim extraction/entailment with deterministic authorization, source/version/offset/span checks. Lexical overlap is only diagnostic. Model support judgments are advisory and method-labeled; they never override denial/integrity checks or independently pass hard regression gates. Invalid references abstain. Preserve ingestion, embeddings, hybrid retrieval and the current UI journey.

## Completion and uncomfortable constraints

Plan completion means the complete artifact packet is reviewed, six changes/44 tasks are registered, the local certification dependency is registered and the handoff names the first pending task. It does not mean implementation or certification is complete. Provider evidence, actual baselines, historical test identity, coverage and stable-platform/profile/live evidence remain explicit execution gates; missing evidence prevents the affected behavior from being enabled or the phase from completing.

The uncomfortable scenario is that lossless protected data simply cannot fit, or no deployed provider has a defensible count bound. A correct runtime will then refuse that request. This plan cannot honestly promise successful long-context execution for every configured model. It can promise a testable preservation and failure contract. Scope excludes unrelated readiness work, dependency upgrades, a replacement runtime, UI redesign and deployment. All proposed guards trace to observed lossy paths, explicit requirements or existing trusted-host authorization/resource boundaries.
