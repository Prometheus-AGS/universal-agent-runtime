# Presentation run details UI plan

Phase: Execute; task selection-provenance-workspace. Mode: Operate/Read. Target: frontend/src/features/chat/ui/run-inspector.tsx. This adds one read-only section to the incumbent inspector, not a new page or redesign. Product context is frontend/PRODUCT.md; reusable templates are separate from the development tester. Browser and behavioral acceptance are deferred until all phase code is complete, per the user.

## Operator flow and visual contract

Place a heading `Presentation` after the inspector's existing heading and before its raw-record tabs. A compact definition list shows `Requested`, `Admitted output`, and `Run outcome`, followed by a plain-language fallback/status sentence. Label absent requested mode `Legacy (not negotiated)` only when an actual valid host record says Legacy; missing evidence instead says `Presentation details were not recorded for this run.` An unsupported schema says that the record cannot be read by this client, never a guessed successful status.

Below the summary, a native disclosure `Published templates (N)` contains stable template IDs and frozen revisions. Preserve full IDs with wrapping; no ellipsis-only identity. An actual empty list is `No template published` and is not confused with pending/unavailable state. Show generated surface publication separately from template publication: a legacy/manual surface can be published without a template. End with `Publication does not confirm client display.` No green success badge or displayed/rendered claim is inferred from eligibility. Failed and cancelled runs remain distinct from a finished text fallback.

Loading uses one contextual status announcement; an unavailable database/subscription shows a specific error and `Retry details` button with min44px target and visible focus. Do not make every field/count a live region. Native disclosure and retry preserve keyboard operation without moving focus on stream updates. Native disclosure state is UI-local and does not duplicate a business record. The status/error is independently subscribed below the section shell; each definition item subscribes to its own primitive where practical. The template list subscribes independently to its stable immutable receipt list.

Use incumbent KnowMe Flat2.0 tokens (foreground, fg-sub, surface, ember focus), Geist body/display and mono only for IDs/revisions. Space related rows tightly and separate the heading/status/disclosure by existing gap2/gap3 rhythm. No new card inside the inspector card, borders, eyebrow, shadow, gradient, icon decoration, animation, fonts or color constants. Definition rows collapse/wrap within the existing340px inspector and narrow-screen layout; avoid fixed width and preserve200% zoom. Do not repair unrelated incumbent inspector styling or move existing checkpoint/replay controls.

## Data path and files

Critique corrections: directly beneath the Presentation heading, say `Latest recorded details for this run.` The section is run-wide, never a reconstruction at the selected event's time; historical scrubbing remains out of scope. Under Admitted output, explain `Output permitted by the host; publication is recorded below.` Keep admitted mode and observed publication separate. The disclosure summary also has a min44px target and visible ember focus treatment, not just native semantics. These corrections address the two bounded interpretation findings without redesigning the selected-event tabs.

New platform/entities/presentation-provenance/{contracts,domain,api,registration,use-presentation-provenance,index}.ts owns the versioned record, strict projection decoder, subscription lifetime and registered normalized entity. The transport subscribes to the existing PGlite run-event repository; domain actions replay STATE_DELTA/STATE_SNAPSHOT with run/sequence correlation, atomically publish one record and reject stale subscription callbacks. Unknown/missing records never become defaults. Hooks expose typed field selectors/actions through platform/entities/index.ts, registered from entities/bootstrap.ts. The new chat UI component presentation-run-details.tsx imports only that public hook API and incumbent Button; run-inspector.tsx only mounts it with the known run ID. No new fetch in feature hooks, graph imports in components, per-row ingestion or separate history cache.

## Verification and limits

Tier0 typecheck/lint after implementation. Whole-phase tests must cover valid/missing/unknown data, no-publication and failed/cancelled outcomes, legacy manual versus template publication, stable frozen revisions, late join, duplicate/out-of-order replay, local database reload and stale run-switch callbacks. Browser checks cover keyboard, screen-reader announcement intent, narrow widths and200% zoom using real states. No source-only review certifies those outcomes.
