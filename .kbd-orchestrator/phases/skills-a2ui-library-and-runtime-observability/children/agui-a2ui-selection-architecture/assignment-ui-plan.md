# Presentation assignment interaction contract

Phase: Execute, task scope-assignment-workspace. Extends ui-plan.md; does not redesign the console. Apply Impeccable4.2.0 audit/critique and UI/UX Pro Max form/error/accessibility guidance before implementation. Two isolated critiques and fresh adversarial review precede UI code. All live browser checks, polish and functional tests remain at the end of the whole Presentation phase.

## Direction and applied rules

Make requested assignment distinguishable from actual eligibility. Retain KnowMe Flat2.0 tokens and existing console typography. Use independent field controls with44px targets, labels, keyboard focus and textual states. No new visual language, animation, dependencies or assets. Impeccable Operate prioritizes a clear scope and recoverable save; UI/UX Pro Max contributes form recovery and accessible status. Frontend-design hierarchy puts scope and requested mode before the catalog list. Vercel React/Composition guidance keeps subscriptions at the mode control, each checkbox and save status. Prometheus Entity Management supplies graph-owned records/drafts and domain-owned writes; components import only public platform hooks. These are the same consulted references recorded in ui-plan.md, applied to this narrower interaction.

## Surfaces

1. Session Configuration: Presentation section beside tool approval and prompt caching. It edits the existing AgentSessionDraft, and the existing Save Configuration commits it with other fields. No second save button, nested form, independent request or duplicate Presentation draft. Parent shell does not subscribe to the field. Opening and saving other settings preserves assignment, including inheritance and denied IDs.
2. Agent detail: Presentation assignment section beside capabilities/memory. It receives only the agent ID and loads through a public typed domain hook. A dedicated Save assignment action patches only the run-policy Presentation field. Existing full agent editor saves must preserve this extension, not reconstruct it away.
3. Settings: Presentation policy entry under Governance & Agents. Scope label explicitly says instance-wide ceiling and admin access required to save. Load the existing run_policy.global setting; do not mistake404 or a load error for an empty policy. No UI claim that owner-specific catalog items are available to other principals.

## Shared control contract

Heading: Presentations. Description: reusable templates this scope may make available for future runs, subject to parent restrictions and client support; saving is not rendering.

Mode options map exactly to ResourceSelection: Inherit; Automatic; All allowed; Selected templates; None. Inherit keeps parent intent without copying IDs; at global scope it leaves the runtime's automatic selection behavior. Automatic lets UAR choose a subset at runtime; All allowed requests every eligible template. Neither bypasses parent restrictions. Mode changes move inactive selected IDs into graph-owned draft metadata, labeled Retained for returning to Selected. Serialize active ids as empty outside Selected, matching the delegated host contract. Preserve unknown IDs in the active or remembered draft list until explicitly removed. Exclusions remain active and visible in every mode: label Inherit with exclusions when applicable. A separate Reset assignment action explicitly clears both selected and denied IDs, rather than overloading the mode choice.

Selected templates shows searchable, labeled checkboxes from the freshly admitted owner catalog. Each row owns narrow title/enabled subscriptions; checked state is a derived primitive. Disabled templates are labeled Unavailable (disabled); selected IDs absent from the admitted list are labeled Unavailable (not in this catalog), using the ID without inventing a title or leaking another owner's metadata. Existing unavailable selections can be removed, not added. Selected with zero IDs explicitly says no templates will be eligible at this scope. A denied selected ID is labeled Excluded here, not represented as eligible. Status text participates in the checkbox's accessible description. An exclusions section remains visible in every mode; it offers an Exclude action for admitted catalog IDs and explicit Remove exclusion actions, including unavailable IDs. After verified admission, removal stays enabled even when the item itself is disabled or missing; failed admission hides the entire assignment draft as described below.

Catalog loading/error is independent of policy loading/error. Never turn a catalog failure into an empty library or convert mode to None. Show Reload catalog. Display no hydrated template titles or assignment drafts until fresh verified owner admission. In this bounded implementation, failed catalog admission hides assignment values and disables assignment edits, including mode, until Reload succeeds; retain the graph draft without erasing it. Do not promise independently verified policy access from an endpoint that supplies no owner envelope. Saving unrelated session settings remains possible by omitting Presentation intent, invoking authoritative host preservation. Initial unverified hydration and subsequent failed re-admission have the same display gate, with a clear message that the draft is retained but currently unavailable.

Empty library links to production Presentations in a new tab, explicitly labeled Opens in a new tab. This retains the session sheet and all its other draft fields; do not navigate away through the incumbent session close/unmount path that cancels its draft. On return, Reload catalog refreshes options without reinitializing policy. Zero search matches has Clear search. Search is transient UI-local state; policy lists and draft status are normalized business entities. Do not show an effective eligible count before the host resolves a run. Requested/selected count may be shown with that exact label; catalog choices remain unresolved until run admission.

## Entities and I/O

Session wire adds presentations as a ResourceSelection object or null. Missing/null legacy values mean preserve the host's stored assignment on save; explicit {mode:inherit, ids:[], denied_ids:[]} resets intent. Host GET returns explicit current intent. Domain copying, dirty-field merging and decoding carry the field. Every save for which presentations is not dirty MUST omit/send null for that field, including agent-selection/default paths: never echo a fetched explicit value merely because it was in the full configuration object. Only an intentional assignment edit sends explicit intent. This prevents a stale pre-POST frontend read from overwriting a newer restriction before the host captures its write baseline.

Standalone agent/global controls use normalized PresentationAssignment and PresentationAssignmentDraft records, partitioned by verified owner and scope/target. Current admission gates public hooks; drafts remain hidden after auth/admission loss and are offered only after fresh admission. No business-record useState, direct graph access from components, feature-hook fetch, per-row graph writes or queued/replayed writes. Domain actions sequence loads and mutations; transport owns fetch. Hydrated draft recovery must not silently replace a fresh remote baseline. Lock draft edits during save; late responses cannot replace another scope/owner's active draft. Keep dirty drafts on navigation and provide explicit discard/reload confirmation. Warn before browser exit while dirty or saving.

Agent assignment reads use the strict GET /api/agents/{id} endpoint, not the legacy catalog list: the list swallows storage errors and injects built-ins, which cannot establish saved policy intent. The strict endpoint returns a persisted artifact,404 if absent and503 on storage failure. PATCH /api/agents/{id} updates the specific extensions.uar.run_policy.presentations merge patch. Agent writes must preserve unrelated concurrent fields in the trusted host, not merely issue a smaller client payload followed by a racy server read/replace. Global UI must use the newly implemented GET/PUT /api/uar/settings/presentation-policy, not full-setting PUT. GET returns {policy}; PUT sends {expected_policy, presentations}, changes only Presentation intent, and atomically compares the full stored policy before writing in each provider. A409 retains the draft and offers explicit Reload/discard; no retry loop. Settings reads/writes retain X-UAR-Admin-Key, while catalog/agent/session requests retain verified API authentication. No credential is stored in entities. Conversation writes also conditionally compare the principal policy read at request entry so omitted-field saves cannot overwrite an interleaved explicit restriction. Sequential stale client edits remain intentional writes unless a client baseline is supplied; do not claim a general revisioned policy editor.

The global scope warning appears beside the mode choice: This catalog belongs to the signed-in owner; this ceiling affects the entire instance. Selected templates excludes every ID outside the selection across the instance, including other owners' IDs; an existing unavailable ID may remain selected, so do not categorically claim all foreign IDs are excluded. None disables templates for everyone. Saving either narrowing mode requires a confirmation naming that instance-wide consequence. Do not expand catalog access to soften this constraint.

Failed saves retain selections with a focusable error; uncertain writes state that the outcome is unknown and require an explicit reread before another save. Never automatically replay. Saved state is shown only after a confirmed response/read. Settings/agent restrictions remain server-authoritative; UI membership is not an authorization decision. Text distinguishes saved intent from a later run's eligible/snapshot/output provenance.

## Acceptance and uncomfortable constraints

Source/design critique is not visual acceptance. End-of-phase checks must cover keyboard mode/search/checkbox/removal, narrow viewport, unavailable/denied IDs, unchanged inherited save, legacy omission preservation, catalog outages, policy503, admin denial, owner change, dirty recovery and uncertain saves. Verify global→agent→conversation restriction at runtime, not by duplicating server resolver rules in the component. No extra effective-policy API is implied here.

The uncomfortable limit: selecting a template is requested intent, not proof it can render in the current client. The assignment UI must say this plainly. The new global conditional field update is deliberately narrower than a general revisioned settings editor; no claim extends to other settings endpoints. Agent-side atomic field preservation is still an implementation prerequisite, not evidence supplied by this contract.

## Independent critique dispositions

A and B source critiques identified unsafe global read/full-write preservation, inactive IDs incompatible with the delegated validator, unclear Automatic/All intent, active exclusions hidden by mode changes, global-owner scope confusion, and a session navigation path that discards drafts. The contract above resolves these without a redesign. Global and conversation conditional persistence code is being implemented before UI acceptance. Both reviews were source-only; no visual score or browser acceptance is claimed. Fresh adversarial review of this revised artifact precedes the controls.

The amended contract passed fresh adversarial source review. Session implementation review then found a late admission-error/save-state race and missing uncertain-write recovery. Assignment errors are now separately stored and generation guarded; uncertain writes require explicit saved-state reconciliation before another save. A confirmed POST is committed independently of the subsequent prompt-caching read. One bounded restriction is explicit: if Presentation changes are dirty when admission is lost, Save Configuration cannot partially commit the other fields; it retains the entire draft and asks for catalog reload. Unrelated saves through omission remain available when Presentation is not dirty. This preserves the existing single-save transaction instead of silently discarding a hidden assignment edit.
