# Presentation provenance implementation contract

Phase: Execute. Task: selection-provenance-workspace. Existing approved scope: requested/effective mode, fallback and actual template publication, persisted through correlated run events and shown through typed normalized entity hooks.

## Host record

Add a versioned host-owned provenance projection under the reserved AG-UI state key `presentation`. Include requested/effective mode, admission fallback, eligible frozen identities/revisions, completed/cancelled state, whether a generated surface was published, and actual template publication identities/revisions. No template source, bound data, owner credentials or client-displayed assertion is included. Missing records remain unknown, not an empty successful result.

Frozen template data stays immutable. Mutable publication receipts belong to the trusted host, never model history or a client declaration. Only the native publication helper can record a template identity after consuming the bound preparation and publishing its validated messages. Legacy/direct surface output may establish surface publication, but cannot establish a template identity from supplied metadata. The host-generated policy summary is admission diagnostics, not generated-template output and does not count toward this outcome. Failed renderer calls set generation-failure state; terminal negotiated non-Text runs without publication receive a no-surface or generation-failed fallback while preserving the admitted mode separately. Cancellation remains explicit, not successful fallback.

## Event and persistence path

RunEventEmitter and emit_to_run use one history-owned projection path. Gate external events first; reject externally supplied patches of the reserved presentation key (including root replacement) so a graph node or generic producer cannot forge provenance. Internally generated STATE_DELTA records bypass only that reserved-key rejection, not output policy. Emit a complete projection at admission, publication changes and terminal boundary, before the terminal event. Existing history assigns ordered event IDs; the existing AG-UI adapter maps the state delta. PGlite RunEventPersistence already persists state events and deduplicates by run/event identity. The provenance domain replays full records from this durable stream; no new parallel history database is needed.

Historical/missing/unsupported records are shown as unavailable, not inferred from prose or template selection. A late-joining client uses the existing state synchronization and persisted run event path; replay fixtures at phase end must prove this claim. This contract does not turn the backend's bounded in-memory event history into restart-durable server storage. Durability is the existing client run-event repository, with its existing authenticated app lifetime.

Review corrections: retain the latest full host provenance and its assigned sequence independently of the512-event buffer. A replay baseline may use that record only when its sequence is at or before the requested cursor; an older cursor uses retained historical evidence or explicitly unavailable provenance, never future state. Stream access checks the exact verified subject/tenant independent of Presentation snapshot existence, preserving authorized anonymous and pre-admission failure streams. Outcome distinguishes running, finished, failed and cancelled. Recoverable renderer/publication diagnostics must use a nonterminal event, not NormalizedEvent::Error (the existing stream closes on Error); genuine terminal errors emit the failed provenance before closure. Failure receipts originate in the host preparation/publication path, never arbitrary ToolEnd data.

If unrelated retained state patches cannot reconstruct a synchronized global STATE_SNAPSHOT, emit the cursor-valid full provenance independently as CUSTOM `uar.presentation.snapshot`. This does not claim the rest of the state is synchronized. Its stable event ID uses a dedicated presentation-snapshot suffix, avoiding collision with per-event frame ordinals. The typed domain replays this extension as well as full presentation records in STATE_DELTA/STATE_SNAPSHOT. No record at/before the requested cursor remains unavailable; a newer projection is delivered only in the subsequent ordered replay.

## UI direction (review required before UI edits)

Extend the incumbent chat run detail surface with a compact Presentation section: requested mode, admitted effective mode, fallback explanation, published template ID/revision and explicit publication-versus-display wording. Use the normalized entity graph and a new typed platform domain hook; components perform no I/O or graph mutations. The transport subscribes to the existing persisted run snapshot, domain actions decode/replay one atomic record, and independent small subscribers render fields. Source/event parsing belongs below components. Show loading, unavailable/unsupported, error/retry, pending and terminal no-publication states. Do not redesign the existing timeline/inspector or migrate unrelated trace state.

## Exit and uncomfortable limits

Tier0 compilation/static checks after cohesive edits. At phase end prove admission-only versus publication, render failure/no surface/cancellation, repeated/replayed/out-of-order events, late join and local database reload, plain-text compatibility, template revisions, tenant isolation and absent/unknown versions. Review desktop/narrow/keyboard/zoom behavior. Publication is not delivery; client persistence is not backend restart durability; source review is not runtime acceptance.
