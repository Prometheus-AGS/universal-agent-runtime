## Interface effects

`A2AState` now receives `Arc<dyn A2aAdmission>` and optional `grpc_url`. `RunManager` resolves the selected artifact and authorizes its server-owned protected preferred skills before a new A2A task reservation. Transports project `Forbidden` as v1 JSON HTTP 403/-32011 and gRPC `PERMISSION_DENIED`; unavailable policy or catalog state maps to service-unavailable transport errors. Legacy transports retain their legacy payload shapes.

The official service keeps `a2a.AgentService` mounted for v0.3 compatibility. It serves `lf.a2a.v1.A2AService` on the same listener. The v1 request `tenant` field is empty or must match the verified tenant; `x-uar-agent-id` remains the gRPC agent route. gRPC task projection now retains durable artifact IDs, descriptions, metadata, completed output, original history indexes, caller message IDs, and public-only message metadata just as JSON-RPC v1 does. Streaming, push notification, and extended-card RPCs return `UNIMPLEMENTED` without task submission. A card advertises gRPC only when the bound listener supplies `grpc_url`.

The external fixture takes `--transport`, `--governance`, `--decision`, and `--receipt-path`. It requires trusted and limited tokens for the same A2A task principal and verified tenant, a protected-preferred agent, a separate dynamic-activation agent and skill, local Dot19 MCP and provider JSONL traces, and an installed local or image target. JSON-RPC chooses the agent in its URL; gRPC chooses it with `x-uar-agent-id`. Both send the explicit verified request `tenant`, then assert a mismatched tenant, missing credential, or missing protected role returns the transport-native authorization error without changing `ListTasks` or invoking a peer. It also asserts gRPC `SendStreamingMessage` is `UNIMPLEMENTED` without a reservation and compares the same terminal task's normalized state, status message, artifact, complete-history, and `historyLength: 1` projections through both transports. It pages real `ListTasks` before and after denied submissions. It counts only Dot19 `tool_call` trace events: zero while input is required, one after approval, zero after denial. Its dynamic provider sequence makes one actual `activate_skill({skill_id})` attempt under limited credentials. The fixture proves its public pending approval record identifies `activate_skill`, its resolved record retains the exact approved or denied decision, and the subsequent controlled-provider assistant tool call contains the exact protected `skill_id`. The fsynced provider trace must contain native `activation_failed` with `failure.code: ineligible`, no peer tool call, and no later protected prompt marker.

`run_default_profile(image, evidence, *, docker, require, wait_for)` starts the actual Docker image first with no UAR configuration, command, environment or published port and requires the compiled fallback-credential refusal. It then starts the unmodified image command with only the documented required secret sources (`UAR_SECURITY__JWT_SECRET` and `UAR_SECURITY__SETTINGS_ADMIN_KEY`), no UAR config file, no model override and no published host port. Docker-exec Python sends loopback requests for health, anonymous effective-settings `401`, non-admin effective-settings `403`, admin effective-settings values and SHA-256 revision, token-subject capabilities/version, public A2A agent-card version `1.1.0` with the expected JSON-RPC and gRPC interfaces, unlisted-origin CORS refusal and explicit `model_not_configured` inference failure. It reads `/proc/net/tcp` and `/proc/net/tcp6` to require that every listening TCP socket is loopback-only and that HTTP `1906` plus A2A gRPC `50051` are present. It samples every 10 seconds for 300 seconds from `/proc/net/dev` non-loopback transmit-packet counters, starting before health, and rejects any TX packet increase. After that pure-default observation it changes governance through the authenticated settings API, requires a new effective revision, restores the original value and original revision, and separately starts an explicit allowed-origin profile to require positive CORS behavior plus anonymous settings `401`.

The initial installed candidate exited before health because `src/server.rs` constructed the optional response-quality `Orchestrator` with the default empty model; its provider constructor correctly rejects that configuration. The server now leaves that optional orchestrator unset for sidecar mode or an empty configured model, preventing provider construction and network access during the offline default startup. Request-time model selection continues to use the existing explicit `model_not_configured` path.

The r12 installed A2A gate passed the four MCP profiles, then its enforced JSON-RPC approval tuple successfully submitted a task but received JSON-RPC `-32004` on the fixture's first immediate `GetTask`. The retained acceptance log is `/tmp/uar-v1.1.0-candidate-acceptance-r12.log`; the exact runtime log is `/tmp/uar-v1.1.0-candidate-evidence-r12/uar-a2a-fcf13d026285.log`. That runtime log records actor spawn, run start, fixture-provider selection, and eligible-skill rendering, but no projection diagnostic. No provider trace was created for the tuple.

The r15 retained binding diagnostic at `/tmp/uar-v1.1.0-candidate-evidence-r15/a2a-cas-read-diagnostic.json` proved the actual fault. Surreal stored `a2a_bindings.data` as a JSON string and compared the complete serialized string in its transition predicate. A parsed `A2aBinding` contains `HashMap` metadata in tasks and messages; reserializing unchanged logical state can reorder those keys. The diagnostic constructed that reordered form, observed `byte_equal: false` with `revision_equal: true`, and the retained row remained revision 3 with the same run and process. `get_durable` has therefore been restored to its pre-r12 behavior. The provider now reads the exact raw string, compares the parsed and validated binding with the caller's expected binding as JSON values, and uses that raw string in the atomic `WHERE data = $before` CAS. Cancellation reconciliation uses the same raw snapshot while retaining its epoch, effect, claim, and thread fences. This supports existing string-backed records without a migration and keeps true concurrent writes observable as CAS failures.

- Complete source-only A2A fixture reconciliation: successful and handler-level JSON-RPC responses require `a2a-version: 1.0`, matching JSON-RPC id/envelope, concrete `SendMessage` task envelope, and all source-projected `GetTask`/`ListTasks` fields; both transports validate pinned TaskState and Role enum names, task/status/history/artifact/message/part shapes, terminal approval decision identity, and cross-transport status-message/history/artifact/metadata parity. The fixture distinguishes that contract response from the global middleware boundary: enforced tuples set `jwt_required=true`, so a missing HTTP bearer is a deliberately bare `401` before A2A dispatch; disabled tuples set optional JWT, reach `v1::dispatch`, and require `401/-32010` in the A2A envelope. Valid limited-role and tenant-mismatch JSON-RPC requests require handler `403/-32011` envelopes. gRPC always verifies bearer metadata, so missing bearer is `UNAUTHENTICATED` in either tuple, role/tenant failures are `PERMISSION_DENIED`, and unsupported streaming is `UNIMPLEMENTED`. Each failure checks unchanged `ListTasks` and peer trace before any reservation. gRPC normalization is narrowly limited to ProtoJSON's omitted implicit defaults: an empty `ListTasksResponse` has absent `totalSize`, `tasks`, and `nextPageToken`; empty `Struct`, repeated fields, strings, and `TASK_STATE_UNSPECIFIED` may be absent elsewhere. The source contract still requires the nonzero requested `pageSize`. ProtoJSON default omission is documented by the official Protocol Buffers JSON guide: https://github.com/protocolbuffers/protocolbuffers.github.io/blob/main/content/programming-guides/json.md.
- `uar_1_1_loopback_client.py` now explicitly applies the requested governance setting for both enforced and disabled tuples. `configure_a2a_runtime` verifies both imported skill IDs before binding them, and `run_a2a_profiles` verifies that all eight `{governance} × {transport} × {decision}` tuples returned receipts. These are fixture/setup changes only; no shared production source change is indicated.
