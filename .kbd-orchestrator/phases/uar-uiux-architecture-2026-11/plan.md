# Plan — uar-uiux-architecture-2026-11, slice S1 (live model choice)

Plan revision bound: 143. Written 2026-11-20 by the lead (Claude Code, claude-opus-5-5).

## What the user gets

An operator changes the system default model in the console and the next answer in
every conversation without an override comes from that model, with no restart. A
conversation with its own model keeps it; clearing it shows what it will inherit before
confirming. A reply already being written finishes on its original model. Each answer
names the model the provider reported, why that model was used, and since when. A choice
the runtime cannot serve is refused and never claimed as served. This is S1-R1 to S1-R9
in the adopted contract.

## Lessons that shape this plan

- Assessment: the system level has three competing default-model settings, none both
  reachable and used. S1 keeps one writer (the live route) and makes the settings API
  refuse `llm.default_provider` (SET 1.6).
- Assessment: Model entities exist twice in client state under two ids. IDN 1.x/2.x runs
  in Wave 1 so the S1 picker reads one provider-qualified identity.
- Gotcha 2026-11-06: Utoipa 6 needs an explicit `type` on plain schemas, and a release
  compile does not exercise the startup path. Any new OpenAPI field for the receipt
  (W2) must declare its schema type; the boundary run, not a compile, proves startup.
- Gotcha (`gotchas.md:778-786`): settings migrations must touch no other key. S1 adds no
  migration; Global-model retirement (S1 change group 3) is out of S1.

## Plan decisions

- **P-1 Receipt origin** (S1 7.1): add a separate `model_origin` field to the effective
  run policy artifact with values `system_default`, `conversation`, `agent`, `turn`,
  `configured_fallback`. Do not add a `PolicyScope` variant: that enum is matched in 15+
  runtime files and a wire change widens the blast radius. W2 confirms by reading the
  consumers before writing.
- **P-2 Activation time** (S1 7.2): the update time of the `llm.default_provider` row the
  live route writes, at second precision, captured at turn admission. Never the client
  clock.
- **P-3 Served model** (S1 7.12): read from the completion result in `liter_driver.rs`.
  If the response model is not available there, W2 stops and reports; no fallback to
  the requested model.
- **P-4 Configured fallback** (open decision 4): keep the YAML `llm_config.model`
  fallback as today. The clear preview names it when the default's provider is disabled
  (SCN-SYS-012). If the operator later retires the fallback, 7.5 switches to refusing the
  clear.
- **P-5 SET 1.4 scope**: in S1, add `x-uar-ui-hidden` only to `llm.model` and
  `llm.default_provider` so SET 2.2 can hide them. The other namespaces stay for the
  settings slice.
- **P-6 Sub-agent rule** (S1 group 5): not in S1; no code change.

## Interface contract between writers (fixed before Wave 1)

- W1 → W4: the default route returns 409 `{"error":"Provider '<id>' is disabled"}` for a
  disabled provider and 404 for an unknown one. The settings API answers 422
  `unsupported_setting` for `llm.default_provider`.
- W2 → W6: each assistant turn's receipt carries `served_model` and `served_provider`
  (provider-reported), `model_origin` (P-1) and `model_origin_since` (RFC 3339, seconds,
  present only for `system_default`). W2 writes the exact field path into
  `review/s1/handoffs/W2.md` before W6 consumes it.
- W2 → W6: the agents read carries `explicit_model` (`provider/model` or null) when
  `extensions` is not already exposed.
- W4 → W5, W6: `@/platform/entities` exports `setSystemDefaultModel`, the
  provider-qualified `Model` hooks (`useConfiguredModels`, `useCatalogProviders`,
  `useCatalogModelsForProvider`) and `useProviderMetaField`.
- W5 → W6: `features/models/pickers.ts` exports `CatalogModelPicker` and `ModelPicker`.
- W6 → W3: the system-default control's live pair, confirmation and the receipt's model

## Boundary

The boundary opens only when every implementation task above is done and recorded in the
inventory. Before any scenario command the contract requires (`boundaryPacket.requiredApprovals`):

1. an operator phase verification grant recorded in the phase ledger;
2. one independent fresh-context review of the step definitions, runner configs and
   control scenarios against the contract;
3. no credentials in tests (auth-off test configuration).

Then the contract's 50 boundary commands run once, serially, through BIND. Results are
reported per scenario as PASS, FAIL, BLOCKED or NOT_EXERCISED. A FAIL is repaired and only
the affected scenarios rerun (B5, max 2 repairs).

## What could go wrong

- **The boundary review the operator does not want is in the contract.** Removing it
  needs a signed amendment. If the operator wants it gone, that is one signature; otherwise
  it runs once at the boundary.
- **P-3 may fail.** If Liter's completion result does not carry the provider's model
  id, S1-R9 cannot be met without a vendored Liter change, which this phase excludes.
  W2 checks this first so the slice stops early rather than at the boundary.
- **No compile until the end.** With VLBV, six writers' Rust and TypeScript are first
  compiled at the boundary. Expect the first boundary batch to stop on compile errors;
  the repair budget (2) may not cover a large backlog. Writers reduce this by matching
  existing signatures exactly and reading every callee they use.
- **The method conflict is still open.** Execution is unaffected, but `method-context`
  will keep reporting CONFLICT until the acknowledgement is recorded.
