## Rules applied (task summary, written before code)

- Impeccable (Operate mode, lens: critique + audit): one job per element; every state named (loading,
  unavailable naming the missing part, error with retry, available); a confirmation that appears only after
  the runtime acknowledged; no typing of model names (the picker is the only input); copy states what
  happens (`Set as system default`, `Confirm clear`) and errors say what was not changed. Flat 2.0 lint
  contract honored: new files use fills and spacing, no `border-*`, `shadow-*`, `ring-1`, outline variants.
- frontend-design / UI/UX Pro Max: extend the console, not a new look. The panel is the "Default chat" role
  card of `docs/design/models-and-providers.html` made operable: label, live pair in mono, picker, one
  primary action. Receipt is one quiet mono line under the answer; hierarchy by foreground versus muted.
  Keyboard: palette command lands focus on the picker; preview takes focus; every control has an accessible
  name; status regions are `role=status`/`alert`.
- Vercel React Best Practices: `rerender-derived-state` (hooks return primitives; the receipt hook returns a
  string so the thread does not rerender per streamed token), `rerender-split-combined-hooks` (each
  effective-model value is its own tiny component), `rerender-defer-reads` (confirm reads state at call
  time), `js-cache-function-results` (provenance receipt parse cached by block text), `rerender-memo`
  (receipt line), no setState in render.
- Vercel Composition Patterns: no boolean-mode props; panel is a composition of `LiveDefaultPair`,
  `PinnedAgentsList`, the shared `CatalogModelPicker`; session sheet composes `SessionEffectiveModelView`
  and `ClearOverridePreview` beside the existing control.
- Prometheus entity rules: components get data only through `@/platform/entities` hooks (`useProviderMetaField`,
  `useConfiguredModels`, `useAgentSession`, new `useSessionEffectiveModelField`) or feature hooks that wrap
  graph reads; fetches live in domain actions/transports (`setSystemDefaultModel`,
  `loadSessionEffectiveModel`, `loadPinnedAgents`); one `replaceEntity` per payload; transient UI state
  (selection, preview open, saving) is `useState` only and duplicates no graph entity.

## Round 2: effective view for a conversation with nothing saved

Source only; nothing run.

Backend finding (not edited): `get_effective_config` (`src/uar/api/discovery.rs` ~1106) starts with `load_conversation_policy(...)` and returns **404 `{"error":"No agent session config found for this session"}`** when the conversation has no stored policy. It never reaches `effective_policy`, `model_origin` or `inherited_model` in that case. The clean fix is backend: answer 200 using a default `RunPolicy` for an unstored conversation (agent from the request or `default-agent`); the console then needs no change, because it only falls back on 404.

Console change (`platform/entities/session-configuration/effective-model.ts`): on 404 `loadSessionEffectiveModel(id, signal, hint)` builds the record from runtime facts, not guesses:
- the active agent's own qualified `provider/model` (`agentConfig.model`, passed by the sheet as `hint.agentModel`) gives origin `agent`;
- otherwise `GET /api/uar/resolve-model` (the runtime's own default route: registry default, else `llm_config.model`) gives the model, and `GET /api/uar/providers` decides the origin: `system_default` only if the default provider is that provider, enabled, and its `default_model` equals the model; otherwise `configured_fallback`; `null` (no origin shown) if the registry cannot be read;
- 422 from `resolve-model` gives no model and the runtime's reason; any other failure is a load error (the sheet's Retry block);
- `since` stays null (no activation time is available there); `inherited_*` equals the effective values (nothing to clear).
Limits: an agent whose model comes only from the `uar.run_policy` extension, or an unqualified agent model, is not recognized, so such an unstored conversation shows the default route instead; a conversation that gains stored settings is read from the real `effective-config` from then on (the save refresh).

Sheet (`session-model-view.tsx`): `session-config-effective` now always renders the Requested and Effective rows once loaded, also for an unsaved conversation. Requested reads `none (inherits)` and has no `session-config-requested` element; `session-config-effective-model` and `session-config-effective-origin` carry the model and origin. A one-line note says nothing is saved yet. Refused save re-check: a 422 only marks the draft error; the entity is replaced only by a successful save refresh or a new sheet open, and the view reads the entity and the saved `AgentSession`, never the draft, so it stays unchanged (covered by the existing refused-save test; fallback paths covered by new `effective-model.test.ts` cases).

Files: `effective-model.ts`, `index.ts` (type export), `effective-model.test.ts`, `features/chat/session-model-view.tsx`, `session-config-panel.tsx` (passes the hint; effect depends on it), `session-config-panel.test.tsx` (call expectation).
Unverified: `/api/uar/providers` body field names (`default_id`, `providers[].enabled`, `default_model`) are taken from `ProvidersResponse` and W3's reads; `resolve-model` does not itself check that a default provider is enabled beyond `registry.default_model()`.
