## SCN-IDN-001 main test: "SCN-IDN-001 Catalog model identity survives shared bare model ids"

Steps and assertions (all exact):
1. Oracle vs snapshot: 8,170 pairs, 3,827 distinct bare ids, 1,123 bare ids on 2+ providers, 2,207 slash ids, and the
   provider list of `claude-opus-5` (19), `claude-opus-4-6` (17), `claude-fable-5` (21), all recomputed from
   `catalog/provider_catalog.json` and compared with `catalog-identity.json`.
2. `GET /api/models` (no headers): pair total equals 8,173 (8,170 + `extraPairs` 3); each of the 65 `sampleRows` and 3
   `customProviderModels` agrees on `limit.context`, `tool_call`, `reasoning` (when frozen), image input = `vision`, and
   input/output price (to 1e-9). The body sha256 and counts are attached as `api-models-digest.json`.
3. UI `/admin/models`: wait (poll, 90 s) until the count line reports exactly 8,173 in catalog and 8,173 shown. Providers
   count must be 225 or 345 (see Gaps).
4. For each of the 68 frozen rows: filter by its key, require exactly one `compare-checkbox-<key>` element, the row names
   the whole key (slash in model id intact, e.g. `baseten/MiniMaxAI/MiniMax-M2.5`, `idn-gw-a/idn-org/slash-model`),
   shows `<round(context/1000)>k ctx`, shows or lacks the tools/reasoning/vision badges as frozen, and shows
   `$<in.toFixed(2)>/$<out.toFixed(2)> per 1M` when input price > 0, else no price. Custom rows: `idn-gw-a/idn-shared-model`
   64k ctx vision tools; `idn-gw-b/idn-shared-model` 32k ctx, no vision, no tools; `idn-gw-a/idn-org/slash-model`
   16k ctx, tools, no vision.
5. Filter `idn-shared-model` reports exactly 2 shown; both checkboxes present. Clearing the filter returns to 8,173.

Non-vacuity: the count is polled until it equals 8,173 (a loading page reads 0); every row check requires exactly one
element; a bare-id keying yields about 3,830 and fails step 3.

Substituted boundaries: none in the main test.

## SCN-IDN-001 negative control: "SCN-IDN-001 negative control: a snapshot record missing model_id is rejected visibly"

Mechanism and what is substituted (two declared substitutions, both via `page.route`, all else real):
- `GET /api/config/persistence`: the real response is fetched and returned with `mode: "remote"`. Needed because
  the real-server config runs embedded Surreal, where the page uses `/api/uar/sync/stream` and never requests
  `/api/live/models/snapshot` (`frontend/src/entities/sync.ts:343`). With `mode: "remote"` the page registers the `/api/live`
  adapters (the runtime serves `/api/live` on embedded Surreal because it has a live bus, `src/server.rs:887-892`).
  This is one more substituted boundary than the contract text names ("the one fulfilled snapshot response").
- `GET /api/live/models/snapshot` (`src/server.rs:2992`): the real snapshot is fetched; one record (the first with a
  `model_id`) has `model_id` removed; the rest is byte-equal. Every other request reaches the server.

Assertions: the intercepted snapshot was actually delivered at least once (polled; else the control would be vacuous),
the persistence response was rewritten, the modified record id is known, then a visible ingestion error, then rows
unchanged: count line total and shown both 8,173, the first 3 sample rows and 3 custom rows re-verified field by field, and
the stripped record's own row still listed once.

Binding assumption (open): no spec, design or source names the UI surface of the "visible ingestion error" (IDN 3.1 and 3.2
are not implemented in the tree: `buildAuthoritativeSnapshotChangeSet` still returns null silently,
`uar-sse-adapter.ts:258-271`). The test accepts a visible element that is `role="alert"`, or `data-testid="models-ingestion-error"`
or `"model-catalog-error"`, whose text matches `/model_id|ingest/i`, or an `ERR-MODELS` bar (models-page.tsx:215) whose text matches
the same. The implementer must surface the error that way, or the lead must re-point this locator. On the baseline this control
fails (no error), as the design states; the runner does not run controls against the baseline.

## Gaps and unresolved limits

1. Fixture inconsistency for SCN-PICK-002 (needs a lead decision). `picker-config.yaml` says `models: []`, but a catalog provider with an
   empty list is auto-filled with all its catalog models, enabled (`src/llm/registry.rs:754-755`, applied at config seeding `:397` and on PUT
   `src/uar/api/providers.rs:278`). The dialog excludes enabled models (`models-page.tsx` AddModelDialog `excludeModelIds`), so with the frozen
   config alone it would offer 0 options, not 597. The test works around it with the REST placeholder step above. This is an additional harness
   state change the frozen config does not describe; if the lead prefers, either amend the oracle's setup text or change the product rule.
   Source-derived, not observed.
2. Providers count: tasks.md 8.1 says "345 providers", but the page derives its count from model rows and 120 of the 343 catalog providers
   list no models (jq), which gives 225 (223 + 2). The test accepts 225 (rows-derived, the baseline) or 345 (provider-registry-derived) and
   asserts the strict oracle only on models (8,173), which is the contract's grader. Lead should fix the 8.1 text.
3. Negative control needs the extra `/api/config/persistence` substitution and an unspecified error surface (above).
4. Row formatting dependency: row assertions read `N k ctx`, tools/reasoning/vision badge text and `$a/$b per 1M` as `ModelRow` renders them
   today (`models-page.tsx`). Task 5.6 (virtualization) says it keeps the compare checkbox testids and `models-count` text but not the row text.
   If the redesigned row changes these strings, `support/models-page.ts` is the one place to adjust.
5. Locators that assume Base UI behavior, not source-verified at runtime: Enter on the focused trigger opens the combobox; `data-highlighted` marks the
   highlighted option (class `data-highlighted:` in `components/ui/combobox.tsx`); the provider option has role `option` named `NanoGPT`.
6. Race: the dialog resets its provider to the first configured one when `configured` changes identity (`AddModelDialog` effect). A late provider
   refresh between choosing the provider and the picker steps would show as a failure, not a wrong pass.
7. Other real-server specs now boot with extra configured providers (above).
