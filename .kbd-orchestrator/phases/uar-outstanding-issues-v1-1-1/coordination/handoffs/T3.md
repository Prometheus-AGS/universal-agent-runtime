# T3 source handoff

Stage: Execute. Source authoring only. No verification command executed.

Changed files: `src/uar/security/credentials/{migration,maintenance,store,principal_store,mod,policy}.rs`
and `src/uar/api/credentials.rs`. S3 supplied both additive schema assets and
Surreal migration registration under state ownership; trust did not edit them.

`CredentialRecord.row_revision: Option<String>` decodes historical absence. All
supported put/rotation writers assign a fresh canonical UUID. Lead's system-seeding
constructor supplies None and the store assigns it. Memory now coordinates legacy,
principal and journal state under one RwLock. PostgreSQL uses transaction/source
uniqueness/row locking and Surreal uses compare/copy/journal transactions. Fixed
source keys use the disjoint five-element principal-fixed-local-v1 JSON array;
legacy three-element keys and historic receipts remain compatible.

`PrincipalCredentialStore` CRUD/migration requires `CredentialOwnerBinding`.
`migration_inventory()` returns metadata only, excluding ciphertext/hints/reasons;
`initialize_revisions()` updates missing revisions without changing secrets or
timestamps. `unresolved_local()` detects unresolved fixed-local ancestry after a
bound miss, but committed journals prevent resurrection after destination deletion.

`ProviderService::migrate_legacy_conditioned(..., if_match: Option<&str>)` extends
legacy compatibility; existing `migrate_legacy_credential(...)` remains unconditioned.
`migrate_principal_credential(owner, source_owner_key, scope, source_scope_id,
provider_id, reason, if_match)` requires exact installed mapping. Both authorize
before journal replay. Conditioned retries compare original receipt precondition;
first apply compares row revision inside the copy transaction. Receipts gain only
optional metadata fields. No decrypt/re-encrypt or secret-derived digest.

`migration_preview(&UserContext, &CredentialTenancyPolicy, MigrationPreviewQuery)`
checks verified trusted-host authority internally, not just at the HTTP route.
Cursor uses authenticated encryption and binds full verified host owner + host ID,
policy/mapping revisions and ordered key tuple. Limit 1–500, cursor bound 4096,
strict query/header/body parsing, bounded count dimensions and selected status
precedence are implemented. HTTP errors expose safe codes only.

`credentials::maintenance::initialize_revisions(&AppConfig, writers_quiesced: bool)
-> anyhow::Result<RevisionInitializationSummary>` is the lead CLI dispatch target.
It rejects missing acknowledgement before connecting, opens only the configured
credential backend, installs additive metadata schema through existing migration
mechanisms, initializes missing metadata, and returns safe counts/errors. It starts
no HTTP, provider or MCP service. Normal startup/preview never backfills.

The uncomfortable limits: explicit acknowledgement cannot prove every replica is
quiesced; SQL and Rust are authored but have no compile/runtime receipt. In
particular Surreal compare semantics, metadata snapshot consistency and cancellation
replay await actual durable-backend integration. Current official documentation was
consulted for transaction result indexing and rand::uuid::v4 syntax:
https://github.com/surrealdb/docs.surrealdb.com/blob/main/src/content/reference/rust/concepts/transaction.mdx
