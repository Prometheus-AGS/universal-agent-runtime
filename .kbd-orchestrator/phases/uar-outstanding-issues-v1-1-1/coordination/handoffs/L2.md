## Changed files and interfaces

- src/config.rs: default operator-owned provider credential policy configuration
  and validation; explicit credentials initialize-revisions CLI with mandatory
  writers-quiesced acknowledgement passed to maintenance.
- src/main.rs: dispatch maintenance without server/provider/MCP startup and print
  only serialized safe counts; initialization failure uses a generic diagnostic.
- src/lib.rs: independent immutable credential policy in AppState. Existing
  optional response-quality orchestrator compatibility slot remains unset at
  startup; correction clients are admitted for the requesting principal.
- src/server.rs: constructs policy independently of optional encrypted service;
  installs policy into ProviderService and RunManager and supplies concrete
  CredentialApiState. Direct /v1/messages and optional correction resolve the
  selected catalog route through policy before constructing a client. Messages
  carries its session selector. Errors use safe allowlisted categories. Optional
  correction startup no longer constructs an unowned global provider client.
- src/embedded.rs: builder accepts optional credential policy and service;
  defaults to single-owner policy and wires manager independently of storage.
  This does not confer shared provenance on an opaque supplied SDK driver.
- src/uar/security/claims.rs: readonly issuer_kind accessor preserves captured
  delegated identity and unchanged general principal keys.
- src/llm/mod.rs: private native Anthropic SSE framing module.
- src/uar/settings/manager.rs: system credential seed provides absent revision;
  supported store writes assign a fresh revision.
- Cargo.toml and matching Cargo.lock runtime package entry: 1.1.1 only.
- example.config.yaml: explicit single-owner policy example and optional stable
  installation/mapping fields; no model or new authentication default.
- docs/releases/v1.1.1.md: setup, maintenance, tenancy, compatibility, recovery
  limits and receipt/publication conditions. Actual observed publication fields
  remain P3 evidence, not missing implementation text.
- Necessary explicit SecurityConfig fixture literals in src/uar/security/middleware.rs,
  src/uar/api/a2a/handler.rs, src/uar/api/a2a/grpc.rs,
  tests/jwks_es256_verification.rs, tests/test_a2a_grpc.rs,
  tests/a2a_thread_service.rs, tests/settings_persistence.rs and
  tests/context_history_integrity.rs include the new default policy field.

No workflow, dependency pin, Dockerfile, vendor/submodule or UI source changed
under this task. Root setup retains loopback/offline/no implicit model defaults;
explicit deployment settings and administrator provider verification/seeding
keep their separate authority. Runtime T2 source consumes decisions before client
capture and inherited paths narrow retained bindings.
