# S4 source handoff — durable recovery fixtures and image adapter

Changed paths:

- `tests/durable_ingestion.rs`
- `scripts/release/uar_1_1_1_recovery.py` (new)

The existing `tests/principal_knowledge_namespace.rs` already contains the
required isolated SurrealKV, network-Surreal, and PostgreSQL child-process
fixture: it seeds a subject-like legacy row, proves it remains invisible to the
same verified principal, persists a new principal record, and denies another
principal and issuer. It is retained without a redundant source rewrite.

`tests/durable_ingestion.rs` now authorizes an unexecuted remote Surreal child
stage with no durability attestation. It creates an owned KB, submits an actual
multipart HTTP request, requires `503`, and checks no document/job exists. The
normal child stages still set the explicit attestation and cover accepted
source/job persistence through separate process boots.

`scripts/release/uar_1_1_1_recovery.py` exposes the lead contract:

```python
REQUIRED_SCENARIOS["recovery"]
run_group(context) -> {"status": ..., "scenarios": [...]}
```

It requires exactly these scenarios: unattested remote refusal; attested
Surreal/PostgreSQL upload, restart, owner retrieval and principal denial;
legacy/principal cold readback; joined quiesce/reclaim with absent/replayed
evidence controls; and qualified supervisor reclaim with valid, absent,
forged, and replayed evidence controls. It receives only runner-owned lifecycle
and private infrastructure helpers, uses real HTTP routes and scoped database
readbacks, records only identifiers/count digests, and never offers a force
recovery path.

The adapter does not fabricate a qualified supervisor proof. A valid positive
requires the existing `scripts/supervisor/controller.py` deployment contract,
retained qualification evidence, an actually contained predecessor, and its
real runtime configuration/mounts. If those private collaborators are absent,
the required supervisor case is `BLOCKED`; a sentinel, invented Kubernetes IDs,
or self-asserted controller qualification cannot become positive evidence.

No test, build, formatter, lint, import probe, schema validation, or review
ran. The new adapter, supervisor fixture, both backend paths, image lifecycle,
and all real recovery observations remain unverified until L4 opens the phase
gate.
