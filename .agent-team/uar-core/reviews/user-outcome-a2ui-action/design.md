## Chosen behavior and ownership

- `a2ui-artifact-block.tsx`: validate the project profile/version/components first, then convert only the version literal to the pinned upstream v0.9 representation before parsing. Keep source messages/project profile unchanged; remove nonexistent constructor option. Retain the processed surface/model as stable memoized render data. Standard surface child subscribes to processor/surface action events in an effect, snapshots the emitting surface's actual current dataModel at click, calls typed platform action hook with the source native run ID, and cleans subscriptions on content/unmount. The actual `chunk.runId` flows through `a2ui-chunk.tsx`; unbound diagnostic/story surfaces remain display-only with an honest unavailable-action message, not an arbitrary current run.
- A narrow new platform `a2ui-actions` capability exports typed action input/receipt/hooks. Its graph record is keyed by source run + surface. Domain obtains exact source native run/session from authenticated inspection, rejects missing/foreign source identity, serializes one pending submission globally with existing single-stream UI ownership, posts exactly once, records actual accepted continuation identity, and attaches the admitted run to its canonical conversation using existing stream processing. No remote mutation transport or optimistic action queue is registered, so graph reconnect cannot replay the POST. Only safe public state/IDs/error category persist; raw user payload/private surface content do not become a receipt entity.
- Same-operation synchronous duplicates are rejected at domain entry before I/O, and the fieldset is disabled while pending/accepted/running. It stays disabled after an uncertain POST result or a completed single submission of this rendered surface; a new generated surface is a new operation. A known refused request may present an explicit retry only if no continuation was admitted. No automatic retry of the POST exists because current endpoint has no idempotency key. A page/process crash between server acceptance and local receipt persistence remains a disclosed limitation; frontend cannot certify host exactly-once behavior.
- `chat-stream-store.ts` (exclusive ownership confirmed by root): extend the existing loop with a narrow attach-continuation path. It GETs the already admitted native run stream with cursor0 and existing AG-UI adapter, canonical message updates, RunEventPersistence, tools/skills/A2UI/selection projections, terminal/error handling and saved-history flow. It does not append a fake user message, issue another chat POST, cancel an unrelated live stream, reconstruct a model or alter selection-notice code. Existing normal start behavior remains intact. Attachment resolves only after successful terminal; cancellation, error, missing terminal and persistence/transport failure do not become “completed”.
- Add schema registration at normal graph bootstrap and typed hook exports from `@/platform/entities`. Auth is the same-origin existing authenticated host transport, not credentials captured from components or new env lookups.

## Minimal UI contract

Within existing A2UI display section, controls remain the same renderer/native catalog. A fieldset provides native disabled behavior and aria-busy while request/model work is pending; status text uses polite status feedback and error uses role=alert with no HTTP/private error dump. Initial: no success claim. Submitting: “Sending action…”. Admitted/streaming: “Agent is responding…”. Success only after actual successful stream terminal: “Response complete”. Known refusal: “Action was rejected. Try again.” Unknown outcome: “Action outcome is unconfirmed. Do not submit again.” Stream failure after admitted identity remains visible with that actual continuation retained; no new POST occurs. No modal, focus move, palette/font change, new motion or animation is introduced.

## Resolved action-state contract after isolated critiques

This section controls any broader wording above. One submitted action is supported per `(source native run ID, surface ID)`. Content refresh, same-ID update/delete/recreate and component remount do not establish a new submission entitlement. A genuinely different source run or surface ID is a different operation. No unimplemented generation identity is invented.

The same single-stream authority used by ordinary chat synchronously reserves an ownership token before source inspection or POST. Both normal send and action acquisition consult it. Two surfaces cannot acquire it together. A busy acquisition sends no request and displays “Another response is active. Wait for it to finish.” The domain guard and current bound surface callback both reject unavailable/pending/consumed or stale actions; fieldset disabling is only the visible affordance. Snapshot/detach the emitting surface's current model at the click boundary. Do not rely on native fieldset behavior to suppress custom/programmatic catalog callbacks.

Persist a pending graph receipt before the POST; a failed pre-I/O receipt/source inspection releases only its own reservation and sends no POST. A successful, fully parsed202 receipt is recorded before attaching the admitted continuation. Explicit pre-admission authentication/not-found/declared-action validation refusals from the mounted endpoint may restore retry eligibility; transport errors, unexpected errors, malformed202 or failed receipt persistence are uncertain and cannot. The implementer must bind this classification to the actual handler statuses; an arbitrary4xx is not automatically definite refusal.

Retain global stream ownership through accepted attachment and terminal processing. Every terminal/failure/finally releases only the matching token; never cancel or release another operation. An uncertain POST consumes this surface operation but releases its UI reservation after request handling has quiesced, allowing unrelated chat; the possibly admitted server run remains explicitly unconfirmed and is not silently retried or attached. Accepted attachment failure likewise retains the actual continuation ID and consumed surface while releasing only its own quiesced UI slot. These local mechanics do not assert that an unobserved server run stopped. Unmount alone does not reset the receipt or release an operation still owned by its async task.

Unbound surfaces display nearby “Actions unavailable: this surface is not linked to a run.” Interrupted accepted response displays “The response was interrupted” with its actual retained continuation identity and no POST retry. Pending/consumed controls expose busy/disabled state through the current callback guard and supported renderer semantics as well as the fieldset. Preserve focus; no recovery state moves it. Browser and assistive-technology behavior remain unverified.

After document/process restart, a restored pending receipt without a current document-owned async task is outcome-unconfirmed and consumed. Show “Action outcome is unconfirmed. Do not submit again.” It owns no orphaned local stream reservation, so unrelated chat remains available. A same-document component remount with its original live task retains that live task's pending state. The distinction uses actual document-local task ownership, not receipt age. This transition cannot discover an unknown continuation, prove the server stopped or close the acknowledged crash window. Author unrun coverage for pending-before-POST, accepted-before-receipt crash/reload, orphaned pending restoration and same-document remount with live ownership.

## Implementation source-identity correction — 2026-10-25

The repository workspace copy of entity-graph-core contains a runPersist catch that swallows failures, but the actually installed3.0.3 distribution's persistNow directly awaits persistGraphToStorage and propagates failure. Its PersistGraphToStorageOptions has no scope member. Production integration uses the actually exported installed `persistGraphToStorage({storage,key})` with the actual bootstrap adapter and awaits the confirmed write before POST. No unsupported scope property is used. This corrects the earlier broad research statement; no runtime claim is inferred.

A second actual pinned constructor mismatch was observed in both eagerly imported UAR catalogs: source supplied a version string as Catalog's components argument. Root explicitly authorized removing only that obsolete argument from basic/entity catalog construction. Project profile/version validation remains unchanged at its boundary; only the representation passed to pinned upstream parser changes to v0.9.

Source run binding is the actual stream's normalized durable run ID, retained in A2UI payload metadata.source_run_id. Ordinary chat chunks initially carry a frontend-local display run ID; that must not become the mounted action's source. The typed chunk view prioritizes the captured metadata, which is retained in its portable payload on history reload. No run is inferred from a surface name or tool identifier.
