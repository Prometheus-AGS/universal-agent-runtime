## Dispatch and authority map

`src/llm/router.rs` already defines `RouteRequirements { needs_tools, needs_reasoning, needs_vision, needs_structured_output, min_context, max_cost_per_1m_input, preferred_provider }`, and `ModelRouter::route_with_preferred_model`. It first filters capabilities/health, then honors exact preference. `src/llm/catalog.rs::CapabilityFilter::matches` checks the boolean requirements and minimum context. No exclusion field exists today. `/api/uar/route` constructs the same requirements from untyped JSON fields in `src/server.rs::api_route_model`, but it does not execute or bind a run.

Runtime candidate construction uses enabled provider/model rows and capability flags from `src/llm/registry.rs::ModelConfig` (including `supports_vision`, `supports_tools`, `supports_structured_output`, context/output values). Router also adds configured healthy compile-time catalog candidates absent from runtime candidates. Explicitly excluded/disabled models must not re-enter through this catalog fallback. `ProviderRegistry::resolve_to_llm_config` checks disabled provider, cooldown and explicitly disabled known model; it is not the same as current owner/model verification admission. `src/uar/api/targets.rs::ModelSources::verified_model` checks current model proof; `allowed_overrides` derives allowed identities from a bound artifact's receipt.

`src/uar/runtime/manager.rs` around 6468 intentionally bypasses availability replacement for team attempts and explicit `target_selection`. Ordinary routing builds requirements with only `preferred_provider` and defaults around 6502. No match or a failed routed config resolution falls back to `preferred_llm_config`, which would defeat any new hard requirements unless changed to a named refusal. When no registry is present, skill override is also applied without this router. Inherited `bindings.models.for_policy(...)` is another destination path to enforce without reconstructing authority.

`src/uar/domain/artifact.rs::ProviderPolicy` has `default: ProviderSelection` and `fallbacks: Vec<ProviderSelection>`, **no broad provider allow/deny fields**. `src/uar/domain/policy.rs::{RunPolicy, EffectiveRunPolicy, ModelRoute}` has model selection and resource scope restrictions; do not invent an existing model-exclusion policy. Manager currently disables failover for explicit target selection, uses artifact fallback identities for credential-bound/team runs, and otherwise uses configured failover list around 6600. Existing selected billing identity, owner/tenant, verified model selection, immutable team receipts, per-run credentials and continuation constraints are hard boundaries; capability filtering may reduce destinations but must not expand them or replace an exact admitted target.

Minimal #464 slice: derive one immutable requirement value from **actual admitted canonical input and supplied tool/response contract**, intersect with authoritative existing destination scope, and enforce it on primary, inherited/bound route, registered/no-registry path, and fallback. Tools available to a run and a hard demand for native tool controls need an explicit rule; do not infer all runs require tools just because UAR has a registry. Structured output should derive from the existing `ResponseFormat` contract, vision from canonical image parts, context capacity from final destination preparation. Keep query and actual dispatch on a shared evaluator, while query output remains advisory and never becomes authority. If public exclusions are added, validate fully qualified identities and define them as subtractive restrictions. This is an additive planned contract, not a field already present.

## Budget and fallback constraints to preserve

- `src/llm/orchestrator.rs::{DestinationRequestPreparation, DestinationRequestPreparations, ProtectedContinuity}` bind destination template/profile, final budget, exact settings and compatible opaque provider continuity. `prepare_attempt` / `prepare_user_attempt` are used per primary attempt and fallback; fallback loops currently check cooldown, then prepare the actual destination before `open_driver_stream`. Add capability refusal before every send without bypassing preparation. Response format already refuses captured Anthropic paths that cannot preserve it.
- `src/uar/runtime/manager.rs` installs destination preparations into the orchestrator and wraps graph primary inference in `DestinationBudgetDriver`. Preserve it; avoid rerouting after model/credential/budget bindings were captured. Re-evaluate final request requirements on actual prepared messages/tools before fallback so growing tools or retained image history cannot evade the first-turn constraint.
- `src/uar/runtime/context/budget.rs::{DestinationLimits, RequestBudgetContract, BudgetInput, BudgetOutcome, WireContract}` and `src/llm/liter_driver.rs` enforce endpoint-bound final serialized requests. The only current named strict wire contract is `SyntheticOpenAiCompatibleChatV1`; the exact model constant is deliberately synthetic. Real model JSON tokenization is not automatically exact image-token billing/capacity evidence.
- `src/uar/runtime/context/token_service.rs::TokenService::count_messages_with` reads only `message.content.as_text()`; it ignores image parts and later text parts. A working typed image path must not upgrade this estimate into a hard-fit guarantee or invent a flat image token allowance. Keep existing output ceilings and explicit unproven-count disposition. The real visual counting policy is a material planning choice below.
- `src/uar/runtime/context/reduce.rs::protected_groups` already protects nonempty multimodal `Parts` and full tool groups byte-for-byte; `canonical_prose_spans` and `summarizer.rs` prohibit summarizing protected multimodal content. Preserve explicit overflow when required groups cannot survive. E07 also requires cold restoration; storing text-only history would invalidate this despite correct reducer code.
- Existing secret projection in `turn/host/event_projection.rs` visits image URLs. Do not assume generic credential scrubbing removes base64 image bytes from logs, Debug, request snapshots or memory. Record hashes/byte counts/order/model/disposition, not raw images or URLs containing credentials. Audit actual capture points as part of the future owned implementation, not a new telemetry subsystem.

## Smallest useful supported slice

Recommend initially advertise only the two aliases of the ordinary OpenAI chat handler, with bounded **inline base64 PNG/JPEG image parts in the current user message**, plus mixed text/multiple-image ordering, streaming and nonstreaming. Make text-only callers unchanged. Do not add URL retrieval. Keep image attachment IDs, remote URLs, native/AG-UI/A2A/SDK image convenience forms, caller-tool multimodal history and unqualified provider adapters explicitly unsupported unless their complete path is included in this phase. Existing attachments/text processing should remain functional; image attachments must get explicit unsupported-image error rather than JSON-text success.

Use existing `MessageContent` as canonical internal representation, plus a separate derived text projection for guardrails/matching/memory where necessary. Validate and retain typed image content through session creation, restored append, checkpoint/restart and final message serialization. Do not parse any arbitrary string beginning `[` into parts: that would alter ordinary text semantics. Bound bytes, decoded file type and image dimensions before model admission; limit total image count and bytes at the turn, including actual data in retained requests. Values must be adopted explicitly rather than borrowing the upload service's 50 MiB constant.

The supported provider adapter must be named separately from public protocol: a real OpenAI-compatible provider via Liter is the smallest candidate. Supporting Anthropic protocol or native Anthropic driver in the same phase adds distinct conversion, governance and budget work. Explicit rejection/downgrading current support claims is a valid bounded disposition; it does not close all of #463 automatically. The claim should remain the exact adopted slice until all advertised paths are qualified.

Likely ownership files for the slice: `src/server.rs`; `src/uar/runtime/turn/request.rs` (and the existing turn plan/resolved files if the type flow requires them); `src/uar/runtime/manager.rs`; `src/session/thread.rs` only if a reusable typed append helper is needed; `src/llm/router.rs`; `src/llm/orchestrator.rs`; existing budget/profile types only for a proven image-counting contract; `docs/product-support-matrix.json`, `docs/releases/v1.4.0-rc.1.md`, SDK/protocol support docs and one narrow OpenSpec delta. `src/llm/anthropic_driver.rs` or upload storage should stay outside scope unless that route is adopted. Do not modify pinned Liter submodule to duplicate already-present image types/conversion.
