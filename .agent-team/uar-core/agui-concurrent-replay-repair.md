# AG-UI completed concurrent result replay repair

Gate007 source/evidence: matrix scenario agui:simultaneous-identical-results failed because completed retry returned HTTP 409 thread_run_not_closed. The winning run in the recorded response was 3535c902-04b0-4b03-8d0e-1ed201305d97 on thread dbce092d-deac-40bf-abd2-da08b66f4630. The request driver deep-copies prior history before concurrent sends; each copy chooses a new wire run ID. A later retry by the original driver therefore uses another wire identity with the original handoff as parent. The HTTP evidence records responses, not rejected request run IDs, so those exact generated IDs are unavailable in the artifact.

Source defect: the latest-run/parent guard for admitting new execution ran before shared completed-result replay. Once the winning continuation became the latest row, an identical retry naming the original predecessor was rejected before consulting its completed caller batch.

Changed only src/uar/api/agui.rs. Before the latest-run guard, tool-result requests with an explicit parent can resolve an already Completed caller batch through the authenticated caller ID and the exact owner/agent/thread/workspace predecessor. The common prepare path still validates the complete visible predecessor, schemas, protocol, IDs, and exact result batch. Replays load and attach to the winning durable wire/native run with a matching previous_wire_run_id; no new run or tool effect is admitted. Pending and Claimed batches do not take this path and retain the existing latest-active/new-execution guard. Existing current authenticated admission policy and source ownership checks still precede access.

No tests, builds, probes, imports, network calls, checks, formatting, or runtime commands executed by this writer. Lead owns local functional retest. Source repair remains unverified. No change to background observer/cleanup ownership in this patch; the separate gate007 forced shutdown issue remains assigned to its owner.
