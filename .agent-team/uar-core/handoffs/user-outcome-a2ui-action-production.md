## Production changes, file by file

- `frontend/src/platform/entities/a2ui-actions/contracts.ts`: typed standard action input and normalized `A2uiActionReceipt` entity keyed by exact source native run/surface, with pending/responding/completed/rejected/uncertain/interrupted states. It stores only public identities/status, not raw field/action/private prompt payloads.
- `.../a2ui-actions/api.ts`: same-origin authenticated-host GET of exact source run/conversation and exactly one POST to its mounted standard action endpoint. Parses the actual202 source/continuation acknowledgment before treating admission as known. Only401/403/404 and the exact mounted declared-action422 message are definite POST refusals. Other422s, unexpected statuses, network loss and malformed accepted bodies are uncertain. No automatic POST retry or independent credentials are introduced.
- `.../a2ui-actions/stream-ownership.ts`: synchronous document-local token reservation shared by normal chat and standard actions. A stale release cannot unlock a newer owner. This is transient workflow ownership, not execution authorization.
- `.../a2ui-actions/durability.ts`: actual bootstrap-adapter persistence binding. Missing persistence fails before POST.
- `.../a2ui-actions/domain.ts`: owns action sequencing and graph receipt writes. Persists pending before source GET/POST, records accepted identity before stream attachment, and records completion only after successful actual stream/persistence. Synchronous pending duplicates and every consumed source/surface operation are rejected before I/O. A document-local consumed set also protects against an uncertain post whose graph write fails. Definite pre-admission refusal restores retry eligibility. Unknown/post-admission failure consumes this operation and releases only its own quiesced UI slot; it does not claim an unobserved server run stopped. Restored pending without a current document task becomes uncertain; restored responding becomes interrupted with actual identity. Remount during a live task retains pending ownership.
- `.../a2ui-actions/hooks.ts` and `index.ts`: narrow status/continuation/intent hooks and schema registration. No remote mutation transport/action queue is registered, so reconnect cannot replay a standard action POST.
- `frontend/src/platform/entities/index.ts`: typed capability export plus existing library's actual `persistGraphToStorage` export.
- `frontend/src/entities/bootstrap.ts`: registers the new entity and binds confirmed `persistGraphToStorage({storage,key:"uar:entity-graph"})` through the actual initialized adapter. Removes the binding at teardown. Installed3.0.3 API was read directly; no unsupported runtime.scope argument remains. The workspace library source's persistNow catch differs from installed3.0.3; the design's appended source correction records this distinction.
- `frontend/src/stores/chat-stream-store.ts`: normal start and action admission consult the same reservation. Added attachContinuation using the existing AG-UI parser, event persistence, message chunks, selection projection, tool/A2UI rendering and saved-history flow. It GETs the already admitted native run at cursor0, does not append a fake user message, does not POST a new chat or cancel an unrelated active stream. Only the exact admitted run's persisted native RUN_FINISHED counts as continuation success; errors/cancellation/missing terminal/transport or persistence failure reject. Attachment additionally awaits insertion of the actual completed continuation message before the receipt can say completed. Existing normal-start EOF behavior remains outside this scoped change. A2UI display payload metadata now retains actual durableRunId as source_run_id rather than frontend-local display IDs. All selection/hydration branches remain present.
- `frontend/src/features/chat/components/a2ui-artifact-block.tsx`: validates the project v0.9.1/uar.a2ui/1 shape and executable-content boundary, then translates only the upstream parser representation to pinned v0.9. Removes the nonexistent MessageProcessor third argument. A small standard-surface child owns effect subscription/cleanup to the actual SurfaceModel.onAction, snapshots detached current model/context before awaiting, guards stale/pending/consumed callbacks, and invokes only typed platform intent. Fieldset disabled/busy plus nearby status/alert text provide initial/unbound/pending/responding/complete/rejected/uncertain/interrupted feedback without focus changes or redesign. Unbound surfaces are explicitly display-only. Actual admitted identity remains visible after interruption. UI-local error fallback never asserts model success when receipt persistence failed.
- `frontend/src/features/chat/ui/chunks/a2ui-chunk.tsx`: passes exact source run binding, preferring captured persisted metadata.source_run_id over frontend-local chunk display run IDs. Existing portable A2UI payload retains this metadata on reload.

## Preserved decisions and limitations

One submitted action is supported per `(source native run,surface)`; same-ID update/delete/recreate/remount does not authorize another submission. Unknown outcomes are deliberately consumed because the backend standard-action endpoint has no idempotency key or discovery contract for an unknown accepted continuation. The process-crash gap between host acceptance and confirmed local receipt cannot be closed by frontend state; this implementation does not claim server exactly-once behavior. Unrelated chat can proceed after an unconfirmed operation releases its own local slot, without asserting that the possibly admitted server run stopped.

All guards trace to observed defects/real boundaries: missing callback/edited data forwarding; actual source identity; duplicate callback and shared stream competition; mounted endpoint admission ambiguity; confirmed receipt persistence; terminal truth; unbound/stale surface callbacks; project profile/executable-content validation before version representation normalization. No new dependency, redesign, fake provider, placeholder external hook, speculative timeout, raw component fetch, graph import in a component or unrelated entity migration was added.

The source-only UI guidance/synthesis and design-review provenance remain in the design artifact. Instrumented Impeccable audit/critique/polish/detector/browser and accessibility measurements remain deferred under the operator lock. This is not an instrumented critique PASS or WCAG certification.
