## Adversarial corrections — persistence, hydration and announcements

The fresh-context adversary identified three source-backed warnings. This section supersedes the earlier insufficient assumptions; no product verification has run.

1. Add frontend/src/platform/pglite/client.ts explicitly to the source boundary. insertMessage must sanitize selection chunks before serialization, stripping transient announce=true. rowToMessage must validate/normalize selected-agent entries even when stored chunks is nonempty and preferred over portable decoding. A shared pure parser checks source/selected/child/roster IDs, reserved MIME+payload identity agreement and stable semantic ID; malformed stored selection-shaped chunks become hidden diagnostic raw chunks rather than positive selection. Other chunk semantics remain unchanged. The portable artifact remains an extension, not a new cross-platform ContentBlock union.
2. Own explicit history ordering in existing message/stream entrypoints. Make loadMessagesFromDb single-flight per thread with a transient in-flight Promise map; concurrent callers await the same operation, failures propagate and remove the map entry. startStream awaits that boundary BEFORE inserting the optimistic user message or beginning network/stream reduction; failure surfaces a history-load error and does not dispatch a model request. A load requested while that thread actively streams must not replace owned in-flight message state; a late load result also checks streaming state before replacing records. The existing mount effect catches and surfaces load errors rather than silently discarding them. No new business entity store or adjacent broad message-state migration is introduced. Future fixture must cover delayed hydration plus concurrent selection/replay.
3. Announcement is a consumed UI-only request, not a persistent render flag. A feature hook owns a per-document Set of consumed semantic selection IDs (no agent definitions or business metadata), and atomically claims an ID in an effect only when the current accepted-live chunk requests it. The effect updates a separate visually hidden polite status string after mount; the visible selection text itself is ordinary historical text. The consumed ID survives renderer remount, while restored chunks force announce=false. Component-local state/ref alone is insufficient. This is allowed transient accessibility mechanics, not duplicate domain state; no graph/service/transport access is added to the renderer. Hooks never set state in render. Actual screen-reader behavior still requires the deferred runtime gate.

Source fixtures will cover nonempty raw stored-chunk sanitation, invalid metadata, stable identity through both protocol forms, persisted duplicate insertion, delayed history loading and a renderer remount with one consumed announcement.
