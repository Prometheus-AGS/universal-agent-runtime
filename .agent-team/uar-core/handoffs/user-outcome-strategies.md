## Observed problem and chosen design before production edits

The mounted SkillService's Llm branch currently calls keyword matching; legacy resource-free classifier factory substitutes Hybrid for Llm/LocalEmbedding; WASM classification always errors; registry vector search itself silently substitutes keyword on missing resources or failures; hierarchy makes one generic summary with min(mid,long) output budget. These labels cannot certify the named behavior.

Chosen minimal design:

- Introduce a pure governed skill-ranking function that accepts the run's captured LlmDriver, destination model and RequestBudgetContract. It sends only public eligible metadata and user intent, performs final-wire preflight, requires a successful complete stream and exact finite unique registered labels, and returns typed candidates without direct activation. No independent Orchestrator/provider construction, secret resolution or fallback is allowed. Root must place it after governed model capture; current ranking precedes capture and cannot honestly call a governed model there.
- Resource-free classifier factories return an explicit unavailable implementation for resource-dependent backends; no Hybrid relabeling. A new factory receives the captured governed driver/model/contract for Llm and existing vector resource for LocalEmbedding. Existing caller error fallbacks must be removed by the lead for configured required backends.
- Implement the existing WASM WIT with the pinned wasmtime Component Model host, no WASI/system/network imports, fixed fuel/memory limits and result validation. Compilation/component loading is authored source only; no component or compiler is executed in this task. Guest-returned errors remain errors, never successful empty rankings. Feature-disabled configurations fail clearly.
- Hierarchy retains recent turns verbatim, assigns older explicitly host-marked prose to chronological long-term fact extraction and mid-term narrative summarization, gives each tier its own aggregate token budget, uses only the already governed summary driver/request contract, and atomically publishes both tiers only when all calls succeed. Protected records stay byte-identical and in order. Generated summaries retain original authority role; no system-message elevation. Small older histories need only midterm; long-term exists when older history spans more than the recent-turn horizon. A directive wrapper over the existing summarizer changes the task prompt before dispatch, with final-wire preflight occurring on the actual modified request.
- Acceptance cases observe mounted configuration, candidate/activation evidence and actual canonical/prepared history; they ask genuine inference to use planted facts. Observer programs query actual run-owned durable data and mounted inspection APIs. Missing observation evidence is BLOCKED, never a green stub. Keep U09–13 required denominator even if an integration remains incomplete.

Uncomfortable limitation: the present normal SkillService route ignores legacy classifier selection, and the current manager ranking phase precedes governed model capture. Fixing factory internals alone cannot make a normal customer setting effective. The lead must integrate both settings selection and the governed driver timing, and preserve any unresolved backend in the implementation ledger.
