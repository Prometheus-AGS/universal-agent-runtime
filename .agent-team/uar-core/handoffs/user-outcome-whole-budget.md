## Observed defect and design

`cases_strategies.whole_budget` required durable `context.request_budget`; `observers_strategies.budget` required `context.host_effect_receipts`. Neither had a production writer. The harness could not prove its claims. Added real serialized-request receipt projection and replaced invented effects evidence with queries against actual durable host admission and canonical receipt tables.

Uncomfortable limit: an ordinary model token count remains approximate even when the exact request bytes are available. The manager's estimated context window and reserved response allowance are capacity estimates, not a model/vendor framing proof. A protected preparation failure has no final provider serialization because preparation never completed. These receipts explicitly identify that different boundary rather than pretending a rejected request reached the wire.

## Production changes and contracts

- `vendor/git/liter-llm/crates/liter-llm/src/client/mod.rs`: local additive pure `DefaultClient::chat_stream_request_body(&ChatCompletionRequest) -> Result<Vec<u8>>` delegates to the same existing private `prepare_request(..., Some(true))` as the actual streaming call. This includes model-prefix stripping, output-cap field rewriting, provider transformation and extra-body merging. It does not dispatch or invoke the `_raw` transport. Existing managed Tower budget/cache/rate controls remain in the actual `.chat_stream` path. Lead explicitly authorized this minimum local vendor API patch after source inspection showed a reconstructed UAR body could differ from actual wire and `_raw` would bypass managed controls. This local vendor change must be included in source inventory/upstream patch provenance; no upstream publish or dependency replacement performed.
- `src/llm/liter_driver.rs`: obtain these actual prepared bytes on preserving OpenAI/Azure/generic-chat/profiled paths, count under the existing contract (ordinary fallback `ApproximateCl100kJsonV1`), retain only hash/length/count metadata, and prepend normalized `uar.request/budget_receipt` to the existing stream. `chat_stream` remains the dispatch method. Existing strict validated bytes must equal actual prepared bytes before dispatch; no exact destination is invented and no strict contract is relaxed. No payload/instructions/secrets are persisted in the receipt.
- `src/uar/runtime/manager.rs`: retain the actual leaf receipt in durable run context (`request_budget` latest, `request_budgets` per-attempt history), enrich only a matching captured primary destination with the manager's actual input allowance/output reservation. A fallback without an identical captured allowance does not borrow primary limits. For pre-dispatch manager context/protected-history rejection, retain a separately labeled approximate preparation-candidate receipt with stable source error code before the existing terminal persistence. Existing production admission/effect state is unchanged.
- `scripts/acceptance/cases_strategies.py`, only `whole_budget`: require actual serialized ordinary request hash/length/representation; allocate a unique caller session ID for every frozen vector request so HTTP errors correlate to one actual run. Allow the current mounted HTTP 500 adapter mapping only when the observer proves the precise durable budget refusal. Reject borrowed exact counting quality at a different rejected preparation boundary. The frozen request's fields are preserved except its dynamic correlation session ID.
- `scripts/acceptance/observers_strategies.py`, only `budget`: require nonempty unique session correlation for HTTP errors; read `canonical_tool_receipts` and `tool_admission_evidence` (including root descendants) through actual owned durable store. Zero model accounting admissions plus zero durable host admission/effect records, a failed durable run and stable budget rejection code establish refusal. Missing tables/read failures are not converted into empty evidence.

Actual successful leaf receipt schema: `schema_version=uar.request-budget.v1`, `representation=final_provider_request`, `serialized_request=true`, `destination_model`, `count_quality`, `counting_revision`, `counted_input_tokens`, `serialized_bytes`, `serialized_sha256`, `tools_included=true`, `instructions_included=true`, `fit_guarantee`, `output_ceiling_enforced`, `reserved_output_tokens`. The manager adds `input_allowance` and `outcome` only for its captured primary model; `within_allowance` with approximate quality is not proof of exact vendor fit. Tools/instructions inclusion means the complete serialized body was counted, including any empty tool set, rather than separately adding a prompt-only count.

Rejected preparation schema uses `representation=protected_preparation_candidate`, `serialized_request=false`, approximate model-message/tool estimate revision, actual candidate message/tool/world counts and manager allowance/reservation; on the existing `context_overflow` or `protected_history_overflow` boundary it adds `outcome=protected_overflow` and `failure_code`. This is not a manufactured final wire receipt. The fixture proves zero admission/provider/effects at that earlier boundary, not equality of a fictional exact serialized request.

## Scope and remaining risk

Refusal evidence uses existing durable rows; no production `host_effect_receipts=[]` placeholder was added. The ordinary serialized count is recorded after stream establishment; failed transport establishment has no new successful leaf receipt. Cache hits retain their logical prepared-request count and must not be misrepresented as physical network dispatch evidence.

No verification result exists. The exact-boundary case is still required only for an actually installed exact destination; ordinary approximate counts cannot borrow the supplementary synthetic COUNT fixture.

## Packet cumulative call/cost envelope source findings

Existing host `CostBudgetTracker`/`ModelCallBudget` (`src/uar/runtime/cost_budget.rs`) intersects thread budgets, checks run/session scopes, finite session USD limits and catalog pricing, request/token rates and remote cumulative grants. `BudgetedModelDriver::stream` records durable model admission before entering the inner provider. `RemoteUsageGrant` supports `max_total_model_requests`, `max_total_tokens`, `max_total_cost_usd`, `max_total_tool_calls`; these apply to an admitted shared delegation lineage, not arbitrary independent acceptance runtimes/observer subprocesses.

`LlmConfig` exposes `budget` and `rate_limit`, and Liter defines `LlmBudgetConfig { global_limit, model_limits, enforcement }`. However source inspection of `src/config.rs::build_client_config` shows it forwards timeout/retries/base URL/transport settings and does **not** copy those budget/rate-limit fields into the constructed ClientConfig. Do not assume configuring those fields enables managed enforcement through this UAR construction path. Even an explicitly installed Liter hard-budget layer keeps client/managed middleware spend state rather than one durable packet-wide scope across independently constructed runtime clients, observer model calls, KB embeddings and restarted processes. Do not label a draft 600-call envelope as enforced by these controls. A packet-wide budget requires an actually shared admission authority or an explicit runner ledger covering every model/embedding entry; that broader implementation was not added here. Freeze realistic source-derived limits after case expansion, and disclose unenforced cumulative limits until the controlling path exists.
