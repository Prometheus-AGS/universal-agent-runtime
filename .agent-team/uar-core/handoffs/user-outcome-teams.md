It uses the existing `UAR_ACCEPTANCE_STARTUP_CONFIG`/`observers_startup.Store` connection contract and exact run-derived isolated schema/database. Catalog owner is deliberately distinguished from session credential principal: catalog uses `v1:s:`/tenant subject partition, while sessions use `v1:k:` credential-principal keys. The observer reads exact unique invocation-owned attempt session IDs in the already-isolated DB, checks the actual credential-principal marker and canonical receipt principal agreement. It does not incorrectly compare session owner to catalog owner. Thread ancestry/root/run IDs are crosschecked. History is privately parsed into call IDs/names/positions, result IDs/positions, selected artifact/message IDs and a digest; raw messages/system prompts/model reasoning/source payloads are never emitted. Attempt output is represented by digest only in the observer; exact useful output predicates use the mounted authorized execution summary. Foreign-sentinel scanning happens privately and returns a boolean. Actual context selection metadata and consumption timestamps are separate fields, so selection alone cannot masquerade as model consumption.

No generic success callback or absent observer is accepted as implementation. Missing session history/canonical receipt/provenance becomes a failed/blocked case, never a green result.
