# Bounded independent protocol and artifact fixtures

Source-authored only. No install, compiler, import, subprocess, Docker, peer or API operation has run while these files were authored. Run them only inside the explicitly approved final whole-set batch. They extend the existing Cucumber framework; they are not a second global acceptance runner.

## Source identity and independent counterparts

- UAR's selected MCP client revision is `2025-11-25` in `src/mcp/interaction.rs`. RC4 pins the runtime to `rmcp =3.9.0`. The installed independent MCP gate uses the sealed `rmcp =3.8.0` peer from Gate 087 so the same external counterpart exercises the upgraded runtime. `examples/production_mcp_peer.rs` implements its loopback Streamable HTTP negotiation, routing and transport using the official SDK. The gate records the SDK version of the actual peer. This does not add a UAR MCP-server role.
- The peer binds loopback on an ephemeral port, emits `PEER_URL`, and creates `UAR_QUALIFICATION_MCP_JOURNAL` with create-only semantics. Externally provision that path as `target/production-artifact-qualification/<case>/mcp-calls.txt`. `qualification_echo` appends/fsyncs one bounded synthetic marker. The additional `qualification_wait` and `qualification_fail` tools trace SDK call lifetime or return an intentional error without a business effect. An invalid marker is an SDK error without journal effects. No credential, filesystem-read/write or network-fetch tool is offered.
- `a2a-client.mjs` resolves the independently maintained official `@a2a-js/sdk=1.0.1` from the existing entity-graph-a2a workspace install/pnpm lock, checks the installed package version, and uses its real `ClientFactory`, card resolver, JSON-RPC transport and streaming decoder. Request shapes and enums follow that package's checked source usage. The peer URL and advertised card must identify the selected UAR instance; streaming/version/method outcomes are observed, never replaced by supplied success receipts.
- Both counterparts are distinct from UAR's own protocol implementation. A version pin and authored source do not prove interoperability. MCP direct negative controls are separate from UAR's actual governed allowed/denied tool runs. A2A optional transports/extensions/resume remain unqualified unless separately selected.

The peer is an ordinary root example, uses only existing root SDK/axum/tokio/serde/schemars dependencies and Cargo.lock, and imports no UAR runtime implementation. The lead owns its required-features target declaration. To rebuild a peer from a different SDK pin, qualify it separately and update the fixture's peer receipt version before use.

The container must carry labels `dev.prometheus.qualification.case`, `.base-url`, `.workspace` matching those selectors, plus `org.opencontainers.image.revision` matching the source commit. The volume must carry the same case ownership label. Steps inspect only projected container/image/volume identity, platform, timing, exit state and mount information; they never inspect Config.Env or acquire/send credentials. Linux/amd64 and exact content-addressed image IDs are required. The externally configured gateway supplies identity and remains stable across selected host transitions. The suite never restarts/signals a shared native service or provisions authentication.

MCP infrastructure must preconfigure the candidate's policy to permit only `Agent::"pr476-mcp-<case>"` to request `Tool::"pr476peer__qualification_echo"`, `Tool::"pr476peer__qualification_wait"` and `Tool::"pr476peer__qualification_fail"`, with ordinary approvals still required. Steps create only that disposable agent, grant the loopback peer per run and decide the actual pending approval. They do not loosen global policy or mutate another chat's settings. The provider/model and tiny synthetic responses must be provisioned by the host; paid provider execution is not authorized by this fixture.

Document cases require a configured local/mounted embedding route and document-intelligence; the OCR input additionally requires the advertised OCR backend. Missing prerequisites are an explicit blocked/failing case to reconcile, not a skipped pass. All five inputs are generated in memory by `tests/fixtures/production-readiness-documents/fixtures.mjs` and uploaded through the real KB API. There is no extractor shortcut or direct database write.

## Finite lifecycle transition sequence

1. Externally provision the actual **prior** image on a fresh owned volume and identity endpoint. `@capture-prior` creates one uniquely marked document using the public upload/index path, verifies retrieval and preserves the exact image/source/volume binding. The capture is create-only; do not overwrite an earlier case.
2. External host stops/drains that owned container. `@observe-stopped` requires the real stopped state, exit code0, exact prior image/volume and finish timestamp after startup. External host starts the same image. `@observe-restart` requires a later start than that observed stop and retrieves the same canary. These cases do not infer clean exit from a running image.
3. External host installs the actual **current** image on the same owned volume and gateway. `@observe-upgrade` requires a different content-addressed image ID and source revision, the exact retained volume and original canary. Same-binary restart cannot count as an upgrade.
4. External host produces a stopped-store backup at `target/production-artifact-qualification/<case>/backup.tar` and restarts the current image. `@delete-after-backup` binds the backup bytes' SHA256, deletes only the synthetic canary through the public API, and proves its document and retrieval result absent. No success callback or database seeding is accepted.
5. External host stops the current container, restores the bound owned backup and restarts the current image with the same volume/gateway. `@observe-restore` requires unchanged backup hash, current image/volume, a later actual startup, and retrieval of the previously deleted original document/marker. An unchanged running store cannot pass the deletion/restoration oracle.
6. External host installs the exact captured prior image for the chosen supported rollback pair. `@observe-rollback` requires that original content-addressed image, the same volume and the restored canary; only then it deletes the owned canary KB. An incompatible prior schema must remain an honest failed/blocked rollback, never a silently changed source pair.

These observations do not certify every migration race, lost-commit state, session/checkpoint recovery or interrupted external effect. The transferred #421 real-path integration cases and #466 canonical guarantee table own those claims. Do not expand this canary's useful evidence into global recovery certification. Each observed stage has its own result; the final #465 artifact record consumes them only if the declared whole-set exit contract is satisfied.

## Additional bounded lifecycle/protocol cases

It records only bounded synthetic marker observations, emits an actual initial SSE delta and holds the active-cancellation stream for at most45seconds. Counts/price/token accounting are not fabricated by this peer; missing provider usage must remain explicitly uncertain under UAR's contract. No key is read or sent by the behavior steps.

`@admission-races` performs two actual concurrent identical budgeted full-harness admissions, reads terminal history, repeats the same admission, rejects changed input and counts actual provider arrivals. Its abandoned-response control cancels the HTTP response body after a real accepted response, resolves the admission through the public GET route, and requires no redispatch. This is **HTTP reply loss**, separate from the real-store post-commit acknowledgement fixture in actor_host.rs. Do not relabel it as a DB outage.

For `@capture-epoch`, preserve the stable owned model peer and identity endpoint while the host restarts/upgrades UAR. `@observe-epoch` must see an actually changed runtime epoch/start time and explicit refusal of the captured task/cursor/controls. The full-harness admission ledger is process-ephemeral; an old admission GET must be unresolved, never silently imported as a new effect. The fixture does not re-POST an old admission after restart because process-local idempotency is not a cross-epoch grant.

PG18-specific stages use an independently provisioned pinned Forge18 container selected by `UAR_POSTGRES_CONTAINER`, its owned `UAR_POSTGRES_VOLUME`, and `dev.prometheus.qualification.database-container` on the UAR container. The pinned image reference and `/var/lib/postgresql` volume mount are observed without reading environments/passwords. `UAR_OTHER_OWNER_BASE_URL` is a second external identity endpoint; bind it in `dev.prometheus.qualification.other-owner-base-url`. The script never obtains either owner's credentials. Store backup bytes at `target/production-artifact-qualification/<case>/postgres-backup.sql` via external infrastructure. Capture owned canary→external backup→delete/absence→external restore→original fact/provenance/other-owner refusals are distinct stages. Preserve actual host administrative commands in final receipts; synthetic API observations cannot certify the dump command itself. The final restore stage removes only its synthetic KB.

Existing scoped-resource lifecycle tests and the new real embedded migration/actor acknowledgement fixtures are named in `docs/releases/v1.4.0-final.md`. ## F10/F11 independent task/call cancellation and error cases

Source-only additions; no protocol operation or verification was executed. The exact pins and authentication boundary above remain unchanged. The extended existing `@independent-mcp` scenario and new `@independent-a2a-cancellation` scenario require the same case-owned controlled model peer (`active-model.mjs`) and its already documented URL label. They add no dependency or global runner.

For A2A, the official1.0.1 SDK opens the advertised JSONRPC task stream, captures the actual original task/context IDs, and waits until the controlled provider confirms an open stream before reading that task as active. It calls **Client.cancelTask**, rather than aborting the observer or using the native run endpoint. Success requires the same task/context, decoded TASK_STATE_CANCELED in both response/stream/readback, no later completed status and no cleanup/execution uncertainty disguised as cancellation. The controlled provider connection must close before its natural fixture expiry. Missing-task GetTask/CancelTask must decode TASK_NOT_FOUND/-32001; repeated cancellation of the terminal original task and cancellation of an independently completed task must decode TASK_NOT_CANCELABLE/-32002. A separate fresh official-client task must still complete. Original IDs, SDK-decoded errors and wire statuses remain in the receipt. A refusal of the selected genuinely active local cancellation case records its exact SDK error and task readback and fails the case; it is not skipped or relabelled successful cancellation. Observer abort is only cleanup and preserves the SDK's actual signal through the fetch wrapper.

For MCP, `examples/production_mcp_peer.rs` creates an additional create-only fsynced `mcp-calls.protocol.jsonl` beside the existing echo journal. The official rmcp RequestContext supplies the **original MCP request ID and cancellation token**. `qualification_wait` records started, then either cancelled, handler_dropped with actual SDK token state, or expired after30seconds; it performs no business effect and never returns a successful completion. A Drop record cannot masquerade as cancellation unless the actual SDK cancellation token is set. `qualification_fail` records the original request ID and returns an official `CallToolResult::error` (`isError:true`), distinct from a transport failure. Existing direct malformed/unsupported controls retain their JSON-RPC errors.

The controlled model selects those exact declared MCP tool names once; it never fabricates peer results or retries an unknown call. The Cucumber scenario approves the real pending call, waits for its counterpart started journal and native tool invocation ID, then requests native-owner cancellation. It requires that **same** official SDK request to terminate once via cancellation (or token-confirmed handler drop), never expiry, with no successful tool result/effect claim. UAR may conservatively retain outcome_unknown after a lost cancellation response; the receipt preserves actual tool-admission/accounting state rather than inferring remote rollback from the fixture's no-effect design. An uncertain session and its disposable agent are retained for reconciliation, not deleted to manufacture closure. The next independent call must return its explicit application error as a failed native tool result and application_failed admission; a fresh approved echo proves a new binding remains usable. No replay of the pending original call is allowed.

This qualifies only the selected UAR MCP-client→official-server Streamable HTTP call path and official-client→UAR A2A v1 JSONRPC task path if the eventual real observations pass. No new UAR MCP-server role, optional transports, remote effect rollback, cross-process task exclusion, reconnect/resume or all-SDK guarantee follows. Source inspection establishes the available SDK/production paths, not that their cancellation propagation has passed. A protocol cancellation failure or claimed success despite uncertainty remains a material F10/F11 gap to report at the permitted gate.
