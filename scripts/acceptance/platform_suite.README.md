# Four-platform controller

`platform_suite.py` is authored source, not an executed gate. It runs the complete macOS and Linux collections serially, then the iOS simulator harness, under one live `PacketProcesses` owner. Windows remains BLOCKED and Android DEFERRED. The controller never claims four-platform certification or phase acceptance.

The exact future CLI is `FROZEN_PYTHON ABSOLUTE_PLATFORM_SUITE_PY --config ABSOLUTE_PRIVATE_CONFIG --evidence ABSOLUTE_NEW_EVIDENCE --execute`. Importing the module starts nothing. This command requires separate explicit verification approval after actual preparation, source inventory, signing/adoption, and fixture composition.

The private version1 configuration requires `executable:true`, `fixtures` with exactly `macos` and `linux` frozen `{path,sha256}` references, `windows:"BLOCKED_NO_EXECUTION_HOST"`, `android:"DEFERRED_OPERATOR_SCOPE"`, finite `wall_seconds` at most43200 and `ios_seconds` at most7200, `max_corrections`, `remaining_global_repairs`, `private_scope`, `scope_id`, and `ios`. All counters include prior work: the named global limit clamps these maxima further. Correction slots are shared across both collections, not granted separately per platform.

`ios` names frozen `runner`, `python`, `selection`, `source_inventory` file references, prepared `artifact_root`, and a new `private_config_path` immediately under the existing owned0700 `private_scope`. The controller writes that0600 file exclusively from the genuine fixture's ingress token environment reference, bare wire model and configured model context window. It never copies an upstream provider key into the simulator. It removes only its exact unchanged private file afterward. Simulator-side ownership and cleanup are governed by the iOS runner's separate scope marker.

`approval` is a private frozen reference to exactly `{operation:"execute-uar-four-platform-suite",operator_approved:true,projection_sha256:SHA256_OF_CANONICAL_CONFIG_WITHOUT_APPROVAL}`. The approval projection is local admission only; it cannot replace actual operator instruction or signed canonical KBD authority. A populated config or true boolean alone grants no execution authority.

Both platform fixtures must name identical source, limits, case manifest, budget proxy executable and configuration bytes, environment references and epoch. macOS uses `macos-native`; Linux uses `linux-container` with its actual extracted ELF/image binding. The controller loads and validates the actual fixtures before starting one budget owner. Each 582-row collection borrows that same owner and carries shared HTTP/output/time/correction consumption. It never restarts the proxy or seeds a new ledger between platforms. The iOS runner observes and uses the same still-live proxy and durable counters.

An ordinary unresolved product failure does not stop an independent platform. Unconfirmed ownership/cleanup, changed controller inputs, exhausted/unknown shared allowance, or a source correction requiring later-platform artifacts to be rebuilt stops dependent dispatch and leaves those platforms NOT_RUN/BLOCKED. In particular, a corrected source cannot silently inherit a later platform's old artifact. A fresh exact inventory/artifact/authority continuation is required for that source wave. Passing earlier receipts retain their original source/artifact identities.

The declared server denominator is97 cases times3 repetitions times2 durable backends on each operating system:582 macOS rows and582 Linux rows. The iOS manifest declares11 predicate groups across3 repetitions, executed in6 seed/restore XCTest process invocations; this is a separate denominator and not33 HTTP cases. User-facing outcomes, source/compile checks, supporting admission integration, and release claims are reported separately.

All source authoring remains unverified. The exact future packet must also name required Parking Lot/main/spec/profile gates, independent reviewers, fixture effects, host-network route evidence, and cleanup. No GitHub Actions product testing or publication is included.
