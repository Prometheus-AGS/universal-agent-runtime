# Legacy declaration migration for the narrow team execution profile

Status: Delivery A/B implementation guidance, 2026-09-30. The frozen narrow execution-profile contract governs these migration decisions. Delivery B source wiring is being completed; its completed-delivery build, functional operation, and installed acceptance remain pending. This document is not an acceptance receipt.

## Evidence and scope

Historical baseline: UAR `006eeaf1f90e0a640b0f8fd568419badac5f4320`; The Boss `c00d9b68695fb452d1f09bd4b154582ecaad0035`. Delivery A adds the source implementation described below without rewriting stored definitions, private bindings, admission captures, or previous receipts. Repository-relative source links identify the implementation seams; line numbers describe the historical baseline and may move.

The draft.2 AgentDefinition uses `/context`, whose closed schema defines `mode`, `artifacts`, `history` and `memoryScopes`; DeploymentBinding separately uses `/contextGrants`. These are the exact source identifiers. `context` is not a TeamDefinition field in the baseline. See [common.schema.json:91](../../../docs/agents/collaboration/v0.1.0-draft.2/schemas/common.schema.json:91), [AgentDefinition:79](../../../docs/agents/collaboration/v0.1.0-draft.2/schemas/agent-definition.schema.json:79) and [DeploymentBinding:196](../../../docs/agents/collaboration/v0.1.0-draft.2/schemas/deployment-binding.schema.json:196).

The ordinary semantics resolver evaluates the five semantic requirement fields but not these legacy selection fields. The team receipt narrows KB/presentation selection to none and disables ambient memory. The selected-artifact path consumes **attempt** `contextArtifactIds`; it does not consume AgentDefinition `/context/artifacts` or binding `/contextGrants`. See [runtime_semantics.rs](../../../src/uar/compiler/collaboration/runtime_semantics.rs), [team policy](../../../src/uar/compiler/collaboration/team_execution/resolution.rs) and [typed context selection](../../../src/uar/compiler/collaboration/team_execution/context.rs). Baseline storage/schema acceptance is not execution support.

## Shared instructions and exact member skills

TeamDefinition may now omit `/instructions` or provide the closed `{revision,digest,text}` object. Null, unknown fields, invalid revision, a mismatching exact UTF-8 text digest, or text exceeding 16,384 bytes refuse with the corresponding `/instructions` pointer. Existing definitions without guidance stay readable. No background migration rewrites their identities. Publish a new immutable team/package version to add or revise guidance; ordinary expected-revision binding rules still apply.

The compiler retains all SkillRef fields in `uar.collaboration/skill-refs` and the canonical definition extension; the preferred-ID list is only a compatibility index. Member resolution compares ID, version, digest, required flag, config, entrypoint and requiredTools against the installed private binding and captures full resolved references. Context selection preserves those exact metadata values without exposing installed filesystem locations or claiming skill-body activation. See [compatibility projection](../../../src/uar/compiler/collaboration/validation/projection.rs), [legacy artifact conversion](../../../src/uar/compiler/to_artifact.rs) and [exact installed resolution](../../../src/uar/compiler/collaboration/bindings.rs).

Selection receipts record the actual admitted root/approval scope, self/assignment, authorized bounded roster and selected input/artifact/message/skill metadata. A continuation includes every ordered terminal target outcome, including failed/cancelled rows with no artifacts. Revoked disclosure edges or oversized required roster/selection material refuse; no truncated guidance or partial success view is dispatched. Token count remains explicitly unknown unless independently qualified. This does not implement shared knowledge bases, implicit memory/history, or nested teams.

## Field-specific changes

Binding field diagnostics carry exact RFC 6901 pointers, dispositions, stable reason codes, safe messages, sourceKind and sourceDefinition where the source is immutable. Binding-owned fields use sourceKind DeploymentBinding and the effectiveBindingRef identifies the exact private revision. Team-package preflight tags each member diagnostic with its own immutable identity rather than attributing it to the package. A package-level diagnostic identifies the affected member definition; it does not blame a generic package field. Report each unsupported item, not only the first failure. Retain the original requested value in protected/portable storage according to its existing classification; do not copy private grant values into public diagnostics.

## Required RAG and supported fields retain their current meaning

`/ragConfiguration` is an existing semantic requirement with `{required, value}`. The baseline emits `runtime.component-unavailable` at `/ragConfiguration`; `required: true` is already `required-unsupported` and blocks activation. Do not describe this as a newly introduced refusal. An optional unsupported RAG value remains preserved/excluded with its diagnostic, not executed by this profile. See [existing unsupported mapping:337](../../../src/uar/compiler/collaboration/runtime_semantics.rs:337) and [required disposition:370](../../../src/uar/compiler/collaboration/runtime_semantics.rs:370).

`/contextStrategy` is separate from `/context`: supported policies already map into the ordinary turn strategy. Preserve that mapping; do not refuse it merely because nonempty selection fields above are unsupported. `/apiHarness`, model requirements and prompt dialect keep their field-specific supported/unsupported semantics and the approved exact request-profile repair. No broad `context unavailable` error replaces their diagnostics.

Preserve every exact SkillRef and DeploymentBinding `/skillBindings`: ID, version, digest, required flag, configuration, entrypoint and required tools. Existing exact skill resolution and selected skill/MCP/tool policy remain valid. An empty skill selection means none; it does not authorize ambient inventory. A skill carrying a separately supported tool is not evidence that implicit shared KB/history/memory selection is implemented.

`/representationGrantRefs` is distinct private authority state with existing validation. This migration does not reject all nonempty representation references, issue authority, rewrite grants or conflate them with `/contextGrants`.

Legacy Markdown import currently emits empty `permittedChildren` and `{mode: none, artifacts: [], history: none, memoryScopes: []}` while retaining source descriptor/legacy sections. Those empty canonical fields remain compatible. Nonempty preserved source prose is evidence of its original authoring, not by itself an executable canonical selection or a reason to reject every imported agent. Reconcile author intent explicitly if translating it into one of the fields above; retain source/authored-field provenance. See [migration defaults:141](../../../src/uar/compiler/collaboration/migration.rs:141).

## Optional declarations, install/launch and rollback

Draft.2's closed `/context` and `contextGrants` shapes have no per-selection optional flag. A caller cannot add `required: false` to those arrays/values and claim compatibility. The approved next schema may explicitly express optional selections. Only a declared supported schema representation can exclude an unsupported optional request with an `optional-unsupported` field diagnostic and requested/excluded/effective receipt entry. Legacy nonempty selections remain required by default; no blanket optional downgrade.

Delivery A installs these diagnostics at executable binding/member preflight and rechecks them at launch against current capability; team-package preflight must inspect the actual member definitions rather than admit solely from a service capability bit. Pending/runnable attempts with old bindings do not bypass unsupported semantics. Empty legacy declarations remain narrow and need no background migration. Planning/import/export preserves immutable definitions even when executable activation is refused.

Operator remediation sequence: inspect exact pointer and installed definition/package/binding revision; choose to preserve the requirement and wait, or deliberately author a new compatible immutable version; recompute canonical/exact-byte digests and lock closure; preflight against the chosen runtime profile; explicitly install/rebind with expected revision; inspect requested/effective/excluded receipt and localized Boss guidance before admitting work. Never overwrite the same immutable ID/version with a different digest, silently revise historical receipts, erase external effects, or tell the operator to delete storage. A compatible rollback is another explicit rebind and does not reverse already issued effects.

The uncomfortable limitation is deliberate: a definition that previously appeared executable while its nonempty resource selection was ignored may now refuse. That change protects the declared task contract. The implementation/release must publish these exact field dispositions; source implementation is not evidence that packaged refusals or their UI have operated.

## Catalog authority and recovery

The catalog holds one nonexpiring execution claim with catalog, stable service, generated incarnation and epoch identities. CAS transitions hold, drain and release the claim; elapsed time or a new process never authorizes takeover. Admissions capture the execution fence and effective provider/model/profile/settings identities. Binding preflight, dispatch, actual effect authorization, durable mutation and recovery compare the current fence. A changed provider setting requires explicit rebind, not a silently adopted setting.

Authenticated host administration additionally requires the configured admin key. The owner view is available at `GET /api/v1/collaboration/execution-owner`. `POST /execution-owner/quiesce` stops admission, cancels and joins the exact owned runtime jobs and their actor roots/children, then records an internal `trusted-runtime-joined` fencing receipt. Unknown already-issued effects stay uncertain and reservations remain held; a stop proof does not certify them. Full process shutdown releases ownership only after global resource cleanup succeeds.

`POST /execution-owner/reclaim` consumes an existing internally recorded fencing receipt, expected epoch, operator reason and fresh replacement incarnation. A caller-supplied string or Boolean cannot create that proof. Reclaim preserves queued attempt/run/task/member IDs, the original admitted fence, effective settings and reservation; an explicit transfer record supplies the new execution fence. Successful results keep their output/dependency readiness even when accounting is unknown.

The fixed host-only `POST /team-instances/{team}/tasks/{task}/admit-queued` accepts the ordinary admission request but leaves its intent undispatched. `POST /team-instances/{team}/attempts/{attempt}/dispatch` accepts `{commandId, expectedTeamRevision}`, records an idempotent dispatch command and invokes the existing controller. It creates no new scheduler. Replacements retaining queued work must use the same stable service placement ID with a new incarnation; another stable service requires an explicitly compatible rebind.

External crash exclusion is deliberately unavailable: this release has no trusted host process-tree evidence importer bound to the dead process identity. A crashed owner without an internally recorded joined proof stays held, and reclaim refuses. A future host-bound implementation must record process start identity, join the owned complete process tree, authorize and persist a replay-safe proof, and retain uncertain issued effects. It must not accept an unchecked caller assertion.
