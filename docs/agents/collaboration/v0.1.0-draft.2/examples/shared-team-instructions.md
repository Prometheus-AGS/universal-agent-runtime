# Shared team instructions

This optional fragment belongs at `/instructions` of a newly authored TeamDefinition. It is not a complete installable package or runtime acceptance evidence.

```json
{
  "revision": 1,
  "digest": "sha256:d6404a82c03bbe7bbc071602806cf42ac899f773e29f0408e7cf8e5ecff8bc60",
  "text": "Keep work scoped to the assigned task."
}
```

The digest hashes the exact UTF-8 text bytes, excluding the JSON quotes and any file newline. Preserve text byte-for-byte; do not trim it. When changing text or revision, publish a new immutable team/package version, recompute the team content digest, exact package file byte digests and lock closure, then explicitly install/rebind. Existing examples and historical receipts remain unchanged.

The runtime projects this guidance separately from selected task input, scoped artifacts and authorized peer envelopes. Its context receipt identifies instruction order, actual member/run/root/approval scope, current directed-edge-authorized roster, complete continuation outcomes, selected sources and token-count quality. Skill selections identify exact metadata/configuration; they do not claim that every skill body was activated.

Shared arbitrary knowledge-base retrieval, implicit memory/history and nested team execution remain unsupported by this narrow profile. A portable schema is not proof that a runtime enforces these semantics.
