UAR Tool Normalizer

A streaming middleware crate that wraps any backend model provider and normalizes tool-calling behavior to be structurally identical to Claude Sonnet 4.6 — regardless of whether the backend speaks structured tool calls natively, requires prompt injection, or emits plain text.

uar-tool-normalizer Rust Axum 0.8 Depends: uar-driver-core v0.1.0-draft 2026-04-08
§ 01 — Motivation

Why This Crate Exists

UAR's LiterLlmDriver routes requests to 142+ model providers. Every provider speaks a different dialect of tool calling — or none at all. Downstream consumers (the OpenFang tool runner, AG-UI event emitters, gen_ui_core's A2UI pipeline) are written against Anthropic's native tool-use contract. Without normalization, every consumer must handle every provider's divergent behavior.

This crate eliminates that surface area entirely. It wraps any DriverTrait implementor and produces a NormalizedEvent stream that is structurally indistinguishable from a real claude-sonnet-4-6 response — complete with ToolUseStart, ToolInputDelta, and ToolUseComplete events carrying valid tool_use_ids, parsed JSON inputs, and correct stop reasons.

Invariant: Every consumer of UAR's event stream can assume claude-sonnet-4-6 semantics. Whether the actual inference is running on a local candle-vllm Qwen2.5 instance at zero cost or a remote Groq Llama endpoint is an infrastructure detail. The tool semantics contract never changes.

§ 02 — Capability Taxonomy

ToolCallCapability

Every backend model is assigned one of four capability levels. The level determines which normalization strategy the ToolNormalizerDriver applies. Profiles are registered at startup and resolved by model-string pattern matching.

Rust uar-tool-normalizer/src/capability.rs 
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ToolCallCapability {
    /// Model produces structured tool-call blocks natively.
    /// Applies to: Anthropic, OpenAI, Gemini 1.5+, Mistral Large, Cohere Command R+.
    /// Strategy: pass-through with response-format normalization only.
    Native,

    /// Model supports grammar-constrained JSON output (Hermes, Functionary, candle-vllm
    /// with --grammar-file or --guided-json flag). Produces valid JSON but not in a
    /// tool-call envelope — the driver must wrap the JSON into a ToolUseComplete event.
    /// Strategy: inject JSON schema as grammar constraint; parse structured output.
    GrammarConstrained,

    /// Model is instruction-tuned to follow a specific tool-call format when prompted.
    /// Applies to: Qwen2.5-Instruct, DeepSeek-V3, Llama-3.1-Instruct, Phi-4-Instruct,
    /// Devstral-Small-2, and most instruction-tuned GGUF variants on candle-vllm.
    /// Strategy: inject XML schema into system prompt; extract via streaming state machine.
    InstructionTuned,

    /// Model has no tool-call capability. Pure text generation only.
    /// Strategy: inject few-shot examples + XML schema; aggressive extraction with retry.
    TextOnly,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ToolCallFormat {
    /// Anthropic native: content block with type "tool_use".
    AnthropicNative,
    /// OpenAI native: tool_calls[] array in choices[0].delta.
    OpenAiNative,
    /// Hermes XML: <tool_call>{"name":…,"arguments":…}</tool_call>
    HermesXml,
    /// Llama-3.1 tag: <|python_tag|> or function-call JSON block.
    Llama31Tag,
    /// Generic XML: <tool_call>{"name":…,"input":…}</tool_call> (UAR standard injection)
    GenericXml,
    /// Raw JSON with best-effort extraction.
    RawJson,
}

#[derive(Debug, Clone)]
pub struct ModelCapabilityProfile {
    pub tool_call_capability:    ToolCallCapability,
    pub tool_call_format:        ToolCallFormat,
    pub supports_system_prompt:  bool,
    pub supports_parallel_tools: bool,
    pub supports_streaming:      bool,
    pub max_context_tokens:      u32,
    /// Some models stall on empty tool lists. If true, omit tools when list is empty.
    pub omit_empty_tool_list:    bool,
}
Native
Structured tool blocks
Pass-through with response-format normalization only. OpenAI tool_calls[] deltas are translated to Anthropic ToolUseStart/Delta/Complete events. No prompt modification.
GrammarConstrained
Constrained JSON output
JSON schema injected as grammar constraint parameter. Valid JSON output is wrapped into a synthetic ToolUseComplete event. Works with Hermes 2 Pro and Functionary variants.
InstructionTuned
Prompt-driven XML format
XML tool schema injected into system prompt. Streaming ExtractorState machine intercepts <tool_call> blocks and promotes them to structured events before they reach the consumer.
TextOnly
Few-shot + aggressive extraction
Full few-shot examples + schema injected. Multi-pass extraction with retry budget. Last resort: emit a partial ToolUseComplete with best-effort JSON repair.

§ 04 — Prompt Injection

PromptToolInjector

For InstructionTuned and TextOnly backends, the tool schema must be communicated through the system prompt. The injector serializes the tool list into a deterministic XML block and prepends it to the system prompt before the request reaches the inner driver. Tool definitions are idempotent — injecting the same set twice produces the same block.

Rust uar-tool-normalizer/src/injector.rs

}

    /// Prepend tool schema block to the existing system prompt.

}

Injected system prompt format (GenericXml)

The XML block is injected at the top of the system prompt, separated from the original content by a double newline. The format is deliberately verbose — models respond better to explicit field descriptions than to compact JSON Schema.

XML Rendered injection — GenericXml format 
<tool_definitions>
  <tool name="search_memory">
    <description>Search the agent's long-term memory store.</description>
    <parameters type="object">
      <property name="query" type="string" required="true">
        The search query string.
      </property>
      <property name="limit" type="integer" required="false" default="5">
        Maximum number of results to return.
      </property>
    </parameters>
  </tool>
  <!-- additional tools … -->
</tool_definitions>

To call a tool, emit ONLY the following format with no surrounding prose,
no markdown fences, and nothing before or after the tag on the same line:

<tool_call>
{"name": "search_memory", "input": {"query": "user preference history", "limit": 3}}
</tool_call>

After receiving tool results in a <tool_result> block, continue your response
normally. You may call multiple tools sequentially but not in parallel.

---
Original system prompt continues below.

Hermes format divergence: When ToolCallFormat::HermesXml is selected the injector switches to the Hermes 2 schema convention (<tool_call>{"name":…,"arguments":…}</tool_call> with arguments instead of input). The extractor normalizes both key names to input before emitting events, so consumers always see the Anthropic-style field name.

§ 05 — Streaming Extractor

ToolCallExtractor — Streaming State Machine

The extractor is the core of the normalization work. It sits in-line on the NormalizedEvent stream and transforms raw text events into structured tool-call events without buffering the full response. It is a pinned, stateful Stream adapter.

ExtractorState

Rust uar-tool-normalizer/src/extractor.rs 
/// The complete state the extractor carries between stream polls.
enum ExtractorState {
    /// Normal text emission. MessageDelta events pass through unchanged.
    Text,

    /// We have seen the opening of a tag but not the closing >.
    /// Buffering tag bytes to confirm the tag name.
    InOpenTag {
        buf: String,
    },

    /// Inside a confirmed <tool_call> block.
    /// Accumulating JSON content. Emitting ToolCallDelta events as bytes arrive.
    InToolCall {
        /// The JSON being accumulated. Pre-allocated to avoid reallocs.
        json_buf: String,
        /// Synthetic tool-use id for this invocation (uuid v4, generated on tag open).
        tool_use_id: String,
        /// Running index of this tool call within the current response.
        call_index: usize,
        /// Whether we've already emitted a ToolUseStart event.
        started: bool,
    },

    /// Accumulated a complete JSON buffer; parsing it now.
    /// Brief transient state — emits ToolUseComplete then transitions to Text.
    Completing {
        json_buf: String,
        tool_use_id: String,
        call_index: usize,
    },

    /// A parse error occurred. Entering retry or degraded-emit mode.
    ParseError {
        raw: String,
        tool_use_id: String,
        retries_remaining: u8,
    },
}

pub struct ToolCallExtractor<S> {
    inner: S,
    state: ExtractorState,
    call_counter: usize,
    format: ToolCallFormat,
    retry_budget: u8,       // default 2 — attempts at JSON repair before giving up
    text_suppress: bool,    // suppress MessageDelta output while inside a tool block
}

impl<S> ToolCallExtractor<S>
where
    S: Stream<Item = NormalizedEvent> + Unpin,
{
    pub fn new(inner: S, format: ToolCallFormat, retry_budget: u8) -> Self {
        Self {
            inner,
            state: ExtractorState::Text,
            call_counter: 0,
            format,
            retry_budget,
            text_suppress: false,
        }
    }
}

State transitions

Stream implementation

Rust uar-tool-normalizer/src/extractor.rs 
impl<S> Stream for ToolCallExtractor<S>
where
    S: Stream<Item = NormalizedEvent> + Unpin,
{
    type Item = NormalizedEvent;

    fn poll_next(
        mut self: Pin<&mut Self>,
        cx: &mut Context<'_>,
    ) -> Poll<Option<NormalizedEvent>> {
        loop {
            let event = match Pin::new(&mut self.inner).poll_next(cx) {
                Poll::Ready(Some(e))  => e,
                Poll::Ready(None)     => return Poll::Ready(None),
                Poll::Pending         => return Poll::Pending,
            };

            match &mut self.state {

                ExtractorState::Text => {
                    if let NormalizedEvent::MessageDelta { text } = &event {
                        if let Some(rest) = text.strip_prefix('<') {
                            // Possible tag opening — transition to InOpenTag
                            self.state = ExtractorState::InOpenTag {
                                buf: rest.to_owned(),
                            };
                            continue; // suppress the delta; wait for tag confirmation
                        }
                    }
                    return Poll::Ready(Some(event));
                }

                ExtractorState::InOpenTag { buf } => {
                    if let NormalizedEvent::MessageDelta { text } = &event {
                        buf.push_str(text);
                        let tag_name = extract_open_tag_name(buf);
                        match tag_name {
                            TagMatch::ToolCall => {
                                let id = new_tool_use_id();
                                let idx = self.call_counter;
                                self.call_counter += 1;
                                self.state = ExtractorState::InToolCall {
                                    json_buf:    String::with_capacity(256),
                                    tool_use_id: id.clone(),
                                    call_index:  idx,
                                    started:     false,
                                };
                                continue;
                            }
                            TagMatch::NoMatch => {
                                // Not a tool tag — flush buffered text and return to Text
                                let flushed = NormalizedEvent::MessageDelta {
                                    text: format!("<{}", std::mem::take(buf)),
                                };
                                self.state = ExtractorState::Text;
                                return Poll::Ready(Some(flushed));
                            }
                            TagMatch::Partial => continue, // still accumulating
                        }
                    } else {
                        // Non-text event mid-tag-open: flush and pass through
                        let flushed = NormalizedEvent::MessageDelta {
                            text: format!("<{}", std::mem::take(buf)),
                        };
                        self.state = ExtractorState::Text;
                        // Return flushed first; re-queue `event` next poll via inner
                        return Poll::Ready(Some(flushed));
                    }
                }

                ExtractorState::InToolCall { json_buf, tool_use_id, call_index, started } => {
                    if let NormalizedEvent::MessageDelta { text } = &event {
                        if let Some(before_close) = split_at_close_tag(text) {
                            // Close tag found — finalize JSON
                            json_buf.push_str(before_close);
                            self.state = ExtractorState::Completing {
                                json_buf:    std::mem::take(json_buf),
                                tool_use_id: std::mem::take(tool_use_id),
                                call_index:  *call_index,
                            };
                            continue;
                        }
                        // Mid-stream JSON fragment — emit ToolInputDelta
                        json_buf.push_str(text);
                        let delta_evt = NormalizedEvent::ToolInputDelta {
                            index:       *call_index,
                            tool_use_id: tool_use_id.clone(),
                            fragment:    text.clone(),
                        };
                        // Emit ToolUseStart on first fragment
                        if !*started {
                            *started = true;
                            // name unknown until JSON is parsed — emit with empty name
                            // (consumer must wait for ToolUseComplete for the name)
                            return Poll::Ready(Some(NormalizedEvent::ToolUseStart {
                                index:       *call_index,
                                tool_use_id: tool_use_id.clone(),
                            }));
                        }
                        return Poll::Ready(Some(delta_evt));
                    }
                    // Non-text events (Done, UsageUpdate) pass through unchanged
                    return Poll::Ready(Some(event));
                }

                ExtractorState::Completing { json_buf, tool_use_id, call_index } => {
                    let json_str = std::mem::take(json_buf);
                    let idx       = *call_index;
                    let id        = std::mem::take(tool_use_id);

                    match parse_tool_call_json(&json_str, self.format) {
                        Ok((name, input)) => {
                            self.state = ExtractorState::Text;
                            return Poll::Ready(Some(NormalizedEvent::ToolUseComplete {
                                index: idx, tool_use_id: id, name, input,
                            }));
                        }
                        Err(_) => {
                            self.state = ExtractorState::ParseError {
                                raw:               json_str,
                                tool_use_id:       id,
                                retries_remaining: self.retry_budget,
                            };
                            continue;
                        }
                    }
                }

                ExtractorState::ParseError { raw, tool_use_id, retries_remaining } => {
                    if *retries_remaining > 0 {
                        *retries_remaining -= 1;
                        if let Ok((name, input)) = repair_and_parse(raw) {
                            let id  = std::mem::take(tool_use_id);
                            let idx = self.call_counter - 1;
                            self.state = ExtractorState::Text;
                            return Poll::Ready(Some(NormalizedEvent::ToolUseComplete {
                                index: idx, tool_use_id: id, name, input,
                            }));
                        }
                    }
                    // Exhausted — emit a degraded ToolUseError and continue as Text
                    let id  = std::mem::take(tool_use_id);
                    let raw = std::mem::take(raw);
                    self.state = ExtractorState::Text;
                    return Poll::Ready(Some(NormalizedEvent::ToolUseError {
                        tool_use_id: id,
                        reason:      format!("json parse failed after retry: {raw}"),
                    }));
                }
            }
        }
    }
}

mem::take discipline: Every transition out of a state containing a String buffer uses std::mem::take rather than .clone(). The state field is left empty (zero-allocation) and ownership moves forward. This is the primary allocation discipline for the hot path — a streaming extractor running across thousands of agent turns must not pressure the allocator on every state exit.

§ 06 — Normalizer Driver

ToolNormalizerDriver

The driver wraps any DriverTrait implementor and produces a fully normalized NormalizedEvent stream. It selects the transformation pipeline at call time based on the capability profile for the active model.

Rust uar-tool-normalizer/src/wrapper.rs 
pub struct ToolNormalizerDriver<D> {
    inner:    D,
    registry: Arc<ModelCapabilityRegistry>,
    model:    String,
    config:   NormalizerConfig,
}

#[derive(Debug, Clone)]
pub struct NormalizerConfig {
    /// Retry budget for the ToolCallExtractor on JSON parse failure.
    pub extractor_retry_budget: u8,          // default: 2
    /// Suppress raw text emission from MessageDelta while inside a tool block.
    pub suppress_tool_text:    bool,         // default: true
    /// If the model omits a tool call entirely, inject a single no-op tool result
    /// so the conversation loop doesn't stall. Applies to TextOnly only.
    pub inject_noop_on_miss:   bool,         // default: false
    /// Parallel tool call behaviour override. If false, emit only the first
    /// tool call even if the model emits multiple in one turn.
    pub allow_parallel:        bool,         // default: from profile
}

impl<D: DriverTrait> ToolNormalizerDriver<D> {
    pub fn new(
        inner:    D,
        model:    String,
        registry: Arc<ModelCapabilityRegistry>,
        config:   NormalizerConfig,
    ) -> Self { ... }
}

impl<D: DriverTrait> DriverTrait for ToolNormalizerDriver<D> {
    async fn stream(&self, req: NormalizedRequest)
        -> Result<impl Stream<Item = NormalizedEvent>>
    {
        let profile = self.registry.get(&self.model);

        match profile.tool_call_capability {

            ToolCallCapability::Native => {
                // Pass-through: inner already speaks structured tool calls.
                // Only normalize event shapes (OpenAI → Anthropic if needed).
                let raw = self.inner.stream(req).await?;
                Ok(format_normalize(raw, profile.tool_call_format))
            }

            ToolCallCapability::GrammarConstrained => {
                // Inject JSON schema as grammar constraint parameter.
                let augmented = inject_grammar_constraint(req, profile);
                let raw = self.inner.stream(augmented).await?;
                // Wrap structured JSON output into ToolUseComplete events.
                Ok(GrammarToolWrapper::new(raw).into_stream())
            }

            ToolCallCapability::InstructionTuned => {
                // Inject XML schema into system prompt.
                let injector = PromptToolInjector::new(
                    profile.tool_call_format,
                    &ToolCallCapability::InstructionTuned,
                );
                let augmented = injector.inject_into_request(req);
                let raw = self.inner.stream(augmented).await?;
                // Stream through the extractor state machine.
                Ok(ToolCallExtractor::new(
                    raw,
                    profile.tool_call_format,
                    self.config.extractor_retry_budget,
                ))
            }

            ToolCallCapability::TextOnly => {
                // Inject few-shot examples + schema into system prompt.
                let injector = PromptToolInjector::new(
                    profile.tool_call_format,
                    &ToolCallCapability::TextOnly,
                );
                let augmented = injector.inject_into_request(req);
                let raw = self.inner.stream(augmented).await?;
                Ok(ToolCallExtractor::new(
                    raw,
                    profile.tool_call_format,
                    self.config.extractor_retry_budget,
                ))
            }
        }
    }
}

format_normalize — OpenAI → Anthropic event translation

Rust uar-tool-normalizer/src/wrapper.rs 
/// Translate OpenAI-style tool_calls[] delta events into Anthropic-style
/// ToolUseStart / ToolInputDelta / ToolUseComplete events.
/// This is the normalization pass for Native-capability models that speak
/// OpenAI wire format (GPT-4o, Groq, Mistral, etc.).
fn format_normalize<S>(
    inner: S,
    format: ToolCallFormat,
) -> impl Stream<Item = NormalizedEvent>
where
    S: Stream<Item = NormalizedEvent> + Unpin,
{
    match format {
        // Anthropic native — already correct shape, pass through
        ToolCallFormat::AnthropicNative => Either::Left(inner),
        // OpenAI native — translate via OpenAiEventAdapter
        ToolCallFormat::OpenAiNative => {
            Either::Right(OpenAiEventAdapter::new(inner))
        }
        // Other Native-tagged formats: shouldn't occur in practice
        _ => Either::Left(inner),
    }
}

/// Stateful adapter that tracks partial OpenAI tool_call deltas and
/// assembles them into Anthropic-style events.
struct OpenAiEventAdapter<S> {
    inner:        S,
    /// In-flight tool calls indexed by OpenAI's tool_call index.
    active_calls: BTreeMap<usize, ActiveOpenAiCall>,
}

struct ActiveOpenAiCall {
    tool_use_id:  String,   // OpenAI provides this in the first delta chunk
    name:         String,   // also in first chunk
    args_buf:     String,   // accumulates JSON string across deltas
    started:      bool,
}
§ 07 — Public Facade

ClaudeSonnet46Shim

The shim is the high-level entry point that consumers use when they want any backend to behave like Claude Sonnet 4.6. It composes the capability registry, injector, extractor, and driver dispatch into a single ergonomic surface. It always reports its model identifier as claude-sonnet-4-6 to callers.

Rust uar-tool-normalizer/src/shim.rs 
pub struct ClaudeSonnet46Shim {
    driver:   Box<dyn DriverTrait + Send + Sync>,
    config:   ShimConfig,
}

#[derive(Debug, Clone)]
pub struct ShimConfig {
    /// The real model behind the shim (e.g. "candle-vllm/qwen2.5-14b-q4").
    pub real_model:      String,
    /// Normalizer behaviour flags.
    pub normalizer:      NormalizerConfig,
    /// Maximum tokens for model responses.
    pub max_tokens:      u32,
    /// If true, return stop_reason "end_turn" on tool calls (Claude behaviour).
    pub claude_stop_reason: bool,   // default: true
}

impl ClaudeSonnet46Shim {
    /// Construct the shim from any DriverTrait + a capability registry.
    pub fn new<D: DriverTrait + Send + Sync + 'static>(
        inner:    D,
        registry: Arc<ModelCapabilityRegistry>,
        config:   ShimConfig,
    ) -> Self {
        let driver = Box::new(ToolNormalizerDriver::new(
            inner,
            config.real_model.clone(),
            registry,
            config.normalizer.clone(),
        ));
        Self { driver, config }
    }

    /// The model identifier this shim presents to consumers.
    pub fn reported_model(&self) -> &'static str { "claude-sonnet-4-6" }

    /// Single-turn streaming request.
    /// Returns a NormalizedEvent stream with Claude-identical tool call semantics.
    pub async fn stream(
        &self,
        req: NormalizedRequest,
    ) -> Result<impl Stream<Item = NormalizedEvent>> {
        self.driver.stream(req).await
    }

    /// Blocking collect — waits for full response, returns assembled MessagesResponse.
    /// Useful for non-streaming agent steps where latency is not the bottleneck.
    pub async fn invoke(
        &self,
        req: NormalizedRequest,
    ) -> Result<AssembledResponse> {
        let stream = self.stream(req).await?;
        ResponseAssembler::collect(stream, &self.config).await
    }
}

/// Assembles a complete response from a NormalizedEvent stream.
pub struct ResponseAssembler;

impl ResponseAssembler {
    pub async fn collect<S>(
        stream: S,
        config: &ShimConfig,
    ) -> Result<AssembledResponse>
    where
        S: Stream<Item = NormalizedEvent> + Unpin,
    {
        let mut text_buf   = String::new();
        let mut tool_calls = Vec::<AssembledToolCall>::new();
        let mut stop_reason = StopReason::EndTurn;

        pin_mut!(stream);
        while let Some(event) = stream.next().await {
            match event {
                NormalizedEvent::MessageDelta { text } =>
                    text_buf.push_str(&text),
                NormalizedEvent::ToolUseComplete { index, tool_use_id, name, input } => {
                    tool_calls.push(AssembledToolCall { index, tool_use_id, name, input });
                    if config.claude_stop_reason {
                        stop_reason = StopReason::ToolUse;
                    }
                }
                NormalizedEvent::Done { stop_reason: sr } =>
                    stop_reason = map_stop_reason(sr, config),
                _ => {}
            }
        }

        Ok(AssembledResponse {
            model:       config.real_model.clone(),
            reported_as: "claude-sonnet-4-6".to_owned(),
            text:        text_buf,
            tool_calls,
            stop_reason,
        })
    }
}
§ 08 — Event Contract

NormalizedEvent Extensions

The crate extends NormalizedEvent with three new variants required to carry full Claude Sonnet 4.6 tool semantics. These variants are additive — existing consumers that don't handle them will receive a no-op default match arm.

Rust uar-driver-core/src/event.rs — additions 
/// Emitted when a tool call begins streaming (name not yet known).
/// Consumers that need to show a "thinking…" indicator can act on this.
ToolUseStart {
    index:       usize,
    tool_use_id: String,
},

/// Fragment of the tool input JSON, emitted as bytes arrive.
/// Allows consumers to show live JSON streaming in the UI.
ToolInputDelta {
    index:       usize,
    tool_use_id: String,
    fragment:    String,
},

/// Tool call fully received and parsed. Name and input are now available.
/// This is the signal for the tool runner to execute.
ToolUseComplete {
    index:       usize,
    tool_use_id: String,
    name:        String,
    input:       serde_json::Value,
},

/// A tool call was detected but could not be parsed after all retry attempts.
/// The tool runner should log this and continue — do not stall the loop.
ToolUseError {
    tool_use_id: String,
    reason:      String,
},

Event ordering contract

For every tool call in a response, the shim guarantees the following ordering invariant regardless of which backend produced the response:

  1. 1

    ToolUseStart

    Emitted on first byte inside a tool call block. tool_use_id is stable for the lifetime of this call. Name is not yet available.

  2. 2

    ToolInputDelta ×N

    Zero or more delta events carrying fragments of the raw JSON input string. Each fragment appended in order reconstructs the full input.

  3. 3

    ToolUseComplete

    Carries the parsed name and serde_json::Value input. This is the authoritative event. The tool runner acts here.

  4. 4

    Done

    After all tool calls and any remaining text content. stop_reason is always "tool_use" when at least one ToolUseComplete was emitted in the turn.

§ 10 — Integration

UAR Dispatch Integration

The normalizer inserts at the UAR dispatch layer. When a request arrives, the provider string determines whether it routes through AnthropicDriver (Phase 1, future) or through LiterLlmDriver wrapped in ToolNormalizerDriver.

Rust universal-agent-runtime/src/dispatch.rs 
pub fn build_driver(
    model_addr:  &str,
    config:      &UarConfig,
    registry:    Arc<ModelCapabilityRegistry>,
) -> Box<dyn DriverTrait + Send + Sync> {
    match parse_provider(model_addr) {

        Provider::Anthropic => {
            // Native Anthropic driver (Phase 1 — uar-anthropic crate).
            // No normalization needed; already speaks Claude semantics.
            Box::new(AnthropicDriver::new(config.anthropic_key(), config))
        }

        Provider::Other => {
            // All other providers: LiterLlmDriver wrapped in ToolNormalizerDriver.
            let base = LiterLlmDriver::new(model_addr, config);
            Box::new(ToolNormalizerDriver::new(
                base,
                model_addr.to_owned(),
                registry,
                NormalizerConfig::default(),
            ))
        }
    }
}

// The shim variant — for consumers that want the full Claude Sonnet 4.6 facade:
pub fn build_shim(
    model_addr: &str,
    config:     &UarConfig,
    registry:   Arc<ModelCapabilityRegistry>,
) -> ClaudeSonnet46Shim {
    let base = LiterLlmDriver::new(model_addr, config);
    ClaudeSonnet46Shim::new(
        base,
        registry,
        ShimConfig {
            real_model: model_addr.to_owned(),
            normalizer: NormalizerConfig::default(),
            max_tokens: config.default_max_tokens,
            claude_stop_reason: true,
        },
    )
}

Zero-change downstream contract: OpenFang's tool runner, the AG-UI event emitter, and gen_ui_core's A2UI adapter all consume NormalizedEvent streams. Adding ToolNormalizerDriver to the dispatch layer requires zero changes in any of those consumers. The new event variants (ToolUseStart, ToolInputDelta) are additive; existing _ => {} match arms absorb them without modification.
