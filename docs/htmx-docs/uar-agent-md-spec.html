§ 01 — Overview

What is UAR-AGENT-MD?

UAR-AGENT-MD is a structured Markdown-based specification that describes a fully executable agent artifact. It is the canonical definition format for agents within the Universal Agent Runtime.

Designed to sit at the intersection of human legibility and machine precision, UAR-AGENT-MD produces a portable, governed, UI-aware, and network-capable agent artifact from a single structured document. Every section has a defined parsing contract; nothing is inferred from convention alone.

The specification is designed to be: human-readable, statically validated, compilable into a runtime-ready agent descriptor, capable of embedding Cedar governance policies, and expressive enough to declare skills, tools, UI contracts (A2UI), MCP dependencies, and Agent-to-Agent schemas in one coherent artifact.

§ 04 — Metadata

Agent Metadata

Top-level identifiers and runtime compatibility declarations. The id, version, and runtime fields are required for descriptor compilation.

YAML ## Metadata 
id:              agent.research.assistant
version:        1.1.0
runtime:        uar>=1.0
schema:         uar-agent-md@1.1
owner:          prometheus
license:        AGPL-3.0
ui_schema_version: a2ui@1
§ 05 — Identity

Principal Identity

Maps directly to Cedar principal attributes. Trust level and classification are enforced at policy evaluation time — they cannot be overridden at runtime.

YAML ## Identity 
principal:
  type:           agent
  namespace:      tenant.default
  trust_level:    medium
  classification: internal
§ 06 — UI (A2UI)

User Interface Contracts

Defines the interactive interface surface available to users or other agents. UI is declared as schema — not implemented as a hardcoded frontend. The runtime resolves artifacts against registered A2UI schemas at boot.

YAML ## UI (A2UI) 
ui:
  artifacts:
    - id:     research.panel
      schema: a2ui.panel@1
      props:
        title:  "Research Assistant"
        layout: two_column
    - id:     research.results
      schema: a2ui.list@1
      props:
        sortable:   true
        paginated:  true

  actions:
    - id:            submit_query
      input_schema:  schemas/query_input.json
      output_schema: schemas/query_output.json
      triggers:
        - skill: web_research
  • Each artifact must reference a valid A2UI schema
  • Input and output schemas must be JSON Schema compliant
  • UI actions must map to declared skills or A2A endpoints
  • UAR validates all A2UI references against registered schemas at compile time
§ 07 — Capabilities

Declared Capabilities

Capabilities are the permitted runtime surfaces. Only declared capabilities may be invoked — the execution engine enforces this strictly.

YAML ## Capabilities 
capabilities:
  - llm.invoke
  - tool.run
  - vector.search
  - net.http.request
§ 08 — Skills

Skill Definitions

Skills are the named, executable units of agent behavior. Each skill declares its entrypoint and required tool dependencies. UAR resolves tool bindings before skill execution begins.

YAML ## Skills 
skills:
  - id:             summarization
    entrypoint:    skills/summarize.rs
    required_tools: [llm.primary]

  - id:             web_research
    entrypoint:    skills/web_research.rs
    required_tools: [web.search]
§ 09 — Tools

Tool Declarations

Tools are typed runtime bindings. LLM tools enforce model allowlists and token budgets. HTTP tools enforce domain allowlists. All tool constraints are evaluated before any invocation.

YAML ## Tools 
tools:
  - id:                  llm.primary
    type:                llm
    allowed_models:      [gpt-4o, claude-sonnet]
    max_tokens_per_call: 4000

  - id:                  web.search
    type:                http
    allow_domains:       [api.tavily.com, wikipedia.org]
§ 10 — MCP Servers

MCP Infrastructure Dependencies

MCP servers are treated as first-class infrastructure. They must be explicitly declared, authenticated, and capability-matched before the agent descriptor is considered valid.

YAML ## MCP Servers 
mcp_servers:
  - id:       tavily
    endpoint: https://api.tavily.com/mcp
    auth:
      type: bearer
      env:  TAVILY_API_KEY
    capabilities:
      - web.search
    timeout_seconds: 10

  - id:       supabase
    endpoint: https://project.supabase.co/mcp
    auth:
      type: service_key
      env:  SUPABASE_SERVICE_ROLE
    capabilities:
      - db.query
      - vector.search
  • MCP servers must be explicitly declared — implicit resolution is not supported
  • Tools referencing MCP capabilities must match a declared server's capability list
  • Authentication types are validated against the UAR auth registry at compile time

§ 12 — Memory Model

Memory Configuration

Session memory is ephemeral by default and scoped to a single invocation context. Long-term memory is vector-backed and namespaced to the agent identity.

YAML ## Memory Model 
memory:
  session:
    type: ephemeral
  long_term:
    type:      vector
    namespace: agent.research.assistant
§ 13 — A2A Contracts

Agent-to-Agent Interaction Contracts

Defines structured endpoints for agent interoperability. All A2A endpoints are auto-registered in the UAR actor routing layer upon successful compilation.

YAML ## A2A Contracts 
a2a:
  endpoints:
    - id:             research.query
      description:   Accepts research query tasks
      input_schema:  schemas/query_input.json
      output_schema: schemas/query_output.json
      allowed_callers:
        - agent.supervisor
      timeout_seconds: 60

    - id:             research.summary
      description:   Produces structured summary
      input_schema:  schemas/summary_input.json
      output_schema: schemas/summary_output.json
  • All schemas must be valid JSON Schema documents
  • Allowed callers are enforced via Cedar principal rules at request time
  • UAR auto-registers all endpoints in the actor routing layer on descriptor load
§ 14 — Governance

Cedar Policy Embedding

Governance policies are embedded directly in the agent descriptor using Cedar policy syntax. Policies are compiled and installed as a Policy Enforcement Point (PEP) at agent boot. No capability may bypass this layer.

Cedar ## Governance — embedded policy 
// Permit LLM invocation within daily spend budget
permit(
  principal,
  action == "llm.invoke",
  resource
)
when {
  context.daily_spend < 5
};

// Permit A2A calls from same namespace
permit(
  principal,
  action == "a2a.call",
  resource
)
when {
  principal.namespace == "tenant.default"
};

// Forbid HTTP requests outside approved domains
forbid(
  principal,
  action == "net.http.request",
  resource not in ApprovedDomains
);
§ 15 — Budgets & Constraints

Resource Constraints

Budget declarations are enforced at the Cedar policy layer. Exceeding any budget causes the governing policy to deny the offending action rather than allow overage.

YAML ## Budgets & Constraints 
budgets:
  daily_cost_usd:          5
  max_tokens_per_session:  20000
  max_tool_calls_per_hour: 50

§ 17 — Observability

Observability Configuration

Audit logging is required and cannot be disabled. PII redaction is applied to all emitted traces before they leave the agent boundary.

YAML ## Observability 
observability:
  audit:      required
  emit_trace: true
  redact:     [pii]
§ 18 — Deployment Profiles

Environment Profiles

Deployment profiles allow environment-specific budget and constraint overrides. All profile values are merged with the base configuration at compile time. The active profile is selected by the UAR host environment at agent instantiation.

YAML ## Deployment Profiles 
profiles:
  local:
    budgets:
      daily_cost_usd: 1

  enterprise:
    budgets:
      daily_cost_usd: 50
§ 19 — Compilation Flow

UAR Compilation Pipeline

The UAR compiler processes an agent descriptor in strict sequential phases. Any phase failure halts compilation and emits a structured diagnostic.

01
Validate Frontmatter
Confirm required metadata fields, version compatibility, and schema version alignment.
02
Validate A2UI Schemas
Resolve artifact and action schemas against the UAR A2UI schema registry.
03
Validate MCP Server Configuration
Check endpoint reachability declarations, auth types, and capability-to-tool cross-references.
04
Validate A2A JSON Schemas
Parse and validate all referenced input and output schemas for structural compliance.
05
Compile Cedar Policy
Parse, type-check, and compile embedded Cedar policy into the enforcement bytecode.
06
Register Actor Endpoints
Bind all A2A endpoints into the UAR actor routing table.
07
Install PEP Enforcement
Attach the compiled Cedar PEP to every capability surface declared in the descriptor.
08
Emit Signed Agent Descriptor
Produce and cryptographically sign the final runtime-ready descriptor artifact.
§ 20 — Summary

Specification Capabilities

UAR-AGENT-MD defines a fully governed, interoperable, UI-aware agent artifact compatible with the Universal Agent Runtime. The following capabilities are now formally specified in v1.1.

// A2UI

Declarative UI

UI surfaces defined as schema contracts, not hardcoded frontend implementations.

// MCP

Infrastructure Dependencies

Explicit MCP server declarations with typed auth and capability matching.

// A2A

Typed Agent Contracts

Strongly typed Agent-to-Agent interaction endpoints with caller enforcement.

// Cedar

Embedded Governance

Policy-first execution with Cedar compiled into a PEP at agent boot.

// UAR

Deterministic Validation

Eight-stage compilation pipeline with structured diagnostics on failure.

// Portable

Signed Artifact Output

Cryptographically signed descriptor enabling verified cross-environment deployment.
