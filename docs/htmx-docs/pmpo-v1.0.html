Precise Definition
PMPO is not "prompt engineering." It is a meta-orchestration methodology that treats documents as inputs to compilation, requires formal constraints and validation gates, produces actionable artifacts (binaries, configs, signed descriptors), and closes the loop with measured outcomes and structured improvement. In the UAR context, PMPO is the operational bridge between human-authored specifications (agent.md), deterministic enforcement (Cedar + PEP), and executable runtime entities (AgentActor + endpoints + skills).
§ 01 — Rationale

Why PMPO Matters for UAR

UAR is explicitly spec-first: behavior is described in documents and enforced by a runtime. PMPO is the operational bridge that makes that conversion repeatable, auditable, and secure.

Repeatable
Same input produces the same compiled descriptor. Determinism is a first-class requirement, not an aspiration.
Auditable
Every decision is logged. The compile report provides stage-by-stage evidence for governance review and incident investigation.
Composable
A task graph, not an ad-hoc sequence. Steps have typed inputs, acceptance checks, and explicit failure modes.
§ 02 — Canonical Loop

Spec → Plan → Execute → Reflect

The four phases are not suggestions. Each phase has strict inputs, outputs, and a defined artifact that gates entry to the next phase.

01 · SPEC
Normalize Intent
Convert ambiguous human-authored intent into a strict artifact with explicit contracts. Produce a parsed and normalized AgentDescriptor IR plus a Validation Contract — what must be true for compilation to proceed.
02 · PLAN
Task Graph
Decompose work into an ordered, typed task graph. Each task has required inputs, the tool or routine used, acceptance checks, and failure modes with remediation hints. Nothing proceeds without a plan.
03 · EXECUTE
Build the Agent
Run the plan against the artifact using UAR-AGENT-MD stages 01–08. Produce a compiled Cedar policy, validated schemas, resolved MCP config, registered A2A endpoints, installed PEP bindings, and a signed runtime descriptor.
04 · REFLECT
Verify & Improve
Check every output against acceptance criteria. Analyze failures. Detect spec-to-runtime drift. Produce a compile report with reason codes and remediation suggestions that feed the next PMPO loop.

§ 03 — Pipeline Mapping

PMPO → UAR Compilation Stages

UAR-AGENT-MD §19 defines 8 compilation stages. PMPO wraps these as a strict orchestration loop. The following maps PMPO phases to their corresponding UAR stages.

Spec Phase Stages 01–02 · Normalization & Contracts
The Spec phase makes intent unambiguous. In UAR compilation this means normalizing the frontmatter and resolving the A2UI contract.
Stage 01 · Validate Frontmatter — normalize versioning, schema compatibility, runtime constraints; produce IR header and compatibility contract
Stage 02 · Validate A2UI Schemas — resolve ui.artifacts[*].schema against registry; resolve ui.actions[*].input_schema/output_schema; produce UI contract
Plan Phase Deterministic Task Graph
PMPO converts the 8 compilation stages into a task graph with explicit acceptance criteria per step. Each task produces a small artifact and a success predicate.
Execute Phase Stages 03–08 · Build the Runtime Agent
Stage 03 · Validate MCP Server Config — verify endpoints, auth types, env var presence; ensure tool capability cross-refs match declared MCP servers
Stage 04 · Validate A2A JSON Schemas — parse input/output JSON Schema; enforce structural constraints; record schema fingerprints for audit and caching
Stage 05 · Compile Cedar Policy — parse embedded Cedar; type-check entity/action/resource usage; compile to authorizer-ready representation; ensure policy covers all sensitive actions (fail-closed)
Stage 06 · Register Actor Endpoints — bind a2a.endpoints[*].id into actor routing registry; attach schema IDs, timeouts, and caller restrictions
Stage 07 · Install PEP Enforcement — for each capability surface (LLM, tools, file, net, plugin load, a2a.call): install a PEP gate, ensure requests build correctly, attach budget and rate-limit obligations
Stage 08 · Emit Signed Descriptor — emit canonical JSON descriptor (stable ordering); sign descriptor and referenced fingerprints; emit compile report with stage results

§ 04 — Acceptance Criteria

What "Done" Means

An agent is considered actionable when all eight criteria are satisfied. Partial satisfaction is a compile failure, not a warning.

01
Descriptor validity — canonical descriptor parses and matches UAR domain types
02
UI contract validity — every A2UI reference resolves; every UI action has typed IO
03
MCP readiness — all declared MCP servers are structurally valid and capability-matched
04
A2A contract validity — every endpoint has valid JSON Schema IO
05
Governance compiled — Cedar policy compiles and references known actions and resources
06
PEP installed — all sensitive capability boundaries are guarded
07
Signature present — descriptor and fingerprints are signed
08
Runtime load test — agent can be loaded and registered without warnings
§ 05 — Tooling Surface

CLI Commands & Artifact Outputs

PMPO becomes concrete inside UAR through a versioned CLI and stable artifact locations. Every compile run is reproducible from its artifact directory.

Core Compile Commands
$ uar compile agent.md
# Full PMPO loop → emits signed descriptor + compile report

$ uar compile --plan-only agent.md
# Emits task graph without execution

$ uar compile --reflect agent.md
# Runs verification against prior artifacts
Governance Debug Commands
$ uar policy simulate agent.md --action llm.invoke --resource model:gpt-4o

$ uar policy explain agent.md --action net.http.request --resource https://example.com

Summary
The Operational Methodology Behind Spec-Driven Agents
PMPO is what makes UAR "specification-driven" in practice rather than in principle. The Spec phase ensures the agent document is unambiguous and contract-complete. The Plan phase converts compilation into a deterministic task graph with measurable acceptance criteria. The Execute phase runs the UAR-AGENT-MD pipeline stages 01–08 to produce a signed descriptor. The Reflect phase verifies determinism, governance coverage, and bindability — feeding improvements into the next loop. This is how a UAR-AGENT-MD document becomes an actionable, governed AgentActor in the Universal Agent Runtime.
