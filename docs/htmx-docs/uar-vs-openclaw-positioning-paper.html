01 · Context

The Moment OpenClaw Created

In early 2026, OpenClaw — born as Clawdbot, briefly Moltbot — became the fastest-growing open-source project in recent memory. Built by PSPDFKit founder Peter Steinberger, it demonstrated to the public what agents actually look like when they escape the chatbot paradigm. Users could tell it to clear their inbox, deploy a commit, or control a smart device — all from WhatsApp or Telegram. The response was immediate and massive.

The cultural moment was genuine. OpenClaw proved that people want agents that act, not just respond. It validated the entire category. Then, almost immediately, the structural problems surfaced at scale.

03 · Architecture

Why the UAR Is Floor-Level Infrastructure

OpenClaw is an application. The UAR is infrastructure. The distinction is not rhetorical — it reflects fundamentally different assumptions about what the system is responsible for and who sits above it.

An application like OpenClaw solves a specific interaction problem: connect messaging apps to LLMs, execute tasks, persist history. It does this adequately for personal use and catastrophically for anything else. Infrastructure like the UAR defines the execution contract, enforces governance, isolates compute, and provides the identity substrate that every application layer above it depends on.

LAYER 1
Governance

Cedar Policy Engine

Every agent action passes through Cedar policy evaluation before execution. Policy is versioned, auditable, and declared independently of agent logic. An agent cannot exceed its declared policy scope regardless of what the LLM outputs.

LAYER 2
Isolation

WASM Sandboxing

Skills execute in WASM runtimes with capability-based access. The runtime is deterministically compiled. A compromised skill cannot read host memory, exfiltrate credentials, or escape its declared capability surface — by construction.

LAYER 3
Identity

Three-Layer DID Architecture

Owner DIDs establish control authority. Agent DIDs provide cryptographic agent identity. User DIDs govern interaction context. The did:uar method maintains W3C DID Core compliance while enabling full blockchain ecosystem interoperability.

LAYER 4
Protocol

A2A / AG-UI / A2UI

JSON-RPC 2.0 for agent-to-agent communication. SSE streaming for AG-UI events. A2UI for agent-driven interface control. These are emerging industry standards — any tool built to these protocols integrates by default, without bespoke adapters.

LAYER 5
Persistence

SurrealDB Federated Registries

Agent registry, skill registry, and policy store backed by SurrealDB. Designed for federated, multi-node topologies. State is queryable, versioned, and consistent across distributed agent deployments — not flat config files on a local machine.

LAYER 6
Runtime

Rust Memory Safety

The UAR runtime is written in Rust. Memory safety is guaranteed by the compiler — not by convention or runtime checks. There is no GC, no npm dependency sprawl, and no single-threaded event loop. The attack surface begins where Rust ends.

The Policy-First Advantage Against Prompt Injection

Prompt injection — embedding malicious instructions in emails, documents, or web content — is OpenClaw's most documented and unresolved attack vector. The Cedar policy layer provides a structural defense that no LLM-layer mitigation can match: agent actions are evaluated against policy regardless of what the model received as instruction. A policy that says "this agent cannot send email to external domains" enforces that constraint even when an attacker's injected prompt says otherwise.
