A2UI registries

Registries are what an agent may render; the AG-UI stream is how clients receive it. Each registry groups component catalogs, promoted components or reusable presentation templates speaking A2UI v0.9.1 (compat v0.9).

UAR catalog

Agents reach templates only through RunPolicy.presentations / AgentSessionConfig.presentations, a ResourceSelection of {mode, ids[], denied_ids[]}. The switch adds this registry's templates to ids[] when the mode is selected, otherwise it removes them from denied_ids[].

Backend gap: a registry is a UI grouping over presentations and components. ResourceSelection holds presentation ids only, so catalog and design-system rows resolve to the templates built on them; there is no registry id to bind.

A2UI messages on the stream

Applied in order per surface_id

CreateSurfaceOpens a surface bound to a catalog_id.
UpdateComponentsReplaces or adds components in the surface tree.
UpdateDataModelPatches bound data; components re-render without a new tree.
DeleteSurfaceCloses the surface; clients drop its state.

Backend gap: there is no per-agent AG-UI endpoint. Clients start a run with POST /api/uar/runs and read /runs/{id}/stream; an agent-addressable URL would need a new route.
