Universal Agent Runtime// OPERATOR SHELL · PROTOTYPE

One sidebar, one inspector, one place to connect a model.

A redesign of the built-in React 19 operator console so it works the way ChatGPT, Codex, Claude and Kimi desktop do: chats and runs in a single left column, a tabbed inspector that slides in on the right, and provider setup that finishes in three steps. Built on the UAR token system; ready to port into the React app and the Tauri shell.

Chat workspace chat-workspace.html

Sidebar with New chat, search, workspace surfaces, projects and recency buckets. Thread with an execution record, inline permission card and artifact chips. Composer with conversation target (orchestrator with routing on or off, or a pinned agent), model, effort and permission-mode controls; each reply shows how it was routed. ?new=1 opens the new-chat chooser. Inspector tabs: Run · Files · Browser · Plan, resizable, slide-over below 1180px.

Projects projects.html

Proposed feature. A project scopes chats, files, knowledge, agents and tools, instructions, memory, members, tasks and budget. Its home is a work board (waiting on you, working, ready for review, resolved). Lifecycle is pause, archive or delete, and moving a chat in re-applies the project's context. Data model in project-management-design.md.

Knowledge knowledge.html

Create knowledge bases, upload and index documents with per-file status, test retrieval against min_score, and catch an embedding-model mismatch before it breaks search. Re-embed, retry failed files, and see which agents use each base.

Agents agents.html

Describe an agent in plain words and the compiler agent asks what is missing, then runs the eight-stage pipeline and registers it. Attach model and fallbacks, knowledge bases, skills, tools and MCP, and A2UI libraries. Built-in agents are protected.

A2UI registries a2ui-registries.html

Catalogs, custom components, presentation templates and design systems an agent may render, which agents may use each, a live surface preview with its wire messages, and the AG-UI recipe clients use to stream a run.

Runs runs.html

Every run with live and waiting runs first, orchestrator runs nesting their sub-agent runs, and an inspector for trace, approvals, admission evidence, usage and resume from checkpoint.

Models & providers models-and-providers.html

Settings as a full page. Roles strip (default chat, fast, embeddings). Provider list with status pills and enable switches. Detail tabs: Connection with write-only credential and a test that names its outcome; Models table with capability chips, prices, bulk enable and default radio; Routing with a fallback chain. Add-provider runs in the right panel in three steps.

Tools & MCP tools-and-mcp.html

Tool sources as master–detail: native tools (file read, opt-in write, web fetch, terminal off) and every MCP server with live health, latency and tool count. Per-tool approval tiers Auto · Ask · Deny · Inherit with a server default, policy-locked rows where Cedar forbids, connection transport and reconnect rules, and a 24-hour audit of decisions. Add-server runs in the right panel in three steps.

Skills skills.html

Installed skills by source with enable switches. Each skill shows its triggers, the tools it needs and whether those tools are actually available, scope and model override. A matching tester explains why a skill fires against the threshold. Evolution is governed per environment by Cedar. Import runs in the right panel with compiler checks.

Knowledge & memory knowledge-and-memory.html

Knowledge bases (documents you add) kept visibly separate from memory (what the agent learns). Documents with indexing status, a retrieval tester, and indexing settings that warn before a re-index. Memory starts off, as in the runtime, and explains itself before you enable it.

Governance governance.html

Effective enforcement state up front, Cedar policies with a request tester, pending approvals, sycophancy and input guardrails, budget limits, and access control.

Appearance appearance.html

Dark, light, high contrast or match system, plus conversation text size, density and motion, all applied live with a preview and kept on this device.

Desktop desktop.html

Tauri-only settings: the in-process runtime and its port fallback, bundled MCP sidecars, window behaviour, logs and data. Tray, shortcuts, launch at login and updates are designed but marked as not in this build.
