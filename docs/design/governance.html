tool-approval.cedar

1 active rulepolicies/tool-approval.cedar · 39 lines
Permit
execute_tool for every tool (line 35).Cedar alone never asks. The pause comes from RunManager, which asks a human when the tool name contains delete, remove, write, drop, truncate or destroy.
Example
Two commented-out forbid rules show how to require context.approved for filesystem__write or any tool with requires_approval.They are inactive until uncommented.
// Tool Approval Policy — require user approval for high-risk tool operations.
//
// Tools matching these patterns will pause execution and request
// explicit user approval before proceeding.
//
// The RunManager checks tool names against a heuristic list:
//   - delete, remove, write, drop, truncate, destroy
//
// To extend or override the heuristic with Cedar policy rules,
// add forbid rules targeting specific tools:

// Example: Require approval for filesystem write operations
// forbid (
//     principal,
//     action == Action::"execute_tool",
//     resource == Tool::"filesystem__write"
// ) unless {
//     context.approved == true
// };

// Example: Require approval for any tool that modifies external state
// forbid (
//     principal,
//     action == Action::"execute_tool",
//     resource
// ) when {
//     resource.requires_approval == true
// } unless {
//     context.approved == true
// };

// Default: permit all tool calls (the heuristic check in RunManager
// handles approval for dangerous tools without Cedar rules).
// Add specific forbid rules above to enforce Cedar-based approval.
permit (
    principal,
    action == Action::"execute_tool",
    resource
);

skill-mutation.cedar

8 active rulespolicies/skill-mutation.cedar · 95 lines
development
Mutate, generate and promote skills freely (lines 18–40).
staging
Mutations need validation_passed; promotions need human_approved and test_pass_rate >= 95 (lines 44–66).While default.cedar permits all, these conditions do not stop anything on their own.
production
Forbids skill.mutate and skill.generate (lines 81–95).There is no production forbid for skill.promote, so the baseline permit lets it through.
// ================================================================
// Skill Mutation Policies — Self-Learning Pipeline Governance
// ================================================================
//
// Gates all write operations against skill artifacts from the
// prometheus-skill-system self-learning pipeline:
// - prompt optimization (dspy-rs writes back to SKILL.md)
// - skill generation (PMPO creates new skills from gap detection)
// - skill promotion (generated skills move from staging to active)
// - trace capture (execution data collection)
//
// Environment is passed in context. Default: "development".
// Set PROMETHEUS_ENVIRONMENT=staging|production for stricter enforcement.
// ================================================================

// --- DEVELOPMENT: permit all skill operations ---

permit(
    principal,
    action == Action::"skill.mutate",
    resource
) when {
    context.environment == "development"
};

permit(
    principal,
    action == Action::"skill.generate",
    resource
) when {
    context.environment == "development"
};

permit(
    principal,
    action == Action::"skill.promote",
    resource
) when {
    context.environment == "development"
};

// --- STAGING: require validation for mutations ---

permit(
    principal,
    action == Action::"skill.mutate",
    resource
) when {
    context.environment == "staging" &&
    context has validation_passed &&
    context.validation_passed == true
};

// --- STAGING: require human approval + test pass rate for promotions ---

permit(
    principal,
    action == Action::"skill.promote",
    resource
) when {
    context.environment == "staging" &&
    context has human_approved &&
    context.human_approved == true &&
    context has test_pass_rate &&
    context.test_pass_rate >= 95
};

// --- TRACE CAPTURE: always allow with governance consent ---

permit(
    principal,
    action == Action::"trace.capture",
    resource
) when {
    context has governance_consent &&
    context.governance_consent == true
};

// --- PRODUCTION: deny all skill mutations ---

forbid(
    principal,
    action == Action::"skill.mutate",
    resource
) when {
    context.environment == "production"
};

forbid(
    principal,
    action == Action::"skill.generate",
    resource
) when {
    context.environment == "production"
};
