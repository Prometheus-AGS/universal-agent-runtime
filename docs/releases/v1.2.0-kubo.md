## OpenAI compatibility and client tools

`POST /v1/chat/completions` maps `model` to a registered UAR agent (`default`
and `orchestrator` retain their aliases), starts a fresh session, and sends the
last message's content to the run. Kubo must not infer complete OpenAI chat or
client tool compatibility from the endpoint name. The request type has no tools
contract and the adapter does not forward client-supplied tool definitions into
the run. Configure tools through UAR's agent policy and registered MCP resources.
On AG-UI, a nonempty frontend `tools` list instead returns HTTP 400 with
`frontend_tools_not_supported`.

For streaming budget failures, the adapter emits an SSE JSON error with
`error.type: "budget_error"`, `error.param: null`, the runtime message and one of:

- `budget_admission_failed`
- `budget_root_cancelled`
- `budget_root_deadline_exceeded`
- `budget_usage_accounting_failed`

It then emits `[DONE]` without a successful `finish_reason: "stop"` chunk.
This closed category does not redefine provider-error or disconnect behavior.
Kubo must inspect the terminal error rather than interpreting `[DONE]` alone as
success. Source: `src/uar/api/openai/{types,routes}.rs` at the release commit.

## MCP destination registry and lifecycle

The `mcp.servers` settings row is the persisted catalog. Hydration now seeds
file-configured destinations when the row is absent or is the untouched empty
bootstrap default (`updated_at` absent). An administrator-written empty map
remains authoritative; it must not silently repopulate from files. The existing
trusted-host grants, persisted agent restrictions and explicit run-resource
requirements described in the v1.1.0 contract still apply.

Registry transport ownership now retains the consuming service owner, retired
connections and cleanup obligations. Borrowed peers do not own service shutdown;
cleanup results remain joinable when a caller is cancelled. An abandoned
elicitation call begins shutdown of its exact connection instead of leaving a
callback able to resume uncertain remote work. These are source changes, not a
claim that lifecycle acceptance passed. Sources: `src/uar/admin/mcp.rs` and
`src/mcp/registry.rs` at the release commit.

## Credentials and authentication

The authenticated `/api/uar/credentials` router retains masked list/read and
write/delete operations, `/principal` and `/migrate-legacy`; it adds
`POST /migrate-principal` and `GET /migration-preview`. Raw provider keys remain
write-only. Credential tenancy policy is present independently of encrypted
storage availability. Identity/source denials return safe policy codes, including
`credential_identity_required`, `credential_source_denied`,
`credential_installation_id_required` and `credential_migration_required`.

Migration preview requires a verified trusted-host context and exposes no raw
key. Principal migration requires the explicit reason
`operator_approved_local_namespace_migration`, nonempty source identifiers and
a non-system scope. Migration uses the declared `If-Match` precondition contract
and reports conflict, stale precondition, unavailable or outcome-unknown states;
clients must not turn an unknown outcome into an unconditional retry.

Authentication middleware retains credential capture only after validating the
presented authority. An invalid presented bearer never falls through to API-key
authority. API keys are checked for current authority; remote workspace admission
uses `x-uar-workspace-id`. The verified capture and user context reach the OpenAI
run, and direct HTTP model operations resolve provider credentials through the
host credential-source policy before provider construction. Sources:
`src/uar/api/credentials.rs`, `src/uar/security/middleware.rs` and `src/server.rs`
at the release commit.

## AG-UI terminal projection

The persisted run binding retains the terminal event and source cursor. A
lifecycle-owned observer subscribes before reconciliation, observes run and
committed-work changes, and retains unresolved effects if projection cannot be
owned or its sources disappear. Terminal projection waits for settled run status;
an error status becomes `RUN_ERROR`, with `host_cleanup_unconfirmed` when no
specific error event is available. Successful, cancelled and interrupt outcomes
remain `RUN_FINISHED` outcomes. Pending approval and elicitation interruptions
are sealed with their exact interrupt IDs. Reconnection projects the retained
terminal rather than claiming success from a disconnected stream. Source:
`src/uar/api/agui.rs` at the release commit.
