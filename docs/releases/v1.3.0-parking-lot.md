## Ownership and capacity

Parking Lot provides admission grants. UAR's `ResourceScope` retains execution,
blocking-worker joins, durable publication and shutdown. This does not adopt
Parking Lot's native worker pool. UAR depends only on the runtime-free core,
with no optional backend or Tokio runtime crate enabled, and retains its pinned
toolchain. The vendored facade and seven sibling manifests remain standalone
exports with upstream inheritance materialized; source implementation bytes and
licenses come from the exact upstream commit.

A document consumes one concurrency slot. The constructor's explicit worker
count remains available; zero selects the CPU count. The server retains its
100-descriptor waiting limit, separate from active jobs and from the durable
backlog. A waiting descriptor contains durable job identity, not loaded source
bytes. Claiming a generation and loading its bytes occur after admission.
Normal-priority descriptors preserve local FIFO order with skip-ahead disabled.
Durable discovery retains its existing ordering; this is not a global upload
FIFO guarantee. Local saturation leaves accepted uploads discoverable for later
dispatch. Completion wakes the dispatcher to refill capacity; repeated wakeups
must not duplicate an active generation. Oversized admission requests fail
explicitly without blocking eligible work.

## 0.4.0 source compatibility

The core dispatch batch now returns `rejected` descriptors as well as admitted
and expired work. Every returned rejection must become an explicit durable
failure outside the dispatch lock. The existing slot, FIFO, permit ownership
and executor-result contracts remain the integration boundary. Pruning now
returns removed task values, and upstream durable mailbox duplicates retain
original result status. UAR does not implement the upstream queue/mailbox
backends and keeps its existing durable ingestion records; the upstream
PostgreSQL protocol-3 and redb schema-3 upgrades do not migrate UAR's stores.
The runtime-free core retains the same dependency requirements, so its locked
local package version changes to 0.4.0 without unrelated dependency updates.
These are source integration changes, not passing runtime acceptance evidence.

## Cancellation and failure

Dropping a caller, a retrieval waiter or a shutdown observer does not end the
underlying work or return its slot. A grant remains owned through actual worker
completion, join and durable outcome handling. There is no new default execution
deadline. Explicit deadlines retain cooperative interruption semantics.

Shutdown stops admission and discards local queued descriptors while leaving
their durable source recoverable. Running work observes cancellation between
processing stages, and shutdown joins actual workers before dependencies close.
A late result cannot publish a canceled or revoked generation. Execution errors
and panic must persist a durable failure before capacity is reused; incomplete
cleanup is retained as failure rather than reported as successful release.

The uncomfortable case is a blocking collaborator that never returns. Cooperative
cancellation cannot stop that code. Shutdown must remain pending and retain its
dependency and slot until the worker exits; a timeout is not evidence of release.
