# UAR 1.4.0-rc.2 — release candidate

**Status:** release candidate. Validated on macOS. 1.4.0 ships after the final
checklist at the end of this note is complete.

## What changed since 1.4.0-rc.1

- **PostgreSQL 18 on flint-forge.** UAR runs on
  `tribehealth/flint-forge-pg:18@sha256:55c12cbf613346315a48a5c465e804c1ca61ccd1be283db4683ca7c690a9069c`
  in its own `uar` database and role. It never uses the `flint` database, which
  flint-forge reserves for pg_cron and GraphQL reflection. See
  [the deployment guide](../operations/postgres-flint-forge.md).
  - Settings record whether a value came from configuration or the API, so a
    configuration change takes effect after restart and an API override
    survives it (#389).
  - The session TTL scan decodes canonical and legacy owner keys with a
    filtered query (#390).
  - Postgres no longer reports memory writes it did not perform. Memory runs
    through the memory service, and startup fails if that service is enabled
    and cannot start (#393).
  - Skill embeddings accept any configured dimension and are re-embedded when
    the embedding fingerprint changes (#395).
  - `GET /api/uar/persistence/capabilities` reports the active store's
    capabilities. On Postgres, team execution, follow-ups, schedules,
    observers and checkpoints are refused with `capability_unsupported`; they
    remain SurrealDB-only (#394). See
    [the capability matrix](../operations/persistence-capabilities.md).
- **Embeddings route.** `POST /v1/embeddings` serves OpenAI-compatible
  embeddings.
- **Configuration fixes.**
  - The configured model is honored: `UAR_LLM__MODEL` overrides `LLM_MODEL`,
    which overrides YAML `llm.model` (#419).
  - The configured memory embedding API is used, and an unknown one fails
    startup instead of falling back to the local 384-dimension model (#420).
  - A request's output cap sizes the budget reservation, and a
    `client_capture_failed` error logs its scrubbed cause (#385).
  - `pnpm sdk-runtime-pin:validate` fails when the Rust SDK's exact runtime pin
    differs from the runtime version (#391).
  - Agent mode on `/v1/messages` is documented in
    [ANTHROPIC_MESSAGES.md](../ANTHROPIC_MESSAGES.md) (#396).
- **Identity.**
  - JWT validation follows one documented access-token profile, exclusive by
    issuer, audience and key; an explicit `typ` other than `at+jwt` or `JWT`
    is refused (#422). See [JWT validation](../security/jwt-validation.md).
  - When the JWKS key source is unavailable, the request gets 503 instead of
    falling through to anonymous access.
  - SSE event parsing is independent of how the byte stream is split (#380).
- **Concurrent first turns.** Two turns arriving together on a new
  conversation now share one session; before, the later save could overwrite
  the earlier turn's messages.
- **Compiler ownership (#387).** Specs and authoring sessions belong to the
  verified owner that created them. Another owner's record answers 404 on
  read, delete, compile and cancel, and is absent from lists. A request with
  no verified owner gets 401 `verified_compiler_owner_required`. `POST
  /compile`, `POST /verify` and `POST /compile-and-register` are unchanged:
  the first two store nothing, and the third writes the agent catalog.
- **Fallback budgets (#388, partial).** On failover, each fallback model's
  context window is resolved the same way as the primary's (run credential,
  provider registry, then catalog). The request is fitted to that window:
  optional history is displaced by the agent's declared strategy, with the
  system message and tool groups kept. A request that still cannot fit is
  refused locally, without counting against provider health, and the next
  fallback is tried. If none fits, the run ends with `context_overflow` and no
  fallback request is sent. The `uar.request` attempt manifest carries a
  `context_fit` object that reports the window, allowance and displacement.

## Behavior changes to check before upgrading

- **Invalid bearers are refused.** With `jwt_required: false`, a request that
  carries a malformed, expired or unverifiable bearer now gets 401. Before
  rc.2 it continued as anonymous. Requests with no credential at all are
  unchanged (#392).
- **Opt-in local owner.** `security.local_loopback_owner` (default `false`)
  makes a no-credential request over a loopback socket act as the local-host
  owner, so history, memory, knowledge and tools share one owner on a personal
  install. It applies only with `deployment_profile: trusted_local` and
  `jwt_required: false`, and reads the peer address from the socket, never
  from a header.
- **Compiler records stored before rc.2** have no owner. They stay readable
  only by the local-host owner. Shared deployments that authored specs before
  rc.2 must re-create them under the intended owner.
- **Postgres memory.** A Postgres primary with memory enabled now requires a
  working memory service at startup.

The catalog found one product defect, fixed in rc.2: two turns arriving
together on a new conversation could each get their own session object, and
the later save overwrote the earlier turn's messages. Twelve configs failed on
the first pass; one was that defect and eleven were test, fixture or provider
problems (a model output cap too small for reasoning, strict JSON parsing, a
stale fixture argument count, provider stream-start timeouts, the model
ignoring a loaded skill). Each was fixed or rerun and passed.

Not covered:

- The catalog's first pass, gates 5 and 6, and 72 catalog configs ran on the
  binary before the session fix (`30c7f806…`). Only the twelve failed configs
  were rerun on the final binary.
- `agent.cucumber.mjs` needs a separately provisioned UAR and was not run.
- E04, E06 and E07 have no runnable scenario (missing capabilities, below).

Batches 1 to 3 passed their own gates before merge (PRs #459, #461, #477);
those receipts are in `.prometheus/session-log.md` and do not certify the
combined rc.2 source.

## Known limits

- **E04, capability-constrained routing**, and **E06/E07 image input** remain
  unsupported, as in rc.1.
- Team execution, follow-ups, schedules, observers and checkpoints are
  SurrealDB-only.
- After a settings reset, `GET` returns 404 until the next restart reseeds the
  configuration value. `DELETE /api/uar/settings/{key}` without `If-Match`
  returns 500 where 428 would be accurate.
- `/v1/messages` cancel parity is documented but not tested, and usage-count
  parity is unverified because the stub model reports no usage.
- #388 is partial. Fallback fitting uses tokenizer estimates, not an exact
  final-wire count, and reuses the primary's output cap instead of the
  fallback's own maximum output. A fallback with no known window is not
  checked. `Summarize` strategies do not summarize during failover and may
  refuse instead. Per-step recompilation of the primary, tokenizer changes and
  summary failure are not addressed; #388 stays open for them.
- Rich-media handling (#386) is deferred past rc.2.
- `/v1/chat/completions` reports `finish_reason: "stop"` even when the output
  cap truncated the answer. The provider's finish reason is read by the Liter
  driver but not carried to the response. This predates rc.2.
- Automatic memory capture does not store an assistant reply longer than the
  local embedding model's 512 tokens; the user's message from that turn is
  still captured. This predates rc.2.
- On the AG-UI stream, when a tool call's first event carries arguments before
  its name, `TOOL_CALL_START` names the tool `tool-Some(<index>)` instead of the
  real tool. This predates rc.2.
