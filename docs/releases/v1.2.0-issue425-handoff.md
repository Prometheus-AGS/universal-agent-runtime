### Tools and Kubo action

At this frozen pin, OpenAI `tools` is accepted as an ignored compatibility field: it is not executed or returned as client tool calls. AG-UI rejects nonempty frontend tools. Kubo's G10-1 assertion therefore matches1.2.0. Keep Kubo's exact digest and existing receipts unchanged; no Kubo repository was edited. Note that OpenAI request `model` selects a registered UAR agent (or default/orchestrator alias), not an arbitrary provider/model. `LLM_MODEL` configures the underlying provider behind that agent.

The operator subsequently requested real client-tool support across OpenAI, AG-UI, Anthropic, A2A and ACP. That is separate **unpublished1.2.1 implementation work** with a future distinct digest; it does not change1.2.0. No upgrade is required to retain Kubo's frozen integration.
