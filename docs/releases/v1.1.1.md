# UAR v1.1.1 — outstanding runtime issues

Publication status: pending implementation completion and phase integration.
Actual tag, workflow, image digests and accepted receipts are recorded at release
handoff. This document makes no release or passing-acceptance claim.

This patch supplies safe run-binding diagnostics, ordinary-manager completion
truth, native Anthropic SSE framing and operator-owned provider credential policy.
It retains explicit budgets, durable accounting, existing tool approval and MCP
outcome semantics, and previously shipped Kubo interfaces.

## Configure and upgrade

Set authentication and deliberate JWT/admin keys as required by the shipped
profile. Omitted `security.provider_credentials.mode` is `single_owner`, retaining
operator-owned house credential compatibility. Shared deployments must explicitly
select `shared`, use verified issuer/tenant/subject identities and grant each
system/config fallback with an exact issuer, tenant, catalog provider and source.
Registration, agent manifests and request metadata cannot grant this policy.
Encrypted credential-service absence does not disable it. Timeout/retry settings
continue to inherit as fixed in #384.

Local/issuerless credential ownership now requires a canonical operator-provisioned
installation UUID in `security.provider_credentials.installation_id`. Provision
it once, back it up and retain it across replicas/restarts. Externally issued
credential owners and general session, knowledge and scheduling keys retain their
existing identity. A new valid UUID denotes a new local credential namespace;
accidental replacement is not detected automatically.

Before migrating, back up credential rows/journals, encryption material, config
and approvals and quiesce every writer and consumer, including provider seeding.
Run the local host command:

```text
universal-agent-runtime --config /operator/uar.yaml credentials initialize-revisions --writers-quiesced
```

The acknowledgement records operator intent; it does not prove exclusion. The
operation only initializes missing metadata revisions on the configured backend
and starts no listeners, providers or MCP. Ordinary startup/preview never performs
this backfill. Preview needs verified trusted-host authority; migration requires
the exact approved installed operator mapping to the authenticated destination.
See [credential policy and migration](../operations/principal-provider-credentials.md)
for strict formats, conditional application, immutable replay, conflict handling
and rollback. Retain old sources. Never restore subject-only shared lookups.

Explicit bounded runs still require an eligible durable accounting store. For
remote Surreal, qualify the actual backing and recovery procedure before setting
its trusted-host durability attestation. A reachable endpoint is not proof.
Safe binding stage/category/reference explains refusal without printing the raw
constructor chain; it does not remove the explicit budget or restore erased logs.
See [durable accounting](../operations/durable-accounting.md).

Issue #385 also confirmed a second admission failure after attestation: a
16,000-token limit could not cover the catalog context-plus-output reservation.
The runtime retains deliberate limits, adds safe per-call refusal diagnostics
and warns at startup about persisted bounded agents on unsupported storage.
See [remote-Surreal upgrade guidance](../operations/remote-surreal-upgrade.md)
for both causes, unchanged timeout inheritance, model verification, legacy KB
reupload and exact team-owner recovery. The operator reports v1.1.0 working after
its configuration changes; that report is separate from v1.1.1 acceptance.

Knowledge recovery uses authenticated reupload of retained originals into the
current verified owner's namespace; old records remain retained and old IDs/chunks
are not adopted. Missing originals are a recovery limitation. Team reclaim still
requires joined quiesce or qualified predecessor exclusion and exact reclaim
proof; elapsed time, replica count or missing Pods confer no takeover authority.
See [durable ingestion](../operations/durable-ingestion.md) and
[knowledge ownership](../operations/knowledge-principal-isolation.md).

Compiler authoring REST remains ownerless in this patch. Both
`/api/uar/compiler` and `/api/compiler` are unavailable when ingress is remote
or `security.provider_credentials.mode` is `shared`, including spec, report,
session, inline compile, verify and compile-and-register operations. This
restriction protects existing compiler records from cross-tenant REST access;
it does not migrate or assign owners to them. Local single-owner deployments
retain the existing compiler REST behavior. Full owner-scoped authoring is
tracked by open issue #387 and is not a v1.1.1 capability claim.

## Compatibility and evidence

Anthropic native transport accepts one initial BOM and CR/LF/CRLF across byte
partitions, ignores only well-formed future kinds with matching/empty SSE names
and rejects malformed known events, incomplete frames and missing terminal.
Ordinary-manager success requires observed orchestration completion. MCP failed,
transport and uncertain outcomes keep their typed receipts and do not authorize
automatic replay. A later independent successful run cannot rewrite an earlier
failed receipt.

The operator selected real integration of this phase's six known-scenario groups,
then the same program on both published architecture digests. See
[phase integration procedure](../operations/uar-1.1.1-acceptance.md). Historical
v1.1.0 Kubo and emulated-amd64 receipts remain historical; the v1.1.0 tag is immutable.
No broader validation sweep or cancelled Dot qualification is claimed. #382 stays
an external dependency tracker. Isolated product repair and actual #385 customer
recovery must be reported separately.

The uncomfortable limit is that a correctly refusing runtime can remain unusable
until backing durability, ownership/source material or exclusion evidence is
established. Publication is withheld if either required architecture lacks the
selected integration observations; an already published tag is never moved.

## Isolated supervisor client compatibility

The private supervisor client explicitly selects rustls for its PEM mTLS identity.
This preserves the dedicated CA, disabled public roots and proxies, refused
redirects, and existing timeout. An enabled native-TLS dependency feature must
not change that client backend. The earlier isolated candidate failed before
registration; the source repair is not physical qualification evidence. See
[supervisor setup](../operations/uar-1.1.1-supervisor-setup.md) for actual service
group permissions, supported timeout bounds, and retained failed stores.
