## Guard provenance and uncomfortable limits

The acknowledgment guard traces to image001's AG-UI partial-rejection setup
failure and a separate run where competing observers disagreed on confirmation.
The original warning discarded the inner error, so its precise failing operation
is unproven. The correction serializes cooperating live-source confirmers; it
does not claim an upstream storage defect, cross-process locking or arbitrary
crash-mid-effect exactly-once execution. Existing authentication, current policy,
actual joins, durable CAS and fail-closed errors remain authoritative.

Acceptance uses real production paths and SurrealKV with an isolated controlled
LLM/MCP HTTP peer. Arm64 was built but not functionally run. PostgreSQL was compiled
but not functionally exercised. Paid-provider certification, arbitrary remote
team graphs, every bundled asset and broader estate certification remain outside
the selected exit contract. The original1.2.0 acceptance tracking remains separate.
No further caller-tool feature work or expanded verification is required by this
finite exit. Unrelated operator verification gates remain CLOSED.
