# UAR v1.2.2 integration contract

This candidate repairs the caller-tool capability published as 1.2.1 before
functional acceptance. The1.2.2 image is now published but failed its exact-image local acceptance gate; see the result below.
Frozen 1.2.0 and the published v1.2.1 source/image tags are not moved.

The native payloads, caller-executed ownership, exact result-batch continuation,
JSON/SSE projections and supported provider controls are described in
[v1.2.1-kubo.md](v1.2.1-kubo.md). Client functions are returned to their caller;
UAR executes only separately authorized host bindings. This patch corrects the
following production paths:

- The mounted `/v1/chat/completions` handler now forwards complete caller history,
  function schemas, selection and parallel controls through the shared durable
  tool loop after its existing model verification, principal, agent, target,
  policy and credential admission. Positive `max_tokens`/`max_completion_tokens`
  caps must agree when both are supplied. Caller history accepts text and nullable
  assistant content with calls. Attachments, alternate stream formats, legacy
  `message` alongside caller history, and cursor replay are explicitly rejected
  on this caller branch. Exact message/result retries use durable replay.
- AG-UI joins actual source cleanup before its terminal handoff, including
  concurrent observers. Text-only completion no longer waits for an event after
  producer finalization. Completed result retries attach to their exact saved
  winning run before checking admission for a new run. Read-only attachment checks
  current principal/workspace ownership; new continuation still follows current
  execution admission.
- A2A retains mailbox completion until consumed before exposing INPUT_REQUIRED.
  Streams observe registration rather than mistaking an enqueued run for a lost
  event source. Mixed-batch public handoffs read caller-visible assistant calls
  and require exact durable pending IDs; hidden host results stay canonical. Continuation CAS uses the current binding revision, and completed
  retries bind the saved response to the exact owner, tenant, task, context and
  session. Projection conflict loops observe shutdown cancellation. Caller-tool
  actor roots resolve the current registered agent; remote policy remains a
  restriction on that current policy rather than replacing it.
- ACP honors the selected session agent on every run. The public `default` alias
  resolves the current registered `default-agent`. Cold continuation recovers
  agent identity from an exact owner/tenant/session/batch lookup, then performs
  normal current-agent admission and exact batch validation. Session restoration
  is published only after validation. Restored defaults retain declarations and
  controls without caching old continuation history; a later fresh input starts
  a new user turn.
- Anthropic text-only assistant history omits absent `tool_calls` instead of
  emitting null. Actual call arrays and IDs remain intact.
- Explicit OpenAI-compatible endpoints classify tool controls from the actual
  selected generic adapter, independently of the bare wire model. Native adapters
  that cannot preserve a requested control still return a capability error.
- `server.ingest_directory` / `UAR_SERVER__INGEST_DIRECTORY` selects the watched
  ingestion directory. The container default remains `/data/ingest`. Directory
  creation completes before watcher admission and reports the original I/O cause.
- Local budget admission refusals retain their actual error and no longer count as
  provider outages or enter model failover before provider dispatch. Anthropic
  and ACP preserve the captured public error after actual failed settlement.
- Accounting retains substantive transaction errors ahead of rollback placeholders.
  The local fixture uses a validated catalog pricing identity; accounting is not
  disabled. The original gate003 transaction failure was not reproduced, and no
  semantic query repair is claimed for it.

## Acceptance and publication status

Local gate017 passes the finite native contract on Intel macOS with real
SurrealKV persistence and an isolated controlled LLM/MCP HTTP peer through the
production server and drivers: 95 core cases, 60 safety cases, native cancellation,
ordinary cold continuation, warm/cold local team graph continuation, warm/cold
cumulative budgets, and settled mixed-host/client handoff crash recovery across
OpenAI, Anthropic, AG-UI, A2A and ACP. Completed retries add no provider calls or
host effects. Actual root/child cleanup and owned process joins are confirmed;
the intentional candidate-only SIGKILL is separately recorded, not graceful cleanup.

The command exits 2 with status `extended_passed_remaining_release_gates` because
broader backend/release certification remains outside this bounded contract.
There are no failed scoped cases or unexpected child exits. Native evidence is
`.kbd-orchestrator/phases/uar-post-lifecycle-verification-readiness/client-tools-local-gate-017-receipt.json`.
The exact published-image proof is still pending at this source commit.
PostgreSQL is compiled, not functionally certified. No arm64 functional or paid
provider certification is claimed. The crash promise covers an acknowledged
handoff after settled host effects, not arbitrary crash-mid-effect exactly-once.
Host argument JSON retains exact call identity and values; whitespace formatting
from provider wire JSON is not a byte-identity guarantee.

For the built-in orchestrator graph, clients must answer the existing required
`spawn_agent` approval. AG-UI uses its native interrupt resume with the same
thread, a new wire run and the exact predecessor/challenge; A2A retains the same
task and observes its post-approval state. An approval interruption is distinct
from a caller-tool handoff. Ordinary selected-agent caller tools do not add a
new approval requirement.

The finite contract and exclusions are recorded in
`.kbd-orchestrator/phases/uar-post-lifecycle-verification-readiness/client-tools-exit-contract.md`.
The release must record paired Docker tags, source commit, canonical index and
its exact-image local evidence before claiming delivered-image acceptance.
All product acceptance runs locally; GitHub Actions performs test-disabled image
build/publication only. Frozen 1.2.0 and published 1.2.1 artifacts remain unchanged.
