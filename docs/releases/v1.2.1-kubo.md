## Ownership, history, and durable handoff

Caller functions are declarations the model may select. The application executes
them and submits their results. They never become registered host executables.
Host calls continue through trusted-host execution and its current admission,
credentials, governance, descriptor, approval, and MCP rules. A caller tool cannot
replace a host tool through a duplicate name; ambiguous ownership rejects.

The model/provider selection still follows each endpoint's existing rules.
OpenAI request `model` selects a registered agent (`default` and `orchestrator`
retain their aliases). It does not introduce a `provider/model` selector there.
Provider configuration is separate. Native AG-UI selects its agent in the path.
Anthropic agent binding is described below.

The host persists a caller batch before exposing its calls. Public IDs use
`uar_client_<batch UUID>_<call UUID>` locators. A locator finds evidence; it is
not an execution capability. Never invent, translate, truncate, or replace the
returned ID. All examples below use an illustrative locator; real applications
must copy the ID returned by the runtime.

Durable rows bind the complete authenticated session-owner key, tenant, actual
agent, source run, protocol, session, declaration/control binding, pending IDs,
visible history, and private canonical history. Continuation re-admits current
policy and restores private history, graph state, and captured budget state.
It does not reset economic scopes or create new budget allowance. This depends
on supported durable continuation and accounting storage; unsupported storage
rejects rather than establishing an in-memory continuation guarantee.

Submit every pending result once as one complete contiguous result batch. IDs,
owner, tenant, agent, protocol, session, visible predecessor history, and schemas
must agree with durable evidence. Partial, duplicate, forged, conflicting, or
cross-owner batches reject. Historical caller exchanges also require their scoped
durable evidence; adding a user message is not permission to manufacture tool
history. Protocol-specific normalization handles declared native differences;
it is not arbitrary transcript replacement. Private host results are never
reconstructed from caller text.

State moves from Pending to Claimed to Completed using the durable store.
Matching completed submissions replay the stored protocol projection or admitted
handle. An interrupted Claimed record is not automatically acquired again:
uncertainty after a possible side effect fails closed and requires operator
recovery. The uncomfortable case is a crash after claim or admission but before
the response record commits. No automatic retry is allowed to repeat uncertain
provider or host effects.

Completed is a transport receipt, not a universal model-success assertion.
OpenAI and bound Anthropic retain their completed native response and event
projection. AG-UI retains the admitted wire/native run binding; A2A retains a
task receipt; ACP retains its caller-tools run response. A receipt may represent
a handoff or an admitted run still in progress. Read the protocol's actual
terminal state and pending calls before deciding the application task succeeded.

## OpenAI Chat Completions

`POST /v1/chat/completions` accepts standard function `tools`, `tool_choice`,
`parallel_tool_calls`, and ordered text `messages`. Function `strict` is retained
when supported by the selected provider path. Choices are `"auto"`, `"none"`,
`"required"`, or the standard named function object.

```json
{
  "model": "default-agent",
  "messages": [{"role":"user","content":"Look up Ada"}],
  "tools": [{"type":"function","function":{"name":"lookup","description":"Look up a person","parameters":{"type":"object","properties":{"query":{"type":"string"}},"required":["query"],"additionalProperties":false},"strict":true}}],
  "tool_choice": {"type":"function","function":{"name":"lookup"}},
  "parallel_tool_calls": false,
  "stream": false
}
```

A caller handoff has an assistant `tool_calls` array and
`finish_reason:"tool_calls"`. SSE uses indexed function-call deltas, then that
finish reason and `[DONE]`. Host-tool lifecycle events do not become caller
function requests. An error terminal does not claim a successful stop.

Append the returned assistant message and a result for each call, retaining the
same declarations and controls. This complete illustrative continuation replaces
the example's call ID with one a real server would return:

```json
{
  "model":"default-agent",
  "messages":[
    {"role":"user","content":"Look up Ada"},
    {"role":"assistant","content":"","tool_calls":[{"id":"uar_client_00000000-0000-4000-8000-000000000001_00000000-0000-4000-8000-000000000002","type":"function","function":{"name":"lookup","arguments":"{\"query\":\"Ada\"}"}}]},
    {"role":"tool","tool_call_id":"uar_client_00000000-0000-4000-8000-000000000001_00000000-0000-4000-8000-000000000002","content":"Ada Lovelace"}
  ],
  "tools":[{"type":"function","function":{"name":"lookup","description":"Look up a person","parameters":{"type":"object","properties":{"query":{"type":"string"}},"required":["query"],"additionalProperties":false},"strict":true}}],
  "tool_choice":{"type":"function","function":{"name":"lookup"}},
  "parallel_tool_calls":false,
  "stream":false
}
```

The protected session is restored from the claimed batch. Repeating an exact
completed result request replays its recorded response/events instead of
admitting another execution. Both JSON and SSE source paths are authored; neither
has acceptance evidence for this candidate.

## AG-UI

`POST /api/uar/ag-ui/agents/{agent_id}` keeps pinned `@ag-ui/core` 1.0.2 native
`RunAgentInput`. Tools use `{name,description,parameters}`. Native input has no
standard `tool_choice` or `parallel_tool_calls` field, so optional UAR controls
use the existing standard extension point `forwardedProps.uar.client_tools`:

```json
{
  "threadId":"conversation-1",
  "runId":"segment-1",
  "protocolVersion":"1.0",
  "messages":[{"id":"message-1","role":"user","content":"Look up Ada"}],
  "tools":[{"name":"lookup","description":"Look up a person","parameters":{"type":"object","properties":{"query":{"type":"string"}},"required":["query"],"additionalProperties":false}}],
  "forwardedProps":{"uar":{"client_tools":{"tool_choice":{"type":"named","name":"lookup"},"parallel_tool_calls":false}}}
}
```

The private controls object rejects unknown members. Its common choice forms are
`{type:"auto"}`, `{type:"none"}`, `{type:"required"}`, or
`{type:"named",name:"lookup"}`. Unknown modes reject. Native `tools` remains the
only declaration field; this extension does not install host tools. AG-UI does
not add a native strict-tool field.

The SSE handoff emits `TOOL_CALL_START`, `TOOL_CALL_ARGS`, `TOOL_CALL_END`, followed
by this native outcome:

```json
{"type":"RUN_FINISHED","threadId":"conversation-1","runId":"segment-1","outcome":{"type":"success","pendingToolCallIds":["uar_client_00000000-0000-4000-8000-000000000001_00000000-0000-4000-8000-000000000002"]}}
```

Success here means the frontend segment ended with pending calls, not that the
function executed. The next request has the same thread, a new run ID, the prior
`parentRunId`, and native tool messages. Results-only messages are supported by
rehydrating the exact durable predecessor; full visible history is also accepted
when it matches.

```json
{
  "threadId":"conversation-1",
  "runId":"segment-2",
  "parentRunId":"segment-1",
  "protocolVersion":"1.0",
  "messages":[{"id":"result-1","role":"tool","toolCallId":"uar_client_00000000-0000-4000-8000-000000000001_00000000-0000-4000-8000-000000000002","content":"Ada Lovelace"}]
}
```

Omitted continuation declarations/controls inherit the durable binding; explicit
changes must match it. Current workspace headers and authenticated ownership are
still required. Ambient `context` and `state` stay explicitly untrusted input.
Existing `tool_approval` and `mcp_elicitation` interrupts retain their separate
native `resume` contract and exact all-pending coverage; tool result messages do
not answer or approve them.

Exact POST retries and owner-scoped reconnect attach to the same reserved run.
`GET /api/uar/ag-ui/agents/{agent_id}/threads/{thread_id}/runs/{run_id}/stream`
and `Last-Event-ID` retain their existing identity constraints. Standard terminal
`metadata.uar.clientToolCalls` retains the caller handoff projection. Native token
history remains bounded; retention of a handoff does not claim a durable complete
text transcript. Stored admission receipts cannot authorize re-execution.

## A2A 1.0 JSON-RPC and gRPC

Caller tools use a private extension, with the exact URI and request metadata key
`https://prometheus.dev/a2a/extensions/client-tools/v1`. It is not a new field in
the official A2A core schemas. JSON-RPC and gRPC feed the same normalized task
service. Discover the configured official endpoint/interface from the agent card;
legacy interfaces reject the extension. Discovery advertises it only when the
task service and required durable stores are available.

A JSON-RPC request to the configured official agent endpoint is:

```json
{
  "jsonrpc":"2.0",
  "id":"request-1",
  "method":"SendMessage",
  "params":{
    "message":{"messageId":"message-1","role":"ROLE_USER","parts":[{"text":"Look up Ada"}]},
    "metadata":{"https://prometheus.dev/a2a/extensions/client-tools/v1":{
      "tools":[{"type":"function","function":{"name":"lookup","description":"Look up a person","parameters":{"type":"object","properties":{"query":{"type":"string"}},"required":["query"],"additionalProperties":false}}}],
      "tool_choice":{"type":"auto"},
      "parallel_tool_calls":false,
      "history":[{"role":"user","content":"Look up Ada"}]
    }},
    "configuration":{"returnImmediately":false}
  }
}
```

Additional current delegation metadata/grants remain necessary where the agent
requires them; the extension grants no extra delegation or execution authority.
Pending caller batches project the task to `InputRequired` (official JSON uses
`TASK_STATE_INPUT_REQUIRED`). Task metadata under that URI contains `batch_id`,
`pending_calls`, exact visible `history`, and `declarations`.

Continue with `SendMessage` or `SendStreamingMessage` on the **same task and
context**, setting `message.taskId` and `message.contextId`. Copy the returned
visible history into the extension and append contiguous canonical result
messages `{role:"tool",tool_call_id:"returned ID",content:"result"}` for the
whole pending batch. Keep the declaration/control binding unchanged. The current
authenticated delegation contract is revalidated before claim. The same task
admits a new actor root and retains its protected session. A stored task receipt
is not proof that the actor root has completed. Existing approval resolution
stays separate from caller result submission.

## Anthropic Messages

`POST /v1/messages` accepts native `tools` with `name`, `description`,
`input_schema`, and optional `strict`; native choices are `auto`, `none`, `any`,
and `tool`. `any` maps to required; `tool` selects its `name`.
`disable_parallel_tool_use` is inverted into the common parallel control. A
contradictory explicit UAR `parallel_tool_calls` value rejects.

```json
{
  "model":"configured-provider-model",
  "agent_id":"default-agent",
  "session_id":"conversation-1",
  "max_tokens":256,
  "messages":[{"role":"user","content":"Look up Ada"}],
  "tools":[{"name":"lookup","description":"Look up a person","input_schema":{"type":"object","properties":{"query":{"type":"string"}},"required":["query"],"additionalProperties":false},"strict":true}],
  "tool_choice":{"type":"tool","name":"lookup","disable_parallel_tool_use":true},
  "stream":false
}
```

Use an actually authorized configured model in place of the illustrative model
name. With a registered `agent_id`, or an agent selected by persisted conversation
policy, execution follows the shared RunManager host path. Registered artifact
policy stays authoritative; request model/provider is restriction-only. This
route rejects `uar:agent:*` catalog targets. It has no implicit default agent
when neither request nor persisted policy selects one.

Bound execution projects caller batches to native assistant `tool_use` content
blocks, retaining the public `uar_client_` IDs, and uses `stop_reason:"tool_use"`.
Append that native assistant message and a user message containing one native
`tool_result` block per pending call:

```json
{"role":"user","content":[{"type":"tool_result","tool_use_id":"uar_client_00000000-0000-4000-8000-000000000001_00000000-0000-4000-8000-000000000002","content":"Ada Lovelace"}]}
```

Send the full native conversation and unchanged declarations/controls. Protected
session, graph state and budget are restored through the common continuation.
A native SDK may omit `session_id`: the authenticated durable call locator
restores the original session internally. If an explicit `session_id` is supplied,
it must match the saved session; it cannot redirect another conversation.
JSON/native SSE response projections commit before successful terminal delivery;
matching completed submissions replay those projections. `max_tokens` is an
optional positive output ceiling intersected with the authorized host limit;
zero rejects. Unsupported bound request extensions reject explicitly instead of
silently claiming support. Recognition of that ceiling does not imply support
for arbitrary other generation settings.

Without an agent binding, this endpoint remains direct provider forwarding. It
passes native tool descriptions and explicit controls to the selected driver;
the caller supplies subsequent native history. It does not gain the bound
host's durable continuation, host-tool execution, or replay guarantee. Provider
control restrictions below still apply. Unknown choice members and unsupported
tool definition fields reject.

## ACP

The `/acp` JSON-RPC endpoint and `/acp/stream` expose the explicit native UAR
`client_tools` extension. `sessions/create` can store declarations and controls
but cannot include history. A run can override/inherit those declarations.

```json
{"jsonrpc":"2.0","id":"session-1","method":"sessions/create","params":{"agent_id":"default-agent","client_tools":{"tools":[{"type":"function","function":{"name":"lookup","description":"Look up a person","parameters":{"type":"object","properties":{"query":{"type":"string"}},"required":["query"],"additionalProperties":false}}}],"tool_choice":{"type":"auto"},"parallel_tool_calls":false}}}
```

Then use the returned session ID:

```json
{"jsonrpc":"2.0","id":"run-1","method":"runs/create","params":{"session_id":"returned-session-id","input":"Look up Ada"}}
```

Caller-tools run responses include `run_id`, status, output and events, plus
`batch_id`/`client_tools` when caller results are needed. Copy the returned
`client_tools.history`, append the entire canonical tool-result suffix, and
submit `runs/submit_tool_results` with that session and `client_tools` object.
`input` is optional on this continuation; results-only without the visible
predecessor history reject. `runs/get` exposes `pending_client_tools` and durable
`client_tool_continuation` state/history for the authenticated run.

Caller-tools streaming is buffered until the manager terminates and the response
projection is persisted; it can increase time to first event. It ends with
`acp_result`. Other ACP runs keep their existing streaming behavior. Process-local
sessions can be restored from an authenticated durable caller batch after
restart. This does not turn every ACP session into durable session storage, and
deleting an in-memory session does not cancel a durable pending caller batch.

## Current provider control limits

These are authored driver checks, not claims that every upstream model supports
the feature. Tool-required/named controls validate declared functions before
provider dispatch. Typed controls cannot be overridden through `extra_params`.
Unsupported explicit controls fail instead of silently becoming automatic choice.

| Path | Source restriction |
| --- | --- |
| Liter without exact endpoint profile | Explicit parallel control is accepted only for detected OpenAI/Azure/Azure OpenAI paths. |
| Liter without exact endpoint profile | Explicit choice is accepted only for detected OpenAI/Azure/Azure OpenAI/Anthropic paths. |
| Liter without exact endpoint profile | A supplied strict field is refused outside OpenAI/Azure/Azure OpenAI; choose a supported native path where appropriate. |
| Anthropic through Liter | Tool parameter root must be object; requests whose schema would be rewritten reject. |
| Exact endpoint profiles | Existing final-wire field validation remains authoritative; a profile is not blanket permission to ignore provider limits. |
| Native Anthropic driver | Maps required to `any`, parallel to inverse `disable_parallel_tool_use`, and retains strict. Forced choice with enabled thinking, and parallel control combined with native none, reject explicitly. Existing budget-contract refusal remains. |

A capable provider may still be refused until its adapter semantics or exact
endpoint profile support that control. Actual provider/model enforcement,
credentials, accounting, and final-wire behavior need authorized real-path
acceptance. No fallback or training-era assumption certifies them.

## Source cleanup acknowledgment

Caller handoff publication waits for the source host worker and graph cleanup to settle successfully. The durable continuation records that acknowledgment before becoming resumable, including after restart. An emitted terminal alone does not authorize continuation; cleanup failure cannot become a successful handoff. This behavior is source-authored and unverified.

The authored acceptance driver supports separate OpenAI and Anthropic model selectors, all five native interfaces, concurrent submissions, disconnects, mixed host/caller batches, and separate cold-restart, graph and cumulative-budget modes. See `openspec/changes/openai-client-tools/handoffs/acceptance.md` for provisioning requirements and limits. No acceptance mode has run.
