Prometheus AGS — Full-Stack Architecture Analysis

The Sovereign Agent Operating Stack

A structural analysis of four Prometheus-ecosystem systems — surreal-memory-server, Universal Agent Runtime, candle-vllm, and the OpenFang UAR driver — operating as an integrated, self-contained agent execution platform with layered MCP, sovereign inference, and persistent memory.

candle-vllm turboquant-rs universal-agent-runtime surreal-memory-server openfang (UAR driver)
01 — Overview

What the Combination Actually Is

When these four systems operate together they form something the ecosystem does not yet have a clean name for: a full-stack, sovereign agent execution environment where inference, memory, tool execution, and agent orchestration are each implemented in Rust, each owned in full, and each independently composable without an external API dependency anywhere in the execution path.

4
Rust systems
All four layers are Rust-native. No Python runtime, no Node.js agent loop, no cloud SDK dependency in the critical path.
3
MCP layers
MCP operates simultaneously at the inference layer (candle-vllm), the runtime layer (UAR), and the agent OS layer (OpenFang). Independent, composable.
142+
LLM providers
Through UAR's liter-llm integration, any provider including candle-vllm itself is reachable with identical API shape from OpenFang agents.
$0
Inference floor
When candle-vllm is the backend, the per-token cost is structural zero — no API key, no metered call, no external service dependency.

The central claim: No existing open-source agent framework combines Rust-native agent orchestration, self-hosted inference with KV compression, SurrealDB-backed semantic memory, and a multi-level MCP protocol mesh in a single deployable stack. The combination described here is novel not because each component is novel in isolation — it is novel because every layer is production-grade, each layer is independently owned, and all four layers compose without translation loss at any seam.

03 — MCP Protocol Mesh

Three Independent MCP Layers — One Memory Substrate

The most architecturally significant property of this stack is that MCP operates independently at three distinct layers, each with a different purpose and scope. surreal-memory-server sits behind all three of them as a shared memory substrate — producing a result that no single-layer MCP integration can achieve.

L3
OpenFang — Agent OS MCP Client openfang-runtime/mcp.rs
OpenFang connects to external MCP servers at kernel boot time. surreal-memory-server's HTTP MCP endpoint (/mcp/http) is registered in config.toml. The 42 memory tools become namespaced as mcp_memory_add, mcp_kg_create_entity, mcp_task_stream_context, etc., and are available to every agent in the OpenFang kernel automatically — no per-agent configuration required. This is the agent-level tool layer: agents explicitly call memory tools as part of their reasoning.
│ memory tools flow up │
L2
UAR — Runtime MCP Orchestrator src/mcp/ + UAR_MEMORY__*
UAR operates MCP at the orchestration layer — the tool loop in the Orchestrator discovers and calls MCP tools from mcp.json on every turn. Simultaneously, UAR's dedicated memory system (UAR_MEMORY__ENABLED=true) connects to surreal-memory-server via REST and runs automatic capture and injection: after each assistant turn it extracts facts and stores them, and before each LLM call it retrieves relevant memories and prepends a structured recall block to the system prompt. This layer operates transparently — the LLM receives richer context without the agent explicitly asking for it.
│ memory injected into system prompt │
L1
candle-vllm — Inference Layer MCP Client src/mcp/
candle-vllm's Prometheus fork includes a hand-rolled MCP client (stdio + HTTP) configured via mcp.json. When surreal-memory-server is registered here, memory tools are injected directly into the OpenAI-compatible /v1/chat/completions tool list — before any token is generated. This means that a raw API call to candle-vllm without any agent framework still has access to all 42 memory tools. This is the deepest possible integration point: memory as infrastructure, not as middleware.
│ tools injected at inference layer │
S
surreal-memory-server — Shared Memory Substrate 42 MCP tools · REST API · A2A SSE
Serves all three layers simultaneously over a single SurrealDB instance. HNSW vector search and BM25 full-text are available to all callers. The dual-transport design (stdio for Claude Desktop, HTTP for programmatic) means the same memory substrate is available for local development, production Docker deployments, and Kubernetes pods without any transport-layer reconfiguration.

The three-layer effect: When all three MCP connections are live, the model's context is shaped at three different points in the request lifecycle — by the inference server (L1, tool injection before decoding), by the runtime (L2, system prompt injection before dispatch), and by the agent loop (L3, explicit tool calls within reasoning). No single integration achieves all three. The stack does.

04 — Inference Routing

OpenFang → UAR Driver → candle-vllm

The UAR driver in OpenFang (crates/openfang-runtime/src/drivers/uar.rs) is the seam that makes candle-vllm a first-class provider for any OpenFang agent. The implementation is clean: the driver wraps UAR's LiterLlmDriver, which in turn points to the candle-vllm endpoint via liter-llm's OpenAI-compatible routing.

What the UarDriver Enables That the Other Drivers Cannot

Provider Breadth
142+ providers from a single agent manifest field

Any OpenFang agent can address openai/gpt-4o, anthropic/claude-opus-4, groq/llama-3.3-70b, or candle-vllm/qwen2.5-32b-q4 by changing a single string — no driver swap, no rebuild, no config restructure.

Cost Floor
Self-hosted candle-vllm as the zero-cost provider

When UAR_LLM__BASE_URL points at a local or private candle-vllm instance, the per-token cost is zero. Routing between self-hosted and cloud providers can be encoded in the agent manifest — different agents in the same kernel can use different cost tiers without any code change.

Streaming Fidelity
Full streaming tool-call delta support preserved end-to-end

The UAR driver correctly emits StreamEvent::ToolUseStart, ToolInputDelta, and ToolUseEnd events by tracking call_index across partial chunks — matching the streaming behavior of the native OpenFang drivers. No polling, no buffering.

Compile-Time Catalog
Provider capabilities baked in — no runtime discovery

UAR's build.rs embeds the full liter-llm provider catalog at compile time. candle-vllm as an OpenAI-compatible provider gets capability metadata (tool support, context limits, cost) resolved at build time — the agent framework makes routing decisions without any network round-trip.

05 — Memory Architecture

surreal-memory-server as the Unified Memory Plane

surreal-memory-server is not just UAR's memory backend. It is the shared memory substrate for the entire stack — accessible simultaneously by OpenFang agents (via MCP), by UAR (via REST + MCP), and by candle-vllm inference sessions (via MCP tool injection). The consequence is that memory written by one layer is immediately readable by any other layer in the same session.

06 — Skills & Agentic Capability

Three-Level Skills Architecture

Skills in this stack operate at three independent levels, each additive. The combination gives any agent in the OpenFang kernel access to a capabilities envelope that no single framework provides alone.

Level 1 — OpenFang Native Skills
60 bundled skills + FangHub + ClawHub

Compiled into the OpenFang binary via include_str!(). Skills are skill.toml + Python/WASM/Node.js/PromptOnly code. SKILL.md auto-parsed for OpenClaw cross-ecosystem compatibility. Prompt injection scanner protects all skill content. Activated per-agent via [skills] in the agent manifest — the LLM receives SKILL.md domain expertise injected into its system prompt at runtime.

Level 2 — UAR Native Skills
MCP-first tool execution + compile-time model routing

UAR's Orchestrator runs the tool loop against any MCP server registered in mcp.json. surreal-memory-server's 42 tools are a UAR-level skill set. The compile-time model catalog enables UAR to select the best available model for each capability requirement — routing specific tasks to candle-vllm versus a cloud provider based on tool support, context, and cost ceiling.

Level 3 — candle-vllm MCP Skills
Memory tools injected at the inference layer

When surreal-memory-server is registered in candle-vllm's mcp.json, its tools are injected directly into every chat completion request — below the agent framework, below the runtime. A model that does not know it is inside OpenFang or UAR still has access to the memory substrate. This is capabilities-as-infrastructure: skills at the inference layer, not the application layer.

Multi-level skills composition: An OpenFang agent using the UAR driver with candle-vllm backend inherits skills from all three levels simultaneously. The SKILL.md domain context shapes how the LLM reasons; UAR's tool loop enables it to act across MCP tools; candle-vllm's MCP injection ensures memory access exists even if both upper layers fail to call it explicitly. The redundancy is intentional — robust agent behavior does not depend on perfect prompt engineering at any single layer.

08 — Strategic Significance

What the Combined Stack Makes Possible

The strategic implications compound across two axes: what individual developers and the Prometheus AGS product portfolio can do with this stack that they could not do before, and what position in the market this combination describes.

Capabilities Unlocked

  • Fully sovereign agent deployment with durable memory — An OpenFang agent using candle-vllm as backend with surreal-memory-server as memory plane has zero external API dependencies. No token charge, no cloud dependency, no data leaving the deployment perimeter. This is a viable architecture for regulated environments (banking, healthcare) where data sovereignty is a hard constraint.
  • Persistent world model across sessions — The knowledge graph accumulates across every conversation, every agent, every session. The surreal-memory-server's temporal history API allows querying "what did the system know at time T" — audit trail for regulated use cases where knowing what the agent knew is as important as what it did.
  • Cost-routing at the agent manifest level — Per-agent provider routing in the UarDriver means a single OpenFang kernel can run some agents on candle-vllm (zero marginal cost, local hardware) and others on frontier APIs (Claude, GPT-5) — routing by task complexity, capability requirement, or cost ceiling, all encoded declaratively in agent manifests without code changes.
  • Multi-agent shared context via global memory scope — Any agent writing to scope = "global" produces knowledge immediately available to every other agent in the kernel. Multi-agent workflows can coordinate through shared structured memory rather than explicit message passing — the knowledge graph is the coordination substrate.
  • Context length multiplied by TurboQuant — For long-running agent workflows that accumulate large TaskStream histories or require deep document context, the 5× effective context multiplier from TurboQuant KV compression directly extends what is possible on fixed hardware. A 32K context window becomes a 160K context window without changing the model or the hardware.
  • OpenFang's 40 channel adapters on self-hosted inference — OpenFang's Telegram, Discord, Slack, WhatsApp (and 36 other) channel adapters route incoming messages to agents that now have candle-vllm as their inference backend. A WhatsApp message can trigger an agent whose response is generated locally, whose memory is stored in SurrealDB, and whose cost to the operator is approximately zero beyond hardware depreciation.
  • Prompt injection protection at every layer — OpenFang's skill scanner, WASM dual-metered sandbox, SSRF protection, and 16-layer security model operate above candle-vllm's MCP tool injection. A malicious tool result from surreal-memory-server (in a compromised deployment) would hit OpenFang's loop guard and tool result truncation before it could affect the agent's behavior.

09 — Known Gaps & Next Actions

What Still Needs to Close

Configuration Gap
UAR 503 handling for candle-vllm backpressure

When candle-vllm's parking-lot scheduler returns HTTP 503 (queue depth exceeded), UAR should implement exponential backoff retry logic in LiterLlmDriver rather than surfacing the error directly to the agent loop. candle-vllm's contract is correct — the client behavior needs alignment.

Configuration Gap
Session TTL alignment between UAR and surreal-memory-server

UAR auto-captures session-scoped memories at every turn. surreal-memory-server's TTL decay worker needs to be configured to expire session-scoped entries when UAR sessions close — otherwise session memories accumulate indefinitely. Requires coordination between UAR_MEMORY__* session lifetime settings and surreal-memory-server's TTL environment variables.

Integration Opportunity
OpenFang A2A → surreal-memory-server A2A SSE

surreal-memory-server exposes GET /a2a/tasks/:id/events as an SSE stream for agent-to-agent task coordination. Registering surreal-memory-server as an external agent in OpenFang's [a2a] config creates a direct task coordination channel between the agent OS and the memory plane — useful for long-running background memory operations (bulk embedding, graph compaction) that shouldn't block the agent loop.

Integration Opportunity
Stratum offline model profiling → candle-vllm models.yaml generation

The Stratum project (offline vLLM profile tool) produces .stratum profile files for models. These profiles contain the per-model memory and performance characteristics that could feed candle-vllm's models.yaml configuration automatically — closing the loop between model selection, VRAM budgeting, and TurboQuant compression policy without manual configuration.

The configuration gaps are not blockers. The architecture is complete. Every protocol seam is implemented and tested. The gaps above are operational tuning items — aligning runtime parameters between systems that are already protocol-compatible. The integration opportunity items represent the next layer of structural depth that this stack is uniquely positioned to achieve.
