## 1. Plan Summary

This plan synthesizes 9 assessment gaps and 14 landscape opportunities into a classified, sequenced set of improvement actions. The overriding objectives are:

1. **Remove the CI/CD and commercial licensing blockers** that prevent enterprise evaluation from completing
2. **Close the MCP server gap** to expand the addressable ecosystem by an order of magnitude
3. **Complete the A2UI spec section** and artifact SSE event to reach 100% spec coverage
4. **Harden the dependency chain** and improve codebase maintainability
5. **Surface the memory system** as a first-class differentiator with marketing and documentation

Total actions: **22**  
Estimated total effort: 4–6 developer-weeks  
Requires human approval: Yes (commercial license terms — Phase 1 gate)

#### A03 — Pin Git Dependencies to Commit Rev/Tag

**Impact**: Critical  
**Effort**: Low (30 minutes)  
**Related Goals**: G1  
**Related Gaps**: Git dep reproducibility  
**Related Opportunities**: O6  

**Description**: In `Cargo.toml`, add `rev = "..."` for:
- `rmcp = { git = "...", rev = "<commit-sha>" }`
- `surreal-memory = { git = "...", rev = "<commit-sha>" }`
- `kreuzberg = { git = "...", rev = "<commit-sha>" }` (if git dep)

Pin to the current working commit SHA. Create a documented upgrade process.

**Rationale**: Git HEAD dependencies are a silent build reliability hazard. Any upstream commit to `rmcp` or `surreal-memory` could break UAR's build. This is not a theoretical risk — it has occurred in similar projects. A CI/CD pipeline (A01) makes this critical because CI will break on unexpected upstream changes without pinned revs.

**Verification**:
- Criteria: All git deps have `rev = "..."` specified; `cargo build` uses the same artifacts across different times
- Method: `cargo build` passes immediately after pinning; `cargo update` controlled explicitly

#### A04 — Implement UAR as MCP Server

**Impact**: High  
**Effort**: Medium (3–5 days)  
**Related Goals**: G2, G4  
**Related Gaps**: MCP server exposure  
**Related Opportunities**: O3  

**Description**: Expose UAR's runtime capabilities as MCP tools via an HTTP MCP server endpoint (similar to `memory/mcp_server.rs`). Suggested MCP tools:
- `uar_create_run` — Create an agent run from a spec or artifact
- `uar_list_agents` — List available compiled agents from the registry
- `uar_get_run_status` — Get run status and streaming URL
- `uar_list_skills` — List available native skills
- `uar_compile_spec` — Invoke the PMPO compiler from MCP

This enables orchestrators (LangGraph, AutoGen, Claude Desktop, and any MCP-aware system) to invoke UAR agents as tools without implementing the UAR REST API directly.

**Rationale**: MCP has 1000+ servers and is adopted by all major LLM providers. UAR being an MCP server multiplies its accessible ecosystem by 10x — any system that can call MCP tools can now invoke UAR agents. This is the single highest-leverage ecosystem expansion opportunity. The infrastructure already exists (`memory/mcp_server.rs` provides the pattern).

**Verification**:
- Criteria: `rmcp` server running at `/mcp/uar`; Claude Desktop can call `uar_create_run`; LangGraph agent can invoke UAR via MCP tool call
- Method: Integration test using MCP client; manual demo with Claude Desktop

**Impact**: High

**Impact**: Medium  
**Effort**: Medium (2–3 days)  
**Related Goals**: G1  
**Related Gaps**: server.rs maintainability  
**Related Opportunities**: O8

**Verification**:

#### A12 — Human-in-the-Loop Approval Workflow

**Impact**: Medium  
**Effort**: High (1–2 weeks)  
**Related Goals**: G3, G4  
**Related Gaps**: No human approval gates  
**Related Opportunities**: O9  

**Description**: Add to `RunManager`:
1. `PausePoint` mechanism: agents can emit a `NormalizedEvent::ApprovalRequired { run_id, question, context }` event

**Rationale**: Multiple enterprise sources cite human-in-the-loop as a critical production requirement. LinkedIn (2026): "Full autonomy isn't realistic or desirable initially. Cedar governance already has the policy enforcement model; this adds the orchestration mechanism.

**Verification**:
- Criteria: An agent that calls an MCP tool tagged `requires_approval: true` pauses and emits `agui.approval.required`; client can approve via REST; agent resumes
- Method: Integration test with approval-required native skill
