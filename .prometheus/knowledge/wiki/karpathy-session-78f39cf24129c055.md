## Delta

I've written the final plan, cut down to what users will actually do. It now runs about two pages instead of twenty, and duplicate-click protection is out.

**What the plan builds:**
- **The agent's UI shows up.** Every surface the agent publishes reaches an app on UAR's AG-UI route as a standard AG-UI activity, the format PEM 4.3.0 renders.
- **Clicks reach the agent.** A button press becomes a new run on the same conversation, carrying what the user typed. UAR first checks that the button is really on a live surface.
- **Clicking again works.** Surfaces belong to the conversation, so a button keeps working after the agent answers.
- **Reloading still shows the surface.** A client that reconnects to the conversation's latest run sees its surfaces again, without the agent running again.
- **The console stops showing raw action JSON.** That change goes through the repo's UI design review first.

**What's deliberately out, listed as known limits rather than designed around:**
- a resent click can act twice, as it can on UAR's existing action path today;
- PEM with default settings needs one setting to match UAR's catalog ids;
- very long runs and conversations;
- surfaces large enough to hit PEM's limits;
- specialists' surfaces on orchestrator conversations.

**The acceptance test is a single scenario:**
1. The agent publishes a surface.
2. The user types a note and clicks; the agent's answer contains that note.
3. The user clicks again with a different note.
4. A fresh client reconnects and sees the surface.
5. A fake button is refused.

That's three model turns.

I've also saved your direction as a standing rule: build and review for the likely path, and note rare cases instead of solving them.

One review is running now, and I've told it to report only problems that would break the four outcomes or the test in normal use. When it's back, I'll fix anything real, and then ask whether to start building.
