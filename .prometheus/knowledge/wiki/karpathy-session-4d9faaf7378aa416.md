## Delta

The lean A2UI plan is ready to build. The likely-path review found one real gap, and I've fixed it in the plan. Nothing is implemented yet.

**The gap: real clicks would have been rejected.**
- **Why:** the route currently requires every run to end with a new user message, and it refuses activity messages in the history. A real AG-UI client doesn't send a new message when someone clicks; it resends the conversation with PEM's click data attached. So every real click would have failed.
- **Why the test wouldn't have caught it:** the test could have added a fake user message and passed anyway.
- **The fix in the plan:**
  - click requests skip the "must end with a user message" check;
  - activity messages are ignored instead of rejected;
  - the test sends exactly what a real client sends.

**A smaller fix:** refusing clicks on orchestrator conversations now happens before the run is reserved, which is the only point where it can return a clear error.

**Everything else on the likely path checked out against the code:**
- the agent's surfaces will reach the app;
- earlier runs' surfaces can be restated from durable history;
- the restated frames won't collide with others;
- PEM keeps what the user typed when a surface is resent;
- a second click works once the agent has answered.

The plan, its review and the session log are updated.
