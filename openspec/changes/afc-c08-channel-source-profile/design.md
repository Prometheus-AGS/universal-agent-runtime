# Design

The authenticated host creates a scoped channel subscription. The subscription fixes owner, workspace, observer instance, source provider/account/workspace/room/thread/sender, and a Gate recipient-delivery grant identity. The ingress endpoint accepts the exact `frf.routed-observer/1` JSON payload; it refuses unsupported profile/classification or subscriber mismatch. `metadata_only` remains content-free. `policy_filtered` accepts only the exact `{ "text": "..." }` projection, with no media, attachments, chunks, or additional keys. UAR hashes the exact UTF-8 text for its own current Gate recipient-delivery release and persists the text on that subscriber's inbox row only after release. BossFang owns the prior source-disclosure release and protected projection storage; its local `projection_sha256` is not a Fabric wire field or a UAR authority token. The durable inbox identity is owner/workspace/subscription/delivery ID. An existing identity with changed occurrence, route, principal, classification or digest is a conflict.

The UAR sidecar receives its Gate endpoint, a narrowly scoped bearer and the corresponding service identity issuer, subject and revision from its supervisor, not the request. The Gate client replaces any caller-supplied identity with that protected process identity before every authority request; the original channel sender remains provenance and is never relabeled as a verified identity. UAR calls Gate evaluate then release for each exact recipient-delivery action. Gate revalidates current grant and policy, returns a release receipt, and UAR stores admitted, withheld or uncertain state. The API never logs or returns the bearer. The already admitted receipt is idempotent; the subscriber acknowledges the delivery independently of Fabric's offset. An opaque subscriber cursor is stored on the subscription; it is not an Iggy group offset.

The authenticated owner can inspect `GET /api/uar/channel-observers/v1/subscriptions/{id}/deliveries` under the same `x-uar-workspace-id` scope as subscription control. The response contains `subscriptionId`, the current `cursor`, and `deliveries` with only `deliveryId`, `occurrenceId`, `subscriberCursorId`, stored `status`, `admittedAt` and `updatedAt`. Paused and revoked subscriptions remain inspectable. The read changes no receipt or cursor and discloses no text projection, principal, grant or Gate receipt. Pause, resume, revoke and inventory are declared separately in the administration manifest.

The selected handler is a separate effect. UAR derives one deterministic C06 command ID from source occurrence, route revision and selected handler. It persists a pending receipt, obtains a fresh Gate handler-execution release as UAR's authenticated execution owner, then calls the existing C06 `submit` path. A repeated request with an admitted receipt only reads an existing matching C06 command; if no command exists, UAR reports uncertain and requires reconciliation. An observer delivery never submits a turn. Cancel uses the existing C06 owner path; Fabric detach is not cancel.

Current Gate service credentials must be JWT, MCP OAuth or Kratos with pinned issuer, audience and `afc.channel.effects.execute` scope. Gate requires that the authenticated UAR execution-owner issuer equal the issuer of each recipient-delivery and handler-execution grant; BossFang must provision those grants under that same issuer. Grant mutation uses a separate `afc.channel.grants.write` scope, which the UAR bearer must not carry. Installed enablement depends on the supervisor supplying the restricted credential through private process environment, with `UAR_CHANNEL_GATE_URL` pointing to Gate's admin-router base URL, `UAR_CHANNEL_GATE_BEARER_TOKEN` containing the bearer, and `UAR_CHANNEL_GATE_IDENTITY_ISSUER`, `UAR_CHANNEL_GATE_IDENTITY_SUBJECT` and `UAR_CHANNEL_GATE_IDENTITY_REVISION` identifying the authenticated host service used for Cedar evaluation. Local embedded SurrealDB is one-host only. A remote `ws://` or `wss://` endpoint is eligible for durable C06/C07/C08 state only when the trusted supervisor sets `UAR_REMOTE_SURREAL_DURABILITY_ATTESTED=1`, attesting a persistent SurrealDB 3.3.0 server; the URI alone cannot establish that property. The C06 source/outbox transaction remains unchanged. Final C08 acceptance must exercise a real remote restart/CAS path before cross-host support is advertised.

Provider candidates inspected for this change are Flint Gate commit `b1539705` (`afc.channel-authority/1`, separated effect/grant scopes) and Flint Realtime Fabric commit `8966d6b` (`frf.routed-observer/1`). They are integration inputs, not proof of installed UAR compatibility. The BossFang/Fabric consumer and replay worker is outside this UAR change; the UAR capability response therefore keeps `crossHostSupported: false` until that route is implemented and its composed gate passes.

SurrealDB's [transaction reference](https://surrealdb.com/docs/learn/querying/concepts-and-guides/transactions) specifies atomic manual transactions and conflict checks across embedded and server backends. The [BEGIN statement](https://surrealdb.com/docs/reference/query-language/statements/begin) groups one query's statements as one transaction. These database semantics support the existing CAS/outbox query; they do not prove the external server's storage durability or the full C08 application flow.
