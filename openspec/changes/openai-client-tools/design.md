# Design: shared caller-tool lifecycle

The approved plan adds caller-executed function tools alongside governed host tools. Tools enter through authenticated protocol adapters, ClientToolInput and immutable ResolvedStep snapshots. Host descriptors remain executable only through existing host policy; client declarations have no executable descriptor. Duplicate names/collisions are rejected at each advertisement boundary.

Provider controls use llm::ToolChoice Auto/None/Required/Named and parallel_tool_calls. Provider adapters preserve schemas/strict settings or refuse unsupported controls explicitly. The model-call output is classified by frozen ownership. Mixed batches settle host calls, then persist canonical transcript and caller pending batch before public ClientToolsRequested. Tool calls are given uar_client_<batchUUID>_<callUUID> locators; locators locate evidence, never grant authority.

Persistence binds full credential-principal owner key, tenant, actual artifact agent, native source run/session, protocol, exact client declarations/controls and visible history. Private canonical history includes internal host results. Pending->Claimed->Completed transitions use durable CAS. Identical completed submissions replay the saved wire projection; competing/changed submissions cannot execute host effects again. Fresh policy and credentials are re-admitted. Protected graph state resumes the current model node and budget snapshots retain cumulative accounting and original budget timing. No active provider resource remains held while the caller waits.

OpenAI uses tool_calls and role:tool results, finish_reason:tool_calls, JSON or indexed SSE. AG-UI uses pinned native tools, pendingToolCallIds, role:tool/toolCallId continuation and existing approval/elicitation interrupts. Its controls extension is forwardedProps.uar.client_tools. Anthropic uses tool_use/tool_result, native tool_choice and stop_reason:tool_use. A2A uses a versioned declared extension in message/task metadata and INPUT_REQUIRED tasks. Repository ACP is Agent Communication Protocol, with owner-scoped session/run methods and runs/submit_tool_results. A2A/AG-UI completion receipts may identify the same durably admitted run; final run state remains authoritative, and replay never readmits.

## Ownership
Lead: normalized/domain events, API resource ingress, remaining request initializers, scoped phase/OpenSpec records and release handoff. Runtime writer: orchestrator, run manager, turn request/snapshot and graph cursor. Persistence writer: DTO, PostgreSQL/Surreal/migrations/scoped facade and common ingress service. OpenAI writer: OpenAI wire and acceptance driver/fixture. AG-UI writer: native adapter. A2A writer: A2A + actor ingress; subsequent bounded accounting ownership cost_budget.rs. Provider writer: provider controls, ACP and Anthropic HTTP segment. One writer per file; no build writer while gate CLOSED.

## Verification boundary
All activity before boundary is source inspection or authorized implementation/documentation. No tests, builds, compiler/import probes, format/lint checks, policy validators, diff --check, review-driven verification or external gates. Prior release-only exceptions do not authorize this feature. Whole active-phase canonical ledger still has pending acceptance and138/153 metric; this scoped ledger cannot override it.
