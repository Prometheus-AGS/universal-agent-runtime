# Proposal

## Why

Original AFC C14.4 requires an ordinary BossFang workflow to execute through the selected UAR with real host-approved effects. The scoped grant cannot supply The Boss's private MCP/admission bridge, and resolving the UAR approval without first recording host authority cannot authorize that effect.

## What Changes

- Register a private process-local context using host authentication and an existing live delegation grant, authenticated workspace and catalog-resolved immutable binding.
- Give the delegated caller only an opaque reference; inject the captured resources after existing bound-agent resolution.
- Coordinate the exact pending UAR issuer/challenge with the private host before resolving the existing waiter. Revalidate the grant/context lease at protected effect claim.
- Preserve existing admission retry semantics, native runs and grants; do not share host credentials, enable native file tools, replace scheduling or introduce a second effect/budget owner.

## Capabilities

### New Capabilities

- `delegated-host-context`: Host-controlled private resources and host-first approval for scoped full-harness delegation.

### Modified Capabilities

None.

## Impact

UAR security grant identity, full-harness admission/control and existing run resource attachment; mechanical server state wiring. The Boss owns bridge creation and canonical human decisions; BossFang retains only the safe context reference. Existing provider resolution and realtime approval events remain authoritative. No dependency changes or KBD ledger edits. Runtime UX gains actionable context refusal; native Windows and completed-boundary approved/denied/cancelled operation remain pending. The uncomfortable case is an expired original grant: an original run cannot silently adopt a replacement context.
