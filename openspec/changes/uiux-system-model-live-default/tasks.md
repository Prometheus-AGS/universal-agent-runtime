## 1. System default action and picker (frontend)

- [ ] 1.1 Add one domain action `setSystemDefaultModel(providerId, modelId)` in the providers platform entity domain, exported through `@/platform/entities`. It fetches the provider's current config, calls `updateProvider` with the new `default_model` only when it differs (`providers-api.ts:57-68`), then calls `setDefaultProvider` (`providers-api.ts:70-73`). Reuse both existing API functions; add no endpoint.
- [ ] 1.2 In the action, publish the result as one atomic `ProviderMeta` update carrying `default_id` and `default_model`. Remove the optimistic `default_model: null` write at `providers-store.ts:156-176` so the displayed pair is never half-populated.
- [ ] 1.3 Map failures (a failed provider save issues no default route call; an optimistic default is rolled back on any failure): 404 from the route and 409 from the update (`TEAM_REVISION_CONFLICT`, `providers.rs:285`) become visible picker errors; on 409 refetch the provider and keep the picker open; on route failure after a successful model write show "model saved, system default not changed".
- [ ] 1.4 Build the System default model panel on the shared picker from `uiux-schema-controls-and-pickers` (Base UI Combobox, cand-002). If that component is not yet available, reuse `features/models/ui/model-selector.tsx`. Offer only enabled providers and models present in the provider's models. Subscribe at the smallest boundary (one field per control) per the entity-state rule.
- [ ] 1.5 Show the live pair from `ProviderMeta` and the existing `SystemDefaultModelStatus` states (loading, unavailable, error, available). Name the missing part when no usable default exists (no default provider, disabled, no `default_model`).
- [ ] 1.6 Point the Models-page star (`models-store.ts:111-121`) and the Providers-page make-default action (`providers-store.ts:156`) at the same action. Do not add a second write path.

- [ ] 1.7 In the default route handler (`src/uar/api/providers.rs:367-399`), after the existence check, reject a disabled provider with 409 and `{"error":"Provider '{id}' is disabled"}` before any persistence or registry swap. The registry returns no default pair for a disabled default provider (`src/llm/registry.rs:551-563`), so accepting it leaves agents without a model. Do not change boot hydration (`provider_sync.rs`). Surface the 409 in the picker error state (1.3).
- [ ] 1.8 Do not write `llm.default_provider` from the console or any new code path. The row is written only by the default route and the boot seed; the settings API rejection is owned by `uiux-settings-truthful-status-and-removals`, and replica refresh of the registry default from the row is owned by `uiux-realtime-topics-and-replica-refresh`.

- [ ] 1.9 Mount the shared `CatalogModelPicker` (from `uiux-schema-controls-and-pickers`; Base UI Combobox with `@tanstack/react-virtual`, candidates cand-002 and cand-003) over the whole provider-qualified `Model` entity set from `uiux-model-identity-graph-ownership` (8,170 catalog pairs plus configured custom models). Reuse it; build no second virtualized list. Confirm virtualization engages above 1,000 options, at most 200 option elements are in the DOM, the match count is shown as `<n> models`, the query is deferred rather than re-rendering the full list per keystroke, and entries whose provider is not configured and enabled (or whose model is not in the provider's models) render as non-selectable.
