## Why

The repo has extensive `docs/*.md` but no published documentation site — a
2026 baseline expectation for customer-adoptable software, and the deferred
deliverable from the prior phase. Operator decision (2026-07-10): Docusaurus on
GitHub Pages via GitHub Actions.

## What Changes

- Scaffold a Docusaurus (classic, TypeScript) site under `website/`, configured
  for GitHub Pages (`Prometheus-AGS/universal-agent-runtime`, baseUrl
  `/universal-agent-runtime/`), blog disabled, autogenerated docs sidebar.
- Add `.github/workflows/deploy-docs.yml` — builds the site and deploys to Pages
  via `actions/deploy-pages` (Actions source), on push to `website/**`.
- Author real documentation pages: Introduction, Installation, Configuration
  reference (every env var + `UAR_*__*` convention + precedence), Backup &
  Restore runbook (embedded SurrealKV), Upgrade guide, Troubleshooting, and an
  API reference — sourced from the real repo.

## Capabilities

### New Capabilities
- `public-docs-site`: a published documentation site covering install, config,
  operations runbooks, and API reference, built and deployed from CI.

## Impact

New `website/` tree + one CI workflow; no runtime code touched. Operator must
enable Pages (Source: GitHub Actions) once. KBD: change 7/9.
