# Design

Authoritative design: .kbd-orchestrator/phases/uar-verification-simplification/analysis.md, coverage-matrix.md, plan.md and exit-contract-draft.md.

Use a registry-driven, dependency-aware serial runner with workflow-local fixture acquisition and append-only attempt outcomes. Reuse existing genuine predicates and host ownership/resource protections. Generate mandatory KBD envelopes from the compact run plan rather than creating an incompatible signing scheme. Current gates remain closed until explicitly superseded. No all-platform/store prerequisite; no mock completion; no omitted legacy obligation.

Risk: a thin wrapper may retain old all97/both-store admission. Acceptance of implementation requires a configured-prompt cell to run with only its named local prerequisites, while missing KB/Windows/iOS resources remain separately visible. Counter-risk: deleting old harness assertions may weaken coverage; require a migration map for every existing case and supporting obligation.

Operator sequencing refinement: finish the complete applicable macOS verification sweep, then Linux, then iOS. Preserve within-platform independence, unresolved outcomes, shared-fix carry-forward and affected earlier-platform regression evidence. Windows is outside this selected sweep with its blocker retained; Android deferred. This refinement has not undergone a new isolated design critique; the existing critique covers the predecessor design only.
