## ADDED Requirements

### Requirement: Keep finite supported release promises
Release/support/version/recovery/measurement source SHALL use one selected-lane contract and existing receipt/checklist tooling; artifactidentity, independentroles, extraction/lifecycle/recovery and comparative exclusions SHALL be finite and explicit. No missing evidence may be relabelledpassed.

#### Scenario: Final qualification is prepared for a selected artifact
- **WHEN** Final qualification is prepared for a selected artifact
- **THEN** Every promotedpromise maps to an authored applicable case or existing justified receipt, with blocked/unverified/excluded/historical outcomes separate

#### Scenario: A pinned source contains reviewed missing metadata links
- **WHEN** A clean candidate includes the exact committed links from a reviewed pinned checkout whose metadata targets are absent
- **THEN** The inventory retains each link's tracked path, blob bytes and unresolved state without reading outside the source tree
- **AND** A moved pin, new dangling path, mismatched link, or external or ambiguous traversal refuses the candidate

#### Scenario: The container context excludes Git metadata

- **WHEN** the root Dockerfile receives the approved source context without Git metadata
- **THEN** it consumes the already-initialized vendored inputs from that context
- **AND** a missing required input fails before dependency installation with its path and the recursive submodule setup requirement

#### Scenario: The selected Linux container packages the frontend

- **WHEN** the root Dockerfile builds the frontend from the exact frozen candidate
- **THEN** Vite resolves the existing configuration paths and plugin through native module syntax, and the realtime transport reuses its already loaded adapter module
- **AND** the receipt retains actual bundle diagnostics and fails on first-party warnings, with only explicitly authorized and recorded third-party exceptions

#### Scenario: The installed image path rejects malformed base64

- **WHEN** a request contains malformed inline image base64
- **THEN** the exact safe invalid_image_base64 code remains recognizable in the qualification check without exposing request data
- **AND** no isolated provider receives the refused request

#### Scenario: The installed document profile settles extraction truthfully

- **WHEN** local English OCR is enabled in the selected Linux image
- **THEN** the packaged pinned language data is available to the non-root runtime without a download at extraction time
- **AND** the mounted qualification retains the actual extracted fact and document provenance from a frozen, legible image fixture
- **AND** malformed or empty extraction cannot publish an indexed generation, deterministic rejection becomes a terminal failed job, and transient failures keep their existing retry budget

#### Scenario: Installed final-wire accounting is carried in a retained artifact

- **WHEN** the selected peer receives an image-bearing request and the run retains its provider budget artifact
- **THEN** qualification decodes that exact run-scoped artifact and checks its qualified destination, while the peer observation checks the destination's actual wire model
- **AND** an attempt manifest alone cannot substitute for final-wire estimated counting evidence

#### Scenario: A verified inherited chat model has an authorized fallback

- **WHEN** ordinary chat inherits its verified primary and the provider fails before output
- **THEN** the runtime retains the verification receipt and may dispatch only to a fallback authorized by the existing run policy
- **AND** each fallback must have current verification for its configured destination and pass its own capability, credential and final-wire budget checks
- **AND** explicit model selections, saved conversation models and bound targets retain exact scope

#### Scenario: Selected independent protocol clients cancel actual active work
- **WHEN** A selected independent A2A client or official MCP counterpart observes positive activity and cancellation is requested for the original task or call
- **THEN** The case retains the original protocol/native identity, observes actual counterpart termination or explicit refusal/uncertainty, and cannot substitute generic model-stream cancellation for protocol evidence
- **AND** Unknown effect or billing liabilities remain retained rather than silently cleaned up or replayed

#### Scenario: Standalone MCP cancellation leaves a claimed effect unresolved
- **WHEN** an approved standalone MCP call is claimed and cancellation closes the connection without a definitive result
- **THEN** the owner-scoped admission evidence retains the same invocation as outcome unknown
- **AND** qualification correlates the model call and durable invocation through their approved admission, verifies cancellation of the original SDK request separately, and retains any unresolved-effect shutdown refusal

#### Scenario: A release branch incorporates dependency changes from main
- **WHEN** a release branch is reconciled with main after dependency changes
- **THEN** the committed lockfile resolves the merged manifests with the selected dependency pins intact
- **AND** the affected local gates consume that lockfile in locked mode before the reconciled source is promoted

#### Scenario: Publish the RC3 Linux amd64 pilot from a locally verified image
- **WHEN** the RC3 source and image are published for the selected pilot
- **THEN** the product version, exact embedded Rust SDK pin and repository tag identify the same source
- **AND** the versioned registry image identifies the exact locally built and checked Linux amd64 artifact
- **AND** the version tag does not trigger a second publisher that replaces the image with a separately built multiarchitecture index
- **AND** the public guide records the pilot scope and the outstanding final qualification separately

### Requirement: Prepare reproducible packaged-runtime measurements without inventing promises
Measurement source SHALL require a frozen workload, hardware/profile, concurrency, thresholds, token budgets and exact source/artifact/provider/settings identities before execution. Controlled-provider framework measurements, real-model task quality and comparative results SHALL remain distinct.

#### Scenario: Measurement selection has not been supplied
- **WHEN** A measurement manifest remains UNSELECTED or lacks its required frozen selections
- **THEN** Measurement refuses before product HTTP activity and supplies no capacity, reliability, quality or SLO pass

#### Scenario: A selected deterministic measurement records actual observations
- **WHEN** The prepared case measures the packaged runtime through its actual streaming API
- **THEN** It retains raw request outcomes and semantic first/complete latency distributions with sample counts, provider timing and explicit resource/startup/queue availability
- **AND** Missing required observations or mismatched reliability receipts cannot become a passing selected promise

#### Scenario: The first Linux candidate has an error-only measurement threshold
- **WHEN** the frozen synthetic workload runs at concurrency 1 and 4 with eight requests per round and three repetitions per concurrency
- **THEN** the existing measurement receipt qualifies the threshold only if all 48 requests complete with zero observed errors
- **AND** latency, throughput and resource samples remain observations without a latency or capacity promise

#### Scenario: No-tools measurement uses native turn admission
- **WHEN** the controlled no-tools measurement submits original native turn and user message IDs
- **THEN** the request omits the caller-owned tools field and retains the original native IDs for read-only reconciliation
- **AND** the peer observes zero offered tools and the original zero-error and sample-count assertions still apply

#### Scenario: An unchanged retained agent is serialized with a different object-key order
- **WHEN** an installed reliability scenario re-reads its retained agent before dispatch
- **THEN** it compares the complete definition in deterministic object-key order while preserving array order
- **AND** any changed field value or ordered element still fails the frozen-definition check

### Requirement: Keep functional qualification free of authentication plumbing
Functional qualification SHALL use externally provisioned identity ingress and opaque host-owned configuration. Fixtures SHALL NOT mint, copy or send credentials, substitute synthetic verified identity, or weaken the original runtime/persistence/effect assertions. Dedicated authentication-security regression coverage remains separate.

#### Scenario: Accounting refuses a run before protected content is admitted

- **WHEN** accounting refuses the run before the host completes its captured publication boundary
- **THEN** only the existing safe error and terminal lifecycle events are published, without generated presentation patches
- **AND** successful admission still enables the existing content and presentation publication

#### Scenario: A persisted graph fixture enters through production admission
- **WHEN** a controlled graph case exposes a tool and uses durable storage
- **THEN** its fixture supplies the production skill-matching service and registers the controlled model's tool capability
- **AND** when the controlled model lacks catalog capacity, its registered synthetic window allows the runtime to apply the ordinary finite output reservation
- **AND** missing persisted history still fails the scenario, with its admission and provider observations retained for diagnosis

#### Scenario: The isolated MCP outcome fixture observes owned peer lifetime
- **WHEN** the controlled stdio MCP peer starts under the isolated verifier
- **THEN** it publishes a process-owned lock before discovery and the verifier checks peer counts and closure by observing that lock
- **AND** the pre-dispatch case still terminates a live owned peer and checks its exit, typed outcome, and absence of an effect

#### Scenario: A controlled team Chat call settles before the next provider dispatch
- **WHEN** a completed controlled Chat stream was requested with streaming usage enabled
- **THEN** the peer reports deterministic provider counters before its stream terminator so ordinary durable accounting can settle the call
- **AND** the next provider call still requires the existing finite team reservation and the tool outcome assertions remain in force

#### Scenario: A Dot04 writer reads the protected deployment catalog
- **WHEN** a functional team or agent-instance writer requests the exact deployment-catalog GET through its loopback fixture host
- **THEN** the host forwards the configured admin key and existing verified owner to the real endpoint without exposing credentials to the functional client
- **AND** the ingress drops caller-supplied authentication and supplies no admin key on other methods or paths

#### Scenario: A trusted Rust host composes a credential-free fixture handler
- **WHEN** A trusted host supplies additional routes through the server's host-route entrypoint
- **THEN** Those handlers use the ordinary initialized server state, production identity/governance middleware and owned shutdown path
- **AND** A genuinely verified context may remain in process while the client receives no credential or serialized identity
- **AND** Existing server entrypoints install no additional host routes

#### Scenario: Measurement consumes a final release artifact
- **WHEN** A selected measurement or reliability case consumes release evidence
- **THEN** Its source inventory is captured from the actual clean committed release into an ignored or external output and agrees with existing release input provenance and the successful image-build receipt
- **AND** Before/after artifact and selected setting observations remain bound to the same candidate; dirty implementation snapshots and incompatible Dot candidate inventories cannot certify it

### Requirement: Reconcile historical AG-UI terminals without inventing settlement
An unsealed durable wire binding SHALL reconcile exact authenticated native terminal evidence after residency loss without executing the original again. Historical terminal evidence SHALL NOT by itself prove successful local producer or graph cleanup.

#### Scenario: Process residency ends before the wire terminal is sealed
- **WHEN** The exact owner/agent/session/native-run binding and native terminal record/events are durable but the wire terminal was not sealed before residency loss
- **THEN** Reconciliation closes the original wire disposition with retained native outcome evidence and explicit cleanup uncertainty rather than generic projection_unavailable
- **AND** Original errors/cancellation remain truthful, repeated reconnect returns the same CAS-sealed terminal/cursor, and further thread admission uses unchanged predecessor, identity, budget and approval checks without replay

#### Scenario: Owned local work or insufficient historical evidence remains
- **WHEN** An owned local producer/graph root remains, or durable evidence is missing, mismatched or nonterminal
- **THEN** Reconciliation cannot bypass local settlement, fabricate cleanup success or dispatch the original again; uncertain or unavailable evidence stays explicit

#### Scenario: Cancellation follows a retained persistence diagnostic
- **WHEN** A cancelled native run has a same-run diagnostic Error such as session_persist_failed before its matching final Cancelled event, and the exact durable run status is Cancelled
- **THEN** Historical recovery uses the matching cancellation event/cursor while retaining preceding diagnostic codes, messages and cursors in native terminal evidence
- **AND** It seals the same cleanup-unconfirmed wire error without success or replay, preserving exact identity/cursor/CAS and successor admission guards
- **AND** Missing matching cancellation, malformed/foreign correlation or contradictory terminal ordering cannot be accepted by blanket error suppression

### Requirement: Preserve admitted native identity separately from the wire selector
AG-UI correlation SHALL preserve the originally admitted native artifact identity independently of a deployment-bound wire selector. Recovery SHALL compare the exact owner, native run, originally admitted native agent and session without re-resolving a mutable current catalog.

#### Scenario: A deployment target selects a differently named artifact
- **WHEN** A supported AG-UI request uses a deployment target whose selector differs from its admitted artifact ID
- **THEN** Resident and historical correlation retain both identities and permit the original authenticated run to project and reconcile
- **AND** A changed current target cannot replace original admission evidence; wrong owner, native run, artifact or session remains refused

#### Scenario: A resident cancelled run emits diagnostics before cancellation
- **WHEN** A settled resident Cancelled run emits same-run diagnostic Errors before its matching final Cancelled
- **THEN** Its wire cancellation uses the matching final cursor and retains preceding diagnostics and actual cancellation usage
- **AND** A diagnostic-only prefix cannot seal cancellation, while duplicate, trailing, foreign or contradictory terminal evidence is refused

#### Scenario: Saving an already-cancelled native turn fails
- **WHEN** The runtime has established cancellation and its final session save fails
- **THEN** The original persistence diagnostic remains nonterminal through the existing host diagnostic transport, followed by the actual cancellation and available usage
- **AND** Native and standard AG-UI/historical evidence retain the diagnostic's original run and cursor; ordinary non-cancelled save failure remains an error
- **AND** Legacy diagnostic Error prefixes remain readable without weakening immutable client terminals or adding a protocol parser

#### Scenario: Graph cancellation cleanup succeeds but its session save fails
- **WHEN** A graph run is cancelled, all actual owned cleanup operations confirm completion, and only saving its cancelled session fails
- **THEN** Session/native projections retain cancellation, emit the existing nonterminal persistence diagnostic, then emit cancellation
- **AND** A genuine unconfirmed cleanup operation remains an error; session-save diagnostics cannot hide it or manufacture cleanup proof

#### Scenario: Browser history acceptance inherits the saved session model
- **WHEN** The shipped Send path intentionally omits a model override and uses saved AgentSession policy for a controlled tool-loop turn
- **THEN** Its fixture asserts inherited-policy dispatch and qualifies the actual selected model through existing authoritative configuration/admitted/provider evidence
- **AND** It retains canonical segment/reload/provider-arrival/effect-count assertions without requiring an impossible POST model override or changing production policy

### Requirement: Qualify audit remediation on the release candidate

The Linux amd64 release candidate SHALL retain the existing vulnerability gates and verify dependency changes on the exact affected lockfiles and artifact. Historical candidate receipts retain their original identity.

#### Scenario: The release candidate updates dependencies to resolve audit findings
- **WHEN** audit remediation changes direct, transitive or vendored dependencies
- **THEN** the affected package and runtime checks exercise the resolved graph
- **AND** the release evidence records the candidate's audit result separately from default-branch alert state and the prior candidate's receipts

#### Scenario: A2UI consumers migrate to a patched Zod 4 boundary
- **WHEN** the shipped UAR renderer or the independent PEM client processes a valid A2UI surface and dispatches a catalog-defined action
- **THEN** the renderer, catalog and binder exchange Zod 4 schemas through the same compatible core in that consumer, preserving data-model bindings and action forwarding
- **AND** Node renderer checks load the same vendored core with its standard decorators compiled, preserving the existing renderer assertions
- **AND** product frontend lint excludes the three vendored A2UI core and reference-renderer directories and keeps its existing rules for first-party source
- **AND** oversized constrained input is refused before traversing its elements, and rich Markdown remains sanitized
- **AND** the existing independent client scenario retains its original interaction and refusal assertions, records the exact packages installed, and distinguishes locally packed compatibility evidence from published registry evidence

#### Scenario: A fresh embedded store receives its first A2UI action
- **WHEN** the trusted SurrealKV host opens a fresh store and a valid AG-UI action checks for an earlier logical receipt
- **THEN** startup has initialized the receipt table and the lookup returns no prior receipt
- **AND** the first admitted claim retains its original scope and identity, while repeated, conflicting, or uncertain claims preserve the existing no-redispatch safeguards

### Requirement: Bind signed image platform claims to published bytes
The release workflow SHALL bind platform claims to the exact published image index and require a passing security audit for the same artifact before signing.

#### Scenario: The release candidate has one runtime platform
- **WHEN** the producer receives a digest-addressed image index containing one runtime platform and attestation descriptors
- **THEN** the manifest declares the runtime platform from the verified index and the independent verifier rejects a changed index or inconsistent platform list

#### Scenario: Release audit evidence fails
- **WHEN** the audit receipt is failed or belongs to another image
- **THEN** the existing producer refuses before creating release output or submitting signatures

#### Scenario: Evidence is mixed across candidate images or repositories
- **WHEN** an RC4 or later evidence bundle omits its digest-bound image index, or the producer receives mismatched source, image, archive or repository receipts
- **THEN** verification refuses the incomplete bundle and the producer refuses mismatched receipts before requesting signatures
- **AND** preparation reports success only after verifying the image signature and both attestations against the approved identity and issuer
