# Design

The existing collaboration catalog remains the single durable writer for team state. Its compare-and-swap transition admits a ready task only against the current team/task/member revisions, ownership epoch, installed binding, host workspace and immutable team definition limits. One transition records the attempt ID, root run ID, aggregate token/cost/time reservation and dispatch intent. A duplicate command returns its receipt. A stale member or insufficient budget returns an explicit denial without starting a turn. A crash between reservation and dispatch is recovered from the durable intent, not by creating another attempt.

The runtime bridge submits that reserved attempt through the existing actor host and captured thread kernel. It resolves the bound agent and current Cedar/host policy rather than promoting C09.2 `assignmentAuthority` into a grant. The tool-claim revalidator checks team, member, task and attempt epochs at each protected effect; revocation fences future delivery and effects. Cancellation and uncertain external effects retain truthful attempt state and reservation until reconciled. Per-instance turn serialization and aggregate admission bound concurrency.

Context is selected explicitly from task input and authorized artifact/history/memory references. Store durable, owner/workspace/team/task/member-labelled artifact references in the team catalog; the existing per-run in-memory artifact receipt is not a substitute. Deliver only the selected projection to a member. Parent-to-child delegation intersects authority and limits, never unions histories or permissions.

Usage settlement is keyed by attempt/run identity and uses cumulative provider counters without double charging streamed updates. A known terminal result settles the reservation; unknown usage remains reserved and visible. Budget, revocation, dispatch, selected-context, artifact and usage views are revisioned, paged where needed, and available through fixed authenticated routes. `teamInstance` becomes executable only for storage modes and runtime paths actually proven to support durable recovery. The Boss presents the authoritative UAR projection in Teams settings, including admission/denial reason, member status, usage uncertainty and recovery controls. It adds all 13 existing locale strings and no duplicate settings database state.

Ownership is split to avoid shared-file contention: one writer owns catalog admission/usage and shared domain registration; one owns membership/context/artifact modules after the schema is fixed; one owns the actor-host bridge and effect revalidation. The Boss adapter/IPC and UI/locales are separate TypeScript owners. One Rust build writer and one Boss build writer operate only at the completed increment boundary. The gate exercises a real member turn, restart, duplicate dispatch, exhausted budget, stale owner, revocation before protected effect, selected context isolation, and remote Surreal behavior where configured. No per-task/unit/mock verification loop runs during implementation.
