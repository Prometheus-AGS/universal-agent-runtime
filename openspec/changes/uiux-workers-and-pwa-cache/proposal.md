## Why

Phase `uar-uiux-architecture-2026-11` goal G8: use web workers only where they help and
have no side effects. The assessment found that no worker exists besides the PGlite
worker added by `uiux-local-first-persistence-worker`, and that the service worker leaks.
Reading `frontend/public/sw.js` shows three defects, not one:

1. **Cached assets are never evicted.** One fixed cache name `uar-v1` holds every
   `/assets/*` response (`sw.js:4,50-64`); the activate handler deletes only other cache
   names (`sw.js:22-31`), so entries from earlier builds stay forever. The file's bytes do
   not change between deploys (it is copied from `public/`), so a deploy does not
   re-trigger `install` or `activate`; eviction cannot rely on the activate event.
2. **Unhashed static files are frozen.** The cache-first rule matches any path ending in
   `.js`, `.css`, `.svg`, `.png` or `.woff2` (`sw.js:50-56`), so `/brand/*`,
   `/apple-touch-icon.png` and any non-hashed script are served from cache forever once
   stored. `manifest.json` goes through the network-first branch.
3. **Navigations grow the cache per URL.** Every navigation response is stored under its
   own request key, query string included (`sw.js:73-80`); an SPA serves one HTML shell for
   all of them.

The second goal item is a possible catalog worker. The Models page runs the pure
functions `projectModelRows` and `filterModelRows` over about 8k rows
(`features/models/model/model-catalog-view.ts:26-76`, `models-page.tsx:110,136`), but it
also renders every filtered row without virtualization (`models-page.tsx:326`). A worker
removes the compute, not the rendering. This change therefore specifies the worker as
conditional and records the case against shipping it.

## What Changes

- Rewrite the service worker's cache policy: hashed build assets kept for the current and
  previous build only, unhashed static files stale-while-revalidate, one shell entry for
  navigations, API and stream traffic never intercepted, and the legacy `uar-v1` cache
  deleted on upgrade. No new dependency; no build step stamps the worker.
- Specify an optional dedicated module worker for catalog projection and filtering, enabled
  only if Plan keeps it. It is side-effect free, falls back to the identical main-thread
  functions, and discards stale results.
- Record, as the measured gate, a scenario that times catalog filtering on the real catalog
  so Plan can drop item 21 on evidence.

## Capabilities

### New Capabilities

- `frontend-web-workers`: rules for computation workers in the console (purity, fallback,
  result ordering) and the optional catalog worker.

### Modified Capabilities

- `pwa-offline`: adds cache-lifetime and cache-bound requirements for the service worker.
  Existing requirements (offline asset caching, offline UI indicator, non-http(s) schemes
  never cached) are unchanged.

## Impact

- `frontend/public/sw.js` and, only if the catalog worker is kept,
  `frontend/src/features/models/**` and a new worker module beside
  `features/models/model/model-catalog-view.ts`. `frontend/src/main.tsx:45-49` registers
  `/sw.js` and is not changed.
- `frontend/public/sw.js` is outside `frontend/src/**`; the lead must assign a single writer.
  The static build output `static/sw.js` is a copy of `frontend/public/sw.js` (verified
  identical with `diff`) and is regenerated by the build.
- Dependencies: the catalog worker depends on the final Model row shape from
  `uiux-model-identity-graph-ownership` (the key becomes `${providerId}/${modelId}`); it
  must follow that change. The PGlite worker is in `uiux-local-first-persistence-worker`
  and shares only the hashed-asset cache policy (its worker script is a hashed asset).
- Rejected alternative recorded in `design.md`: Workbox / `vite-plugin-pwa`. Not evaluated
  against the registry; this change adds no dependency.
