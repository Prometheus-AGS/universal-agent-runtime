# Design: user-outcome acceptance

## Decisions

The phase assessment, analysis, plan and 25-family coverage matrix under `.kbd-orchestrator/phases/uar-post-lifecycle-verification-readiness/` are this change's detailed design inputs. The unit of acceptance is useful work through the actual mounted boundary, with observed configured inference and durable state. Protocol conformance, typed failures, accounting, review and builds are necessary supporting claims where mapped; none substitutes for task completion.

Use shared outcome predicates with separate protocol adapters and store fixtures. Freeze all reachable supported entrypoints/modes and customer strategy selectors into an instantiated case manifest before execution. Required outcomes run on both Postgres+pgvector and durable Surreal; deep cases use a representative native path plus necessary AG-UI/browser-specific paths. Three fresh positive repetitions and true process restarts provide bounded repeatability evidence, not a statistical SLO. Missing resources block; synthetic providers serve fault injection only. First failed invocation stops and preserves evidence before exact-owned cleanup.

The orchestrator selects from current authorized persisted agent definitions and executes the selected artifact through the existing child-thread contract. This is separate from skill classification. Current `defaults.rs::orchestrator_graph` uses a fixed general-purpose/rust-reviewer roster, so registered-roster routing needs explicit implementation work. Preserve current user-facing protocol contracts; expose selection through normalized events and AG-UI custom-event delivery, with agent/run/thread/roster correlation and no private reasoning. The same case must prove selected-agent contribution and context continuity, not merely the selected label.

Protect default-agent and orchestrator-agent at every public management mutation boundary using the domain guard. Verify denied deletion leaves persisted and live definitions unchanged; recreating an agent at next boot does not pass. Custom agent create/update/delete remains supported and prompt revisions affect execution after restart.

For skill/context/KB/team gaps, follow the effective production path recorded in the source traces. A fallback algorithm is not proof of the requested algorithm; a rejected embedding-space change is not regeneration; a saved wait is not arbitrary process-future restoration. Required designed behavior stays pending until implemented and covered. Do not add speculative runtime defenses or broad refactors.

## Ownership and safety

Lead owns canonical state, shared composition/schema files and harness integration. Runtime, provider, state, trust and console specialists receive file-owned packets. One build writer; no early tests. UI implementation later follows installed design/entity rules. Native KBD commands own generated ledger projections; do not edit tasks/progress/waypoint projections by hand. Record static review isolation and unavailable machine screening honestly.

## Trade-off and unverified claims

The expanded suite may expose missing production behavior and exceed a bounded packet; stop/incomplete is preferable to a fabricated certification. Current source findings are not test results. Old packet failures remain failed, and absent raw causes remain unrecovered. No product reliability, supported-platform equivalence or new source build claim is made by this design.
