# Proposal

## Why

The existing post-lifecycle packet cannot establish whether users can accomplish UAR's supported tasks. It combines useful internal controls with synthetic provider responses and incomplete failure evidence, while missing positive interface, durable agent, effective strategy, regeneration and team-context journeys. The operator requests source assessment, analysis and a replacement plan before further implementation or verification.

## What Changes

Define user-outcome acceptance for configured genuine inference, supported prompting interfaces, durable/protected agents, live-roster orchestrator routing and streamed selection, effective skills/context, grounded KB regeneration, Postgres/Surreal parity, teams, REST configuration and startup maintenance. Preserve historical failed packets and separate publication from product suitability. Plan bounded production/harness slices; keep all executable gates closed until source completion, inventory and renewed authority.

## Capabilities

### New Capabilities

- `agent-definition-lifecycle`: persisted user-defined agent behavior and protected default/orchestrator deletion through supported management interfaces.

### Modified Capabilities

- `product-validation-evidence`: add outcome-based real-provider acceptance, explicit denominator, durable-adapter parity and failure evidence requirements. Existing UI/video and release-profile requirements remain; no silent retirement.
- `multi-agent-orchestration`: add intent-based selection from the current eligible registered roster, observable selection streaming and multi-call attribution.

## Impact

This change currently authors assessment/analysis/plan/specs only. Future implementation affects runtime/provider/agent management, settings/startup, skills/context, knowledge/team persistence, interface adapters and browser evidence fixtures. No dependency pins or public runtime APIs are changed by this planning cycle. New event/API design is a future implementation task under the supplied acceptance predicates. No product checks, signing, publication, archive or phase certification are requested now.
