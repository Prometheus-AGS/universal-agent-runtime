## Why

UAR advertises an `agentic` chunking strategy and it does nothing: `ChunkingStrategy::Agentic` logs a warning and returns the whole document as one chunk (`src/uar/rag/chunking.rs:79-82`). the-boss decision D3 requires every exposed option to work, and names agentic chunking as a build item.

Reading the ingestion path shows three more defects that make any chunking choice inert today:

1. **No parser produces `Agentic`.** Both string parsers map unknown names to `Recursive`, and neither knows `"agentic"` (`src/uar/defaults.rs:244-260`, `src/uar/api/knowledge.rs:734-745`).
2. **The settings value `fixed_size` is not the parser value `fixed`.** Settings offer `fixed_size` (`src/uar/settings/manager.rs:1987-1991`); the parsers accept only `"fixed"`, so `fixed_size` silently becomes `Recursive`.
3. **The stored per-knowledge-base strategy is never used.** Every document goes through one `IngestService` built with a hardcoded `Semantic { threshold: 0.5 }` (`src/server.rs:738-742`); the ingestion worker calls it without the knowledge base's strategy (`src/uar/rag/ingestion_worker.rs:191-200`). `KbConfig::chunk_strategy` is stored and echoed (`src/uar/api/knowledge.rs:648`) but never read at ingest. Fixing the parsers alone would change nothing a user can observe.

`Chunker` and `IngestService` hold an embedding backend and no model handle (`chunking.rs:26-42`, `src/uar/rag/ingest.rs:12-43`), so there is no way to call an LLM from chunking today.

In the-boss the host's default model configuration has no usable key: sidecar mode persists no provider keys, and runs get theirs only as run-scoped credentials (`run-scoped-credentials-and-mcp-servers` D10). Ingestion is not a run. Upload is `POST /api/uar/knowledge-bases/{id}/documents` (`upload_document`, `src/uar/api/knowledge.rs:383-477`), which reads only the multipart `file` field (`:405-420`), saves the document as `pending`, hands it to the ingestion worker pool (`:449-467`) and answers 202 before any chunking. So an agentic knowledge base in the-boss would always fall back, and the upload would still look like a plain success. Operator decision 2026-09-23: UAR agents in the-boss use UAR knowledge bases owned by the host-asserted session principal (`sidecar-session-principal`), so this path must work there.

## What Changes

- Implement `Agentic` chunking per `design.md` (the one-page design, approved before code): the document is split into contiguous units, the LLM proposes chunk boundaries as unit offsets within a window, long documents are processed window by window, chunks are exact slices, a reconstruction check verifies the chunks concatenate to the exact input, and any error falls back to `Recursive`.
- Give `Chunker` an optional LLM handle; the server passes a driver built from its default LLM configuration.
- Map `"agentic"` to `Agentic` in both parsers; accept `"fixed_size"` as well as `"fixed"` for `FixedSize`.
- Apply a knowledge base's stored `chunk_strategy` at ingest only when that strategy was chosen explicitly, and record the strategy actually used (including a fallback) in each chunk's metadata.
- Add an explicit-choice marker to `KbConfig` (`chunk_strategy_explicit`, default `false`). A stored default cannot be told apart from a chosen strategy today: knowledge bases that never set one store `Recursive { size: 512 }` (`src/uar/domain/knowledge.rs:64-66`, `:204-213`), and the API stores the same value for `recursive`, for an unknown name, and for a request with no strategy (`src/uar/api/knowledge.rs:693-711`, `:734-745`).
- **Ingestion behaviour for existing knowledge bases (operator decision 2026-09-23, task 0.3):** a knowledge base with no explicit strategy keeps today's behaviour for new uploads — semantic chunking at threshold 0.5, the value `src/server.rs:738-742` hardcodes today. Only an explicit per-knowledge-base choice changes chunking. Every knowledge base stored before this change has no marker and so keeps semantic chunking, even if its stored value says `Recursive { size: 512 }`. Existing chunks are not re-chunked.
- **Request-scoped ingestion credential (operator decision 2026-09-23).** A document upload may carry a `model_credential` multipart field with the run credential's shape and validation rules (`{provider_id, provider_kind, base_url, api_key, default_model?}`, `run-scoped-credentials-and-mcp-servers` D10, reused, not redefined). It is used only for that document's agentic chunking and is never persisted, serialized, logged or kept after the ingestion finishes. In sidecar mode an upload without it never uses the host's default model.
- **Fallback is reported, not silent.** When an agentic knowledge base ingests a document without a usable credential, or agentic chunking fails for any other reason, the document is still chunked with `Recursive { size: 512 }`, and the document record and response report the strategy used and the fallback reason. When the fallback is already certain at upload (no credential in sidecar mode), the 202 response says so too.
- **Ownership.** In sidecar mode, knowledge-base create, list, get, update, delete, upload and search run as the request's principal (`sidecar-session-principal`). The handlers already scope by `user.user_id` (`knowledge.rs:181`, `:209`, `:252`, `:277`, `:332`, `:342`, `:392`, `:594`); this change adds the cross-principal test, not new scoping code.
- **Capability flag** `ingest_scoped_credentials`, added to the closed vocabulary of `GET /api/uar/capabilities` (`sidecar-launch-security` Decision 12) and listed only when this behaviour lands.

Not in scope: the global `rag.chunking_strategy` setting (`settings/manager.rs:2007-2012`), which has no runtime consumer and stays inert — the-boss must not expose it; re-chunking existing documents; a cost budget for ingestion; a credential for embeddings — the only embedding engine wired into ingestion and retrieval is local fastembed (`knowledge.rs:678-691`), which needs none; a credential on the directory-watcher path (`ingest.rs:46`), which has no request.

## Impact

- **Code:** `src/uar/rag/chunking.rs` (agentic algorithm, LLM handle), `src/uar/rag/ingest.rs` (per-job strategy, chunk metadata), `src/uar/rag/ingestion_worker.rs` (pass the knowledge base's strategy or the service default), `src/uar/domain/knowledge.rs` (explicit-choice marker), `src/uar/defaults.rs` and `src/uar/api/knowledge.rs` (parsers, marker, `model_credential` field, fallback in `DocumentResponse`), `src/server.rs` (driver for ingestion), `src/uar/domain/knowledge.rs` (`KnowledgeDocument` chunking outcome), `src/uar/persistence/` (write the outcome), `migrations/surrealdb/schema.surql` (two `knowledge_documents` fields), `src/uar/api/capabilities.rs` (flag). The credential input type and validator come from `run-scoped-credentials-and-mcp-servers`.
- **APIs:** `POST/PUT /api/uar/knowledge-bases` accept `chunk_strategy: "agentic"` and `"fixed_size"` with effect. A request that carries `chunk_strategy` or `chunk_size` marks the choice explicit. The response gains one additive field, `config.chunk_strategy_explicit`; the existing `chunk_strategy` echo keeps showing the stored value, so for an unmarked knowledge base it still reads `Recursive { size: 512 }` while ingestion uses semantic chunking. Chunk metadata gains a `chunk_strategy` key. `POST /api/uar/knowledge-bases/{id}/documents` accepts an optional `model_credential` multipart field; an invalid one is 422 `ingest_credential_invalid` or `ingest_credential_provider_kind_unsupported` with no echo. `DocumentResponse` gains `chunk_strategy` and `chunking_fallback` (both nullable, additive). `GET /api/uar/capabilities` may list `ingest_scoped_credentials`.
- **Stored data:** `KbConfig` gains `chunk_strategy_explicit` with `#[serde(default)]`; existing records read as `false`. `KnowledgeDocument` gains `chunk_strategy` and `chunking_fallback`, both `Option<String>` with `#[serde(default)]`; existing records read `None`. No data migration; `knowledge_documents` is `SCHEMAFULL` (`migrations/surrealdb/schema.surql:67-77`), so the schema file gains two `option<string>` fields. There is no API to clear the marker once set. Nothing stores the credential.
- **Provider compatibility:** an ingestion with a `model_credential` calls that provider's endpoint, outside any run budget. Without one, standalone UAR uses the host's default model; sidecar UAR does not, and every agentic ingest falls back to `Recursive` and reports `no_credential`.
- **Security:** the upload route becomes a second place where a host hands UAR a provider key and endpoint (a real boundary). Confinement follows D10 and D1/D6 of `run-scoped-credentials-and-mcp-servers`: no `Serialize`, redacting `Debug`, no error text from the credential's driver stored or logged.
- **Depends on:** `run-scoped-credentials-and-mcp-servers` (credential type, validator, run-provider kind in `build_driver`), `sidecar-session-principal` (principal ownership, `HostAuthenticated`), `sidecar-launch-security` (capabilities route).
- **Cost and latency:** agentic ingestion sends the whole document to the model once, window by window, sequentially.
- **Runtime UX / realtime state:** no new events; the strategy used is visible per chunk.
- **Dependencies:** none new.
- **KBD workflow state:** YES. D3 build item for child phase `the-boss-universal-agent-runtime`; its stop rule needs dated start/stop entries in that child's task log (tasks 0.1-0.2). Shares the 8-day cap with `skill-matching-llm-and-local-embedding`.
